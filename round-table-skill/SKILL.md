# 圆桌勘探 Agent（Skill 形态）

## 0. 形态与位置

- **形态**：纯 Skill，无代码。统筹者=主对话自身，每轮并行派 5 个 Task 子代理当席位。
- **位置**：`d:\owned\ai\myskills\round-table-skill\`，最终报告落盘到 `data\meetings\`。
- **动机**：省 token，走 CLI 订阅额度。
- **模型**：所有子代理用 CLI 当前选中的同一个模型。多样性来自角色提示词+独立上下文，不依赖多模型。

## 1. 五席位角色绑定

| 席位 | 边界类型 | 职责 |
|---|---|---|
| forward | 目标 | 产出具体的、可操作的方面/维度 |
| reverse | 约束 | 产出限制/禁区/前提条件 |
| counter | 反例 | 产出击穿已有维度的反例场景 |
| assumption | 前提 | 产出隐含的、未被明说的前提 |
| blindspot | 盲区 | 产出所有人都还没提到的方面 |

席位提示词模板见 `prompts/seat-{role}.md`。

## 2. 调度流程（R0 → R5）

### R0 开题（统筹者=主对话）

用户发议题后，主对话先输出：
1. 一句话复述议题（用户真正想问什么）
2. 识别产出目标（枚举清单/判断/方案/诊断）
3. 判断目标类型 goalType：enumerate / judge / design / diagnose / other
4. 圈定勘探范围（什么是本题边界、什么超出范围）

然后**等用户确认**再进第一轮勘探。

### R1 盘问（每轮）

用户说 `继续`（单轮）或 `跑到收敛`（连跑）后：

1. **统筹者为每席生成盘问问题**：基于当前边界池，为 5 个席位各生成 1 个精准、开放、不暗示答案的问题。
2. **并行派 5 个 Task 子代理**：每条 query 包含议题、产出目标、勘探范围、当前边界池摘要、对应席位的盘问问题、席位角色提示词路径。
3. **收齐回复**：用两级容错解析（见 §4）。
4. **去重入池**：新边界加入边界池，编号 B001、B002…
5. **贴本轮新增 + 完整 GFM 清单**（见 §3）。
6. 等下一个指令（`继续` / `跑到收敛` / 用户插话）。

### R2 收敛判定

每轮结束后判定是否收敛（继续盘问几乎不会再有新边界）：
- 自动判定信号：连续 2 轮新增 ≤1 条
- 用户也可主动说 `收敛` / `出方案`

收敛后进入裁决。

### R3 裁决（统筹者=主对话）

统筹者审查所有边界条目，对每条裁决：
- **保留**（一致、有效）
- **合并**（与另一条重叠；mergeInto 填保留目标的条目 id）
- **否决**（无效/跑题/无法验证，须给出 reason）

裁决后贴**最终清单**（含裁决状态列），等用户说 `出方案`。

### R5 终局（统筹者=主对话）

用户说 `出方案` 后，主对话基于裁决后的清单生成四节式 Markdown 报告，落盘到 `data\meetings\{topic}-{timestamp}.md`，并在对话里回显路径。

## 3. 边界清单 GFM 格式

**每轮更新整张大表**（勘探中 + 裁决后）：

```markdown
## 边界约束清单（第 N 轮 · <状态>）

共 X 条 · 本轮 +Y ｜ 勘探范围：<scope>

| 编号 | 类别 | 边界描述 | 可信度 | 轮次 | 裁决状态 |
|---|---|---|---|---|---|
| B001 | 目标 | ... | 高 | R1 | - |
| B002 | 约束 | ... | 中 | R1 | - |
| ... | ... | ... | ... | ... | ... |
```

裁决后，"裁决状态"列从 `-` 变为 `保留` / `合并→B00N` / `否决：理由`。

**清单摘要策略（R1 缓解）**：边界池超过 30 条时，子代理提示词里只附摘要（编号+类别+描述截取 30 字），完整表仍贴对话。

## 4. 两级容错协议

子代理回复解析规则：

1. **协议 JSON 优先**：尝试 `extractJson`（括号平衡提取）→ 有 `description` 字段且非空 → 正常收入，confidence 取原值
2. **非 JSON 但有中文正文**：含 ≥6 个汉字的中文正文 → 标 salvaged + confidence=medium → 收入
3. **其余**（空串 / 超时 / 全英文思考链）→ 丢弃 + 控制台通知 "本轮 X 席位失败"

容错时若命中"含 JSON 但 extractJson 失败"（如被代码块围栏包裹），先去 ` ```json ` 围栏再试 extractJson。

## 5. 子代理调用模板

每次派 Task 子代理时的 query：

```
你是圆桌会议「{席位名}」，负责勘探「{边界类型}」类边界。

议题：{topic}
产出目标：{objective}
勘探范围：{scope}
当前边界池（避免重复）：
{当前清单摘要或全量}

第 {round} 轮。请回答统筹者的盘问：
{question}

规则（详见 prompts/seat-{role}.md）：
- 只输出 1 条当前最值得补充的「{边界类型}」边界
- 不得重复已有边界
- 必须给出与上一轮其他席位不同维度的边界
- 输出严格 JSON：{"description":"一句话边界描述","confidence":"high|medium|low"}
- confidence 取值锚点：high=可直接举例验证；medium=方向明确但边界模糊；low=推测
- 禁止英文思考链；描述要具体可验证，不要抽象定义
```

## 6. 连跑方向确认（R4 缓解）

`跑到收敛` 连跑时，每 3 轮强制插一次方向确认：
- 统筹者贴当前清单并问"方向是否正确，是否需要调整范围"
- 用户说 `继续` 再跑
- 异常自动停（连续席位失败、方向错误等）

## 7. 最终报告格式

四节式 Markdown，落盘到 `data\meetings\{topic}-{timestamp}.md`：

```markdown
# 圆桌勘探报告：{topic}

## 方案概述
（2-4 句话给结论）

## 关键结论
（用列表给出，每条后用括号标注依据的边界 ID，如（依据 B1、B3））

## 落地方案
（分步骤或分模块，用编号列表；每步写清「做什么 / 怎么做 / 验收标准」）

## 风险与前提
（逐条标注对应边界 ID；明确哪些前提不成立会导致方案失效）

## 待补充信息
（清单信息不足时列出需要用户补充的具体问题；没有则写「无」）
```

落盘后在对话里回显"报告已保存到 {完整路径}"，用户可直接验证；若失败则把报告全文贴对话里兜底。

## 8. 用户插话支持

勘探中 / 收敛后，用户可：
- **追加边界**：直接说出一条边界，主对话分类（目标/约束/反例/前提/盲区）后入池
- **补充说明**：对议题的补充、歧义澄清、范围修正
- **停止**：明确要求停止勘探/出结果
- **调整方向**：在连跑方向确认时修正范围

## 9. max_rounds

默认 10 轮硬上限。Skill 版因走订阅额度成本低，后续可调。

## 10. 与代码版的关键差异

| 环节 | 代码版 | Skill 版 |
|---|---|---|
| R0 开题 | 自动 | 等用户确认再进第一轮 |
| R1 盘问 | 自动连跑 | 每轮等 `继续` 口令（或 `跑到收敛` 连跑） |
| 容错 | 四级挽救 | 两级简化 |
| 边界池维护 | 内存+每轮 snapshot.json | 仅主对话上下文 |
| 裁决后清单 | 自动推送到前端 | 手动贴完整 GFM 表 |
| 落盘 | 每轮 snapshot.json + 终局 report.md | 仅终局 report.md |
| 模型 | 6 席位可绑定不同供应商 | 全部用 CLI 当前选中模型 |
