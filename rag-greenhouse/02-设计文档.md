## 1. 设计范围

本设计实现方案文档 §6 的四层幻觉治理机制，对应验收标准 S1–S5。

**形态定义**：一个独立的 Spring Boot 本地工程，通过 HTTP 接口自测；不接入平台前端，不接入生产数据库。

## 2. 系统架构

```
┌──────────────────────────────────────────────────────────┐
│                    接入层  (CLI / REST)                    │
│         POST /ingest  ·  POST /ask  ·  GET /stats          │
└───────────────┬──────────────────────────┬───────────────┘
                │                          │
        ┌───────▼────────┐        ┌────────▼─────────┐
        │  IngestionChain │        │  AnswerChain      │
        │                │        │                  │
        │ ① Parse        │        │ ④ Retrieve (L1)  │
        │ ② Chunk        │        │ ⑤ Rerank         │
        │ ③ Embed+Store  │        │ ②' Route (L2 分级)│
        └───────┬────────┘        │ ⑥ Generate       │
                │                 │ ⑦ Cite (L3)      │
        ┌───────▼────────┐        │ ⑧ Observe (L4)   │
        │   VectorStore   │        └────────┬─────────┘
        └────────────────┘                 │
                                    ┌────────▼─────────┐
                                    │  外部 LLM / Embed │  [C22]
                                    └──────────────────┘
```

**六个环节与 S3 的对应**：

| 环节 | 组件 | 失败模式（S3 讲解要点） |
|---|---|---|
| ① 解析 Parse | `TikaDocumentReader` | PPT 表格/层级/页码丢失；页眉页脚噪声 |
| ② 切块 Chunk | `TokenTextSplitter` + 元数据注入 | 切断语义单元；块太小丢上下文；块太大引噪声 |
| ③ 向量化 Embed | embedding API | 中文模型选错；农药名/剂型等专名不在词表 |
| ④ 检索 Retrieve | `VectorStore.similaritySearch` | 纯向量对关键词/型号不敏感（→ 后续需混合检索 BM25） |
| ⑤ 重排 Rerank | `DocumentPostProcessor` | 召回对了但排序错，前 K 条被噪声占满 |
| ⑥ 生成 Generate | 三级模板 + `ChatClient` | 模型忽略 context 自由发挥 |
| ⑦ 引用 Cite | `RETRIEVED_DOCUMENTS` 二次比对 | 模型伪造引用编号 |
| ⑧ 观测 Observe | 问答流水表 | 无指标 → 无法定位是哪一层坏了 |

## 3. 组件设计

### 3.1 IngestionChain（入库链）

| 项 | 内容 |
|---|---|
| 职责 | 文件 → Document → 切片 → 向量入库，并保证元数据可回溯 |
| 输入 | 本地目录下的 `.docx` / `.md`（首批**不含 PPT**，见风险 R3） |
| 输出 | VectorStore 中带完整元数据的切片 |

**关键设计决策 D1：元数据在切块阶段注入，不在入库后补**

```
元数据 = {
  source_file : "豆豆叶斑病防治.docx",
  chunk_index : 3,
  doc_id      : "a1b2c3...",     // 主键
  ingested_at : "2026-10-05T10:22:31",
  doc_version : "v1"
}
```

理由：L3 引用闭环完全依赖这些字段。若入库后再补，切片与来源的对应关系会丢失，引用无法校验。

**决策 D2：首批只收 `.docx` / `.md`，PPT 列为待验证**

依据：`TikaDocumentReader` 官方文档明确「直接返回纯文本，不保留任何格式」。农技内容的核心载体是「作物 × 病害 × 药剂 × 浓度 × 用量」表格，结构丢失后召回的是残缺文本，L1–L4 全部失效。

### 3.2 AnswerChain（问答链）

```
question
   │
   ├─(1) Retrieve ──────────────────── L1
   │      similaritySearch(threshold=T)
   │      → hits[], 记录 maxScore
   │
   ├─(2) Grade ───────────────────────  L2 分级判定
   │      hits非空 && maxScore ≥ T        → LEVEL_1 库内命中
   │      hits非空 && maxScore ∈ [T*0.8,T) → LEVEL_2 库外·有方向
   │      否则                             → LEVEL_3 库外·无方向
   │
   ├─(3) Generate ─────────────────────  L2
   │      按 Level 选模板
   │
   ├─(4) Cite ─────────────────────────  L3
   │      比对答案中的 [来源N] 与 hits
   │      对不上 → 降级为 LEVEL_3 并重打「知识库外」标
   │
   └─(5) Observe ───────────────────────  L4
          写问答流水表
```

**关键设计决策 D3：L2 分级用两个阈值而非一个**

单阈值只能区分「命中/未命中」，无法实现方案文档 §6.3 的三级分流。故引入 `T`（命中阈值）与 `T_low = T × 0.8`（方向阈值）双阈值。

> 该分级规则是**待实测校准**的初版，必须用阶段 1 的评测集验证后调整，不得直接采信。

**关键设计决策 D4：L3 校验失败时降级而非报错**

伪造引用属于「有嫌疑但无法证实」，不是「系统故障」。降级为 LEVEL_3 的行为对农户安全，同时把异常记入流水表供复盘。

### 3.3 CitationVerifier（引用校验器）

```
输入：answerText, hits[]
输出：VerifiedCitation { sourceFile, chunkIndex, quoteSnippet }[], degraded: boolean

校验规则：
  1. 正则抽取答案中所有 [来源N]
  2. N 超出 hits 范围        → degraded = true
  3. N 在范围内但内容不相关  → degraded = true（人工判定，阶段 3 先只做规则 1、2）
  4. 答案无任何 [来源N] 且 Level==LEVEL_1 → degraded = true
```

### 3.4 QueryLogRepository（问答流水表，L4）

```sql
CREATE TABLE query_log (
  id             BIGINT PRIMARY KEY AUTO_INCREMENT,
  question       TEXT        NOT NULL,
  answer         TEXT        NOT NULL,
  level          VARCHAR(16) NOT NULL,   -- LEVEL_1 / LEVEL_2 / LEVEL_3
  grounded       BOOLEAN     NOT NULL,   -- hits 非空
  max_score      DOUBLE      NULL,       -- 最高相似度
  threshold      DOUBLE      NOT NULL,   -- 当时的阈值（阈值会调，必须留痕）
  hit_doc_ids    TEXT        NULL,       -- JSON 数组
  citations      TEXT        NULL,       -- JSON 数组
  citation_ok    BOOLEAN     NULL,       -- L3 校验结果
  model          VARCHAR(64) NULL,
  asked_at       TIMESTAMP   NOT NULL,
  reviewed_result VARCHAR(16) NULL,      -- 人工抽检：正确 / 存疑 / 错误 / NULL
  reviewed_at    TIMESTAMP   NULL
);
```

**设计要点**：
- `threshold` 必须留痕 —— 阈值是会被调整的，不留痕则历史数据无法解释
- `reviewed_result` 是 L4 的第二维度（方案文档 §6.4），无此列则只能算兜底率，看不出内容质量
- 索引：`asked_at`、`level`、`reviewed_result`

## 4. 接口定义

```java
public interface IngestionService {
    IngestResult ingest(Path fileOrDir);   // 扫描目录，返回入库/跳过统计
}

public interface AnswerService {
    AnswerResult ask(String question);
}

public record AnswerResult(
    String  answer,
    Level   level,                    // LEVEL_1 / LEVEL_2 / LEVEL_3
    String  sourceTag,                // "[来源1 · 豆豆叶斑病防治.docx · 第3段]" 或 "【知识库外 · 未经平台知识库验证】"
    List<VerifiedCitation> citations,
    boolean citationDegraded,
    double  maxScore,
    long    queryLogId
) {}

public enum Level { LEVEL_1, LEVEL_2, LEVEL_3 }
```

REST 端点：

| 方法 | 路径 | 说明 |
|---|---|---|
| POST | `/ingest` | 指定目录，执行入库 |
| POST | `/ask` | 提问，返回答案 + 来源标注 |
| GET | `/stats` | 返回兜底率、抽检交叉表、各 Level 分布 |

## 5. 关键参数表

| 参数 | 初值 | 来源 | 校准方式 |
|---|---|---|---|
| `chunkSize` | 512 token | 经验起点 | 阶段 2 对照 256 / 512 / 1024 |
| `minChunkSize` | 64 token | 经验起点 | 同上 |
| `chunkOverlap` | 显式 10–20% 重叠 | 经验起点 | 阶段 2 观察边界截断 |
| `topK` | 5 | 经验起点 | 阶段 2 观察 |
| `similarityThreshold` (T) | **0.75** | **未校准占位** | 阶段 1 用评测集画「问题 vs 相似度」分布图后定 |
| `lowThreshold` (T×0.8) | **0.60** | **未校准占位** | 同上 |
| embedding 模型 | 待选 | C22 可用外部 API | 阶段 2 对照（如有 ≥10h/周） |
| LLM 模型 | 待选 | C22 | 阶段 1 选定后固定，中途不换（换模型需重跑评测） |

> ⚠️ **T 和 T×0.8 是占位值，不是结论。** 未校准前，LEVEL_2/LEVEL_3 的判定不可信。校准是阶段 2 的强制产出。

## 6. 提示词模板设计（三套）

### 6.1 LEVEL_1 严格模板

```
你是「智慧数字大棚平台」的农技助手。请**只依据**下面提供的资料回答。

【资料】
{context}

【要求】
1. 资料中每一段前有编号（如 [1]、[2]），引用时必须在答案中写出来源编号
2. 资料没写到的内容，明确说"资料中未提及"，不要补充
3. 禁止给出资料中没有的具体数值（浓度、剂量、用量）

【用户问题】
{question}
```

### 6.2 LEVEL_2 保守模板

```
你是「智慧数字大棚平台」的农技助手。平台知识库中**没有**这个问题的直接记录。

【已检索到的相关资料（仅供参考，不足以直接回答）】
{context}

【要求】
1. 可以给出**方向性**判断（例如"更可能是缺肥或病害，建议先排查叶片背面白粉"）
2. **禁止**给出任何具体商品名、浓度、剂量、施用次数
3. 明确告知用户：本回答来自大模型通用知识，未经平台知识库验证
4. 结尾必须提示"用药与用量请以农技专家意见或农资标签为准"
```

### 6.3 LEVEL_3 转人工模板

```
你是「智慧数字大棚平台」的农技助手。平台知识库中没有与该问题相关的内容，
且我无法给出可靠的方向性判断。

我不提供推测性回答，因为这可能误导你的农事操作。

建议：
1. 联系平台合作的农技专家
2. 或者提供作物名称、生育期、近期症状照片，由专家判断
```

> 6.2 与 6.3 的分界是**待实测校准项**（决策 D3）。若实际使用中发现 6.2 输出过于空泛，收紧为直接进 6.3。

## 7. 关键流程时序

### 7.1 入库流程

```
上传/指定目录
  → 过滤扩展名（仅 .docx/.md）
  → TikaDocumentReader.get() 得到 Document（纯文本）
  → TokenTextSplitter 切块 + 注入元数据（决策 D1）
  → VectorStore.add() 触发 embedding 调用
  → 记录入库统计：成功 N / 跳过 M / 失败 K
```

**失败处理**：
- 单文件解析异常 → 记录到入库报告，继续下一个，**不中断整批**
- 解析结果为空 → 标记为「空文档」并告警（常见于纯图片 PPT/扫描件）

### 7.2 问答流程

```
提问
  → Retrieve（L1，阈值 T）
  → Grade（决策 D3，T 与 T×0.8 双阈值）
  → 按 Level 选模板
  → Generate
  → Cite（L3，正则抽 [来源N] + 范围比对）
  → 降级判定（D4）
  → Observe（L4，落库）
  → 拼装 sourceTag 返回
```

## 8. 可观测性

| 指标 | 计算 | 用途 | 期望 |
|---|---|---|---|
| 兜底率 | `level != LEVEL_1` 占比 | 知识库覆盖缺口 | 越低越好，上线后持续压 |
| 引用校验失败率 | `citation_degraded == true` 占比 | 引用机制有效性 | 应接近 0 |
| 各 Level 分布 | 分组计数 | 校验 T 阈值是否合理 | 单 LEVEL_2 占比畸高 → T 偏低 |
| 抽检错误率 | `reviewed_result = '错误'` 占比（需人工填） | **内容质量** | 与兜底率**交叉**看（方案文档 §6.4） |
| 相似度分布 | `max_score` 直方图 | 阈值校准依据 | 阶段 2 必须产出 |

## 10. 演进插槽（上线前替换点）

| 插槽 | 本期实现 | 上线时替换为 | 触发条件 |
|---|---|---|---|
| 解析层 | `TikaDocumentReader` | MinerU / Docling / RAGFlow 解析服务 | 风险 R3 发生或需要表格/图示 |
| 检索 | 纯向量 topK | 混合检索（向量 + BM25） | 症状：专名/型号/剂量类问题召回失败 |
| 重排 | 空实现 | 真实 rerank 模型 | 症状：召回对了但排序错 |
| 存储 | 本地 VectorStore | PgVector / Qdrant / Milvus | 文档量级上升或多实例部署 |
| 流式 | 非流式 | 流式（注意 `RETRIEVED_DOCUMENTS` 在流式下取回报错，见 spring-ai issue #1747） | 前端需要打字机效果 |

> 五个插槽都在本期留出接口，替换时不动上层逻辑。

## 11. 设计决策与依据对照

| 编号 | 决策 | 依据 | 状态 |
|---|---|---|---|
| D1 | 元数据在切块阶段注入 | L3 引用闭环强依赖来源字段 | 已定 |
| D2 | 首批只收 .docx/.md，PPT 待验证 | `TikaDocumentReader` 官方文档「不保留任何格式」 | **待阶段 2 实测确认或推翻** |
| D3 | L2 用双阈值三级分流 | 方案文档 §6.3；C10「都会出现」但无比例数据 | **初版占位，必须实测校准** |
| D4 | 引用校验失败时降级而非报错 | 伪造引用是「有嫌疑」非「系统故障」 | 已定 |
| D5 | `threshold` 字段必须落库 | 阈值会被调整，不留痕则历史数据无法解释 | 已定 |
| D6 | `reviewed_result` 人工抽检列必须建 | C7 内容来源未定，兜底率看不出内容质量 | 已定 |
| D7 | 只用最小 Spring AI API 面 | 依赖坐标在不同版本参考文档中不一致 | 已定（风险 R1 缓解） |
