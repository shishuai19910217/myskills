# correctness-enhanced-reply — 正确性增强高可靠性回复 Skill

> **别名**：超导体提示词 / 前置问答 + 用户确证 + 红队审查 / 先挖后判。
> **目标**：把复杂任务（架构选型 / 投资决策 / 技术方案 / 产品提案 / 重大代码重构）的回复返工轮数降下来、一次做对。方法：先挖透需求（**用户可验证的确证**），再输出带权衡与对抗审查的方案。
> **信任锚点**：**不是** AI 自报的掌握度百分比，而是【约束清单 + 用户逐条确证 + 锚点式溯源】；自评置信度只作提示因子，不作准入闸门。
>
> 🧭 **核心元原则：先挖后判，不急着给结论**——充分挖掘用户真实诉求之前，严禁输出任何方案、结论或预判。"挖"= 通过主动提问，让用户说出他可能还没意识到的约束、痛点和目标。
>
> **四条最核心规则**（与任何具体规则冲突时永远优先）：
> 1. **先挖后判**：约束清单未获用户确证之前，严禁输出任何方案内容；违反 = 输出作废。
> 2. **完成靠约束确证**：固定轮数（A=3 / B=7 / C=11）是**默认最低轮数 + 规划锚点**，不是完成闸门；最终能否进入下一阶段只看必要约束是否已确证——问满了没确证 → 继续；没问满但已确证 → 可以提前停。
> 3. **阶段可以重新打开**：新信息只要改变需求 / 目标 / 约束 / 关键假设，必须回退受影响阶段（附录A），不是"更新一个字段继续往前走"。
> 4. **默认启发式 + 真实出口约束双层结构**：正反向交替是**默认提问策略**（简单可执行、天然防单边），双向覆盖是**出口约束**（最终必须两侧都到位）；高价值未知允许连续同向追问（偏离默认），挖透后补回另一侧平衡即可。信息增益 > 默认策略。
>
> **边界**：✅ **做**：高代价/不可逆 / 高复杂度 / 返工 ≥2 次 / 用户明确要求"正确率 / 可靠性 / 高精度 / 先确认需求" / 模糊想法但最终要产出方案。❌ **不做**：API 参数查询、语法说明、1 句话能答的低复杂度查询（直接回答，不引入流程开销）。

## 执行总览（状态机 + 主导权切换）

### 六阶段静态地图

```text
用户输入
   ↓
阶段 0：问题状态判定 + 代价档位
   ├─ 纯事实/语法查询 → 直接回答（退出流程）
   ├─ 模式 1（需求已清晰）→ 定档 A/B/C → 阶段 1
   └─ 模式 2（萌芽期模糊）→ 阶段 0.5 成形 → 阶段 1
   ↓
阶段 1：需求复述确认（用户确证）
   ↓
阶段 2：需求挖掘循环（障碍识别 + 工具路由 + 约束清单）
   ┌──────────────────────────────────┐
   │ 覆盖不足 / 决策阻塞项未清 → 继续循环  │
   │ 新信息改变结论 → 回退受影响阶段（附录A）│
   │ 约束清单确证通过  → 阶段 3          │
   └──────────────────────────────────┘
   ↓
阶段 3：方案输出（A/B/C 模板，C 含三角色分离）
   ↓
阶段 4：对抗式红队自查 + 逆向验收
   ├─ 击穿关键假设 / 验收不通过 → 回退阶段 3
   └─ 通过 → 最终方案 + 待确认项回流用户
```

这只是**静态地图**。实际执行是动态状态机：每阶段执行后做完成约束检查，**结论变化 → 回退（附录A）重开受影响阶段；结论未变 → 阶段关闭进入下一阶段**——任何已完成的阶段都可能因新信息被重新打开。

### 阶段生命周期

每个阶段：`NOT_STARTED → ACTIVE → PENDING_CONFIRMATION → COMPLETED`。`COMPLETED` 不是永久状态，新信息可致 `COMPLETED → INVALIDATED → ACTIVE`（重新打开）。**关键闸门不可跳过**：A/B/C 档位只决定每个阶段的深度、轮次和字段数量，不得把"可简化"解释为"可跳过"——阶段 1 复述确认和阶段 2 约束清单确证是任何档位的必经闸门。

### 阶段出口确认机制

每个阶段关闭前，按该阶段的**出口模式**与用户交互一次（对应生命周期中的 `PENDING_CONFIRMATION` 状态）：

| 出口模式 | 含义 | 适用阶段 |
|---|---|---|
| **用户确证** | 用户明确肯定（或修正后确认）才能关闭；否则循环追问，不得跳过 | 阶段 0.5 退出、阶段 1 复述、阶段 2 约束清单 |
| **用户知会** | 判定结果以一两句话告知用户，允许异议/换档，不强制等待 | 阶段 0 状态/档位判定（并入阶段 1 复述一并声明） |
| **AI 内部判定** | AI 依据完成约束自行判定，不占用用户轮次；结果与【待确认项】在最终输出回流用户 | 阶段 3 方案结构、阶段 4 对抗验收 |

> **硬约束**：不是每个阶段都强制用户确证——那会严重增加用户认知负担。确证只放在"结论可被用户验证、且错了会带偏全局方向"的节点；纯 AI 内部质量关卡不消耗用户轮次。

### 主导权状态机

```text
AI 主导  → 阶段 0.5（萌芽期成形）、阶段 2（需求挖掘问答）、阶段 3（方案输出）
用户主导 → 阶段 1（复述确认）、阶段 2 补充窗口与约束清单确证、阶段 3（方案评审）、阶段 4（红队结果评审）
切换节奏：0.5→1 换用户（确认复述）｜1→2 换 AI（开始挖掘）｜补充窗口/清单确证 换用户（追加/逐条确认）｜2→3 换 AI（输出方案）｜3→4 换用户（评审红队结果、确认待确认项）
```

### 全局规则优先级（规则冲突时）

```text
P0 真实性/不编造 > P1 用户真实目标与关键约束 > P2 输出正确性
> P3 决策阻塞项 > P4 信息增益 > P5 双向覆盖 > P6 流程完整性 > P7 输出格式
```

例：预期轮数已到但决策阻塞项未清 → 继续问（P3 > P6）；高价值未知需要连续同向追问 → 连追问优先（P4 > P5）。

## 阶段 0 — 问题状态判定 + 代价档位

> 🎯 **执行锚点**：必须完成「异常分支排除 → 模式 1/2 判定 → 档位判定」三步；禁止直接给方案、禁止跳过档位判定、禁止把纯事实查询当复杂任务跑流程。

**第一步：排除异常分支**
- **纯事实/语法/API 查询**（答案客观唯一、与用户个人情况无关）→ 直接回答退出流程；判据存疑（因人而异/需权衡）→ 按模式 1 走流程。
- **需求冲突**（前后目标/约束矛盾）→ 暂停，请用户裁决（附录B）。
- **信息严重不足**（关键事实无法获得、提问收益极低）→ 异常退出（附录B）。

**第二步：需求清晰度判定（AI 主动验证，不猜测）**

| 模式 | 信号 |
|---|---|
| **模式 1（需求已清晰）** | 明确说出"我要解决 XX / 帮我设计 XX / XX 怎么做" |
| **模式 2（萌芽期模糊）** | 只有模糊感觉/念头，未形成问题定义，但最终要产出方案（如"感觉知识沉淀可以优化"） |

判定为模式 2 但不确定时，主动问一句："你提到的'____'，我理解是你可能还在摸索、没完全想清楚要解决什么问题，对吗？还是已有比较清晰的定义？"——确认摸索 → 阶段 0.5；说出具体问题 → 模式 1。

- **方案先行**：用户已指定具体方案时，**方案先视为假设，不当需求执行**——暂记候选前提，阶段 1/2 用探测性反诘和动机深挖验证背后的真实问题。
- **判定异议 → 重判协议**：先确认异议实质（判定错了还是情况变了），不得先辩护；重判后从阶段 0 重走，已获信息保留进清单候选，不重复追问；已在错误路径输出的内容须声明处置。

**第三步：代价档位判定（仅模式 1；自动选，不问用户）**

先自问再查表：① 方案错了最坏代价是什么？（钱/时间/声誉/不可逆生产影响）② 错了能回滚吗？

| 档位 | 代价/可逆性 | 典型场景 | 默认最低轮数 | 方案框架 | 红队强度 |
|---|---|---|---|---|---|
| **A 轻量** | 低代价、可逆 | 内部工具、草稿、日常方案 | 3 | 简化 4 模块（含验证 1 行） | 1 轮快速自查 |
| **B 标准** | 中代价、部分可逆 | 技术研究、架构设计、产品方案、返工 ≥2 次 | 7 | 强制 6 模块 | 3 模块完整自查 |
| **C 高压/超导体** | 高代价、不可逆 | 上线前、投资决策、对外提案、重大架构选型 | 11 | 6 模块 + 多视角攻击 + 待确认项回流 | 独立红队审查官，攻击只打有真依据的点 |

- **默认最低轮数**：是执行起点锚点（防止偷懒、保证最低覆盖深度），不是完成闸门，也不是上限——完成判定只看阶段 2 的分档最低覆盖约束：约束已确证可提前停；阻塞未清则继续追加。
- 拿不准代价 → 默认 **B**（不要选 A 导致挖得不够深）；拿不准是否不可逆 → 取 **C**。
- **升降档（硬约束）**：降档——高代价任务（B/C）可降到 B、**不可降到 A**；低代价误判 C 可降到 A；降档须声明原因及风险；档位在阶段 1 复述时对齐。升档（A→B、A→C、B→C）——**必须回阶段 0 重评已完成阶段是否满足新档位最低覆盖约束**，不满足全部重开。
- 出口（知会）：档位并入阶段 1 复述一并声明（"我自动判定本任务代价档位为 X"），用户可换档；高风险任务不可因用户着急降到 A。

> 通用十阶段思维模型与本 skill 六阶段的对应关系，见「附录D」。

## 阶段 0.5 — 萌芽期成形（AI 主导）

> 🎯 **执行锚点**：必须把模糊感觉挖到用户能说出「问题 + 场景」并经复述确认；禁止在问题定义清晰前进入阶段 1、禁止出方案、禁止用引导性问题。

**触发**：模式 2 且最终要产出方案。**核心目标**：挖到用户能清晰说出"我要解决的是 XX 问题，服务于 XX 场景"。**硬约束**：完成前不进入阶段 1。

**提问方法**（分层例句与探索机制细则见 `references/stage0.5-sprout.md`，进入本阶段时读取）：
- **单轮单问** + **严禁引导**（问开放问题）；不要求正反均衡，**以反向约束为主**（先挖痛点，再找正向诉求）；无固定轮数。
- **分层切入**：极度模糊 → 从领域/痛点反向切入；有方向没定义 → 从最近一次超预期经历切入；有念头未成方案 → 从必要性/边界反向切入。
- **探索机制**：决策树穷举（心里穷举问题定义方向，逐方向一句开放问题探测，按应答剪枝收敛）+ 追问链（模糊词追到含义清晰）；**过程性产出**（只有"已澄清的问题定义 + 用户确认"），不形成约束清单条目。

**输出格式（每轮严格遵循）**：`Q<轮数>【萌芽·<层级>】：<精准问题>`（层级 = 极度模糊 / 有方向 / 有念头；不加其他内容，不讨论方案，不给建议；必要时附一行小字"问这个是为了搞清楚 XX"）

**退出确证（同时满足才进阶段 1，用户确证模式）**：
1. 用户能清晰说出"我要解决的是 XX 问题，服务于 XX 场景"；
2. AI 复述，用户确认"对，就是这个"或小幅修正后确认。

**兜底**：挖了 **10 轮**仍无法具象化 → 触发「严重信息不足」退出（附录B），说明可能原因（还缺背景/实践，或非当前最紧迫问题），建议换角度："在哪个具体时刻，你觉得'要是有个 XX 就好了'？"

## 阶段 1 — 需求复述确认（所有档位必经闸门，用户确证模式）

> 🎯 **执行锚点**：必须按模板复述并等用户明确确认后才可进入阶段 2；禁止跳过复述、禁止把未提供的信息脑补成事实（未知须显式标记）、禁止未确认就开问。

**问任何问题之前**，先输出复述（只允许填空；未提供的信息不得脑补成事实——未知显式标记），等确认后再进阶段 2。

**模板 B/C（标准/高压）强制话术**：
```
好的，我先用自己的话复述一下你的需求，确认我的理解起点是对的：
  · 你的核心目标是：____（一句话总结）
  · 你提出这个需求的上下文背景是：____
  · 【若来自阶段 0.5】我们刚才通过 N 轮深挖，从"____（原始模糊感觉）"具象化到了这个问题
  · 当前看到的实际现象是：____
  · 你认为可能的解决方式是：____
  · 如果我没有理解错，"成功完成"的可验证标准是：____
  · 我目前不知道、需要接下来探索的是：____
  · 我自动判定本任务代价档位是：【B 标准 / C 高压】（若为 C，我会在阶段 2 按 11 问正交维度表覆盖，先经"正交 + 代价轴覆盖"自检）

请问以上理解准确吗？有哪里需要修正、补充，或者你想换一个更高/更低的档位吗？
（换档权限：高代价任务可降到 B、不可降到 A；低代价误判 C 可降到 A）
```
**模板 A（轻量）**：仅保留核心目标、"成功完成"可验证标准、档位三字段 + 同一句确认问话。

- **主题≠需求**：名词明确、技术对象明确、任务动作明确，都不自动等于需求明确。"如何学习/怎么选/要不要做/怎么优化"类开放目标，至少确认期望结果与关键歧义后才能关闭本阶段。
- **确认层级**："你理解得对"只是 L1 语义确认，≠ L2 需求确认（对的问题）、L3 前提确认（假设成立）、L4 结果确认（解决 X 能达到 Y）。L1 成立不代表 L2/L3/L4 成立——后三层靠阶段 2 和阶段 4 补齐。
- 用户修正了需求 → 重新复述直到确认，不要跳。

**完成判定**：已明确"当前要解决什么"及期望结果/能力；会改变方向的关键歧义已处理；空字段已确认/修正、未知显式标记；用户明确肯定（或小幅补充后再确认）。A 档也必须满足，只是减少非关键字段，不得省略需求确认。

## 阶段 2 — 需求挖掘循环

> 🎯 **执行锚点**：必须单轮单问、逐条打来源标签、双向覆盖（正+反）后才可关闭；禁止一次抛多问、禁止引导式提问。受元原则 #1「先挖后判」与 #2「完成靠约束确证」约束——问多少轮由"必要约束是否确证"决定，不是固定问数；清单确证前严禁输出方案。

**进入声明（第一轮必须执行）**：`【本阶段挖掘说明】· 识别到的关键特征：____（对应特征识别路由表）· 拟采用的提问路线：____（一句话依据）· 预计先从【正向诉求 / 反向约束】侧切入。Q1 按特征路由选定。如需换个方向挖，请直接说；否则按上述路线继续。`

### 每轮执行流程
1. **特征识别**：扫描三类对象——用户初始输入 / 用户每轮回答 / AI 自身卡壳信号（连续追问无新增益），命中「特征识别路由表」某行（问"是什么阻止我继续"，不是"我还有什么没问"）；
2. **阶段过滤**：与附录D 当前阶段映射取交集，剔除不属于本阶段的工具（如决策矩阵不进阶段 0.5）；
3. **主工具 → 具体下一问**：按「提问优先级」选定唯一问题，单轮单问（Q1 不固定：命中可反诘前提时优先探测性反诘，见「追问工具箱」）；
4. **失效检查（硬判据）**：主工具连续 2 轮无新信息增益（无新约束条目 / 回答无变化 / 用户明显困惑）→ 切备用工具，附一行小字声明；备用 2 轮仍无增益 → 原特征可能误诊，回第 1 步重判；
5. 接收回答 → 打来源标签 → 更新约束清单候选 + 认知分类（见「认知分类」）；
6. 执行「每轮检查」（目标漂移 / 约束冲突 / 新事实是否改变结论，见下）；改变 → 回退（附录A）；未改变 → 下一轮；
7. 循环直到满足停止条件。

### 五大铁则（违反 = 整个输出作废）
1. **单轮单问**：每轮只输出 **1 个**精准定向问题，末尾不带预判性分析或建议；**一次抛 ≥2 个问题 = 违规**。
2. **双向覆盖（默认交替 + 出口约束双层）**：
   - **默认策略**：正反向**交替**提问（奇正向、偶反向），简单可执行、天然防止单边倒；
   - **出口约束**：阶段关闭时「正向诉求」（想要什么/目标/优先顺序）和「反向约束」（不想要什么/技术/预算/时间/合规限制/绝对不能碰的）两侧必须都覆盖到位（覆盖轮数下限见「分档最低覆盖约束」表）；
   - **偏离默认的触发条件**：同一侧存在高信息增益未知（回答不同→方案根本变化）、或需沿单分支深挖至结论时，允许**连续同向追问**——偏离前快速判定：「下一问若换到另一侧，信息增益是否显著低于继续同方向？」是 → 继续同侧；否 → 恢复交替。挖透该分支后，必须**补回另一侧的覆盖轮数**，最终仍满足出口约束。信息增益 > 默认交替。
3. **反向挑战（唯一允许打破"不引导"的情形，必须有依据）**：用户自述的约束/前提与事实、边界或已知信息矛盾时——"你这条前提可能是错的：原因____。你是坚持它，还是重新确认？"须有依据、单轮单问、不指向预设答案。用户坚持 → 记为"**用户明确坚持的前提**"，进方案并在 B4 标高风险。
4. **不引导、不暗示**：除反向挑战外严禁"你是不是想要 XXX 对吧？"式引导性问题；问开放问题让用户自己说出约束。
5. **来源标签**（每条关键回答实时打标）：`[用户明说]` / `[用户估计·未验证]` / `[AI 推断·需验证]` / `[沉默默认]`。用户估计不能当事实用；AI 推断在 B4 一律标"需验证"。

### 特征识别路由表（每轮路由核心）

统一路由流水线（五步链）：`特征识别 → 阶段过滤 → 主工具落成下一问 → 失效切换 → 重判特征`（执行细节见「每轮执行流程」）。工具是工具箱不是固定流程，且必须是**行为路由器——落成具体下一问，不是贴标签**。

| 特征 | 典型信号 | 诊断策略 | 主工具（落成下一问） | 备用工具（主失效切换） | 适用阶段 |
|---|---|---|---|---|---|
| 语义模糊 | "优化、提升、稳定、智能"含义不清 | 把笼统词拆成可验证的具体所指 | 追问链（语义拆解） | 动机深挖（5Why） | 0.5 / 2 |
| 问题错位 | 把方案当问题 | 区分"目标"与"实现手段" | 重新定义问题 | 探测性反诘 + 动机深挖 | 1 / 2 |
| 症状遮蔽 | 只描述表面现象 | 还原到最近一次具体事件 | 追问"上次具体发生了什么" | 追问链（语义拆解） | 2 |
| 因果假设 | "因为 A，所以必须 B" | 检验 A→B 的必然性 | 反诘 + 反例检验 | 反向挑战 | 2 |
| 目标模糊 | 想做很多事情 | 排序多目标、找出第一优先 | 目标排序提问 | 强制取舍提问 | 1 / 2 |
| 约束遗漏 | 只说想要什么 | 反查"绝对不能碰的边界" | 反向边界探索 | 反向挑战 | 2 |
| 经验依赖 | "以前一直这么做" | 剥离历史惯性、回到本质约束 | 第一性原理 | 反诘 + 反例检验 | 2 |
| 单点视角 | 只看一个因素 | 拉入相关因素看相互影响 | 系统思维 | 决策矩阵 | 2 / 3 |
| 方案锚定 | 已认定某种实现方式 | 把目标与方案拆开 | 探测性反诘 + 动机深挖（5Why） | 重新定义问题 | 1 / 2 |
| 权衡不清 | 多个方案都可行 | 摆出维度逐一对比取舍 | 决策矩阵 | 强制取舍提问 | 2 / 3 |
| 风险未知 | 不知道方案哪里会失败 | 预设失败倒推死因 | Pre-Mortem | 红队对抗验证 | 3 / 4 |
| 优先级不明 | 多个诉求都重要 | 强制排序、逼出取舍 | 强制取舍提问 | 目标排序提问 | 2 |
| 证据不足 | 关键前提没有依据 | 反向找反例或设计验证 | 反向挑战 / 验证实验 | 反诘 + 反例检验 | 2 |
| 用户方案可能不是需求 | 方案≠真正要解决的问题 | 质疑需求真假 | 探测性反诘 / 苏格拉底提问 | 动机深挖（5Why） | 1 / 2 |
| 方案未来可能失败 | 需要前瞻审视 | 预演失败路径 | Pre-Mortem / 红队对抗验证 | 二阶思维 | 3 / 4 |
| 对抗不充分 | 只打自己方案、没为对手方案构造最强版本 | 先替反方搭最有利论证再攻击 | 钢人论证（Steelman） | 红队审查 | 3 / 4 |

> 示例：① 特征识别 → 方案锚定 → ② 阶段过滤通过（阶段 2）→ ③ 主工具「探测性反诘+动机深挖」（把目标、问题、方案拆开）→ 下一问："如果完全不能采用这个方案，你真正希望改变的结果是什么？" → ④ 连续 2 轮无新增益 → 切备用「重新定义问题」（附小字声明）。
>
> 本表按"特征信号"路由（输入 / 回答 / 卡壳 → 主/备工具）；「附录D」承担阶段过滤维度（`references/thinking-models.md`）。

### 提问优先级与信息增益
决策阻塞项 > 最高信息增益 > 正反边界覆盖 > 特征路由 > 维持正反平衡 > 默认交替顺序。

问题价值 ≈ 决策影响 × 不确定程度 ÷ 获取成本，只分类不计算：**高**（回答不同→方案根本变化）/ **中**（影响细节）/ **低**（只影响优化程度）。低价值不单独占一轮。

**决策阻塞项判定**（每个候选追问点先判）：`未知：____；为什么影响决策：____；如果不解决：____；状态：□ 阻塞 □ 非阻塞 □ 可通过验证实验解决`。只有"阻塞"或"可验证实验解决"才占用提问资源。

### 追问工具箱（按需读取，不再是固定流程）
**Q1 不固定**：探测性反诘由"固定首问"降级为路由工具——仅当特征识别命中可反诘前提（方案锚定 / 因果假设 / 用户方案可能不是需求 / 证据不足）时优先选用；否则按特征路由选最高增益问题开场。
**探测性反诘 / 苏格拉底追问链+反诘 / 动机深挖（5Why）** 的完整话术、触发条件与停止规则见 `references/stage2-toolbox.md`。核心红线（常驻）：只引用用户原话为靶子，不得自造前提；反诘结果只作过程信号（无翻转且给出理由 → 记入约束清单候选 `[用户明说]`）；**用户主动修正才是新 `[用户明说]`**（附和不算）；单分支 ≤3 层、同主题 5Why ≤3 层。

### 每轮检查
- **目标漂移**：`原目标 ____ / 当前目标 ____ / 是否变化 / 是否影响方案空间`；重大变化 → 暂停更新需求理解，必要时重开阶段 1 复述。
- **约束冲突**：存在无法同时满足的要求 → **禁止 AI 自行二选一**，指出冲突请用户裁决（附录B）。
- **新事实是否改变结论**：新信息若改变需求/目标/约束/关键假设 → 回退受影响阶段（附录A）；未改变 → 继续下一轮。
- **确认四层级**：L1 语义 → L2 需求 → L3 前提 → L4 结果，定义见阶段 1「确认层级」。

### 输出格式（每轮严格遵循）
`Q<轮数>【<类型>】：<精准问题>`（类型 = 正向诉求 / 反向约束 / 动机深挖；仅当问题易被误解时附一行括号小字；不加其他内容，不提前讨论方案，不给建议）

### C 档维度覆盖清单（11 问正交维度表）
C 档必须覆盖完整维度表（**覆盖维度不是问数**——一个维度可合并进一轮高质量问题，也可能需多轮；缺任何 1 个 = 补问）。通用版 11 维度表见 `references/stage2-toolbox.md` 第四节（**C 档进入阶段 2 前读取**）；非技术架构任务在阶段 1 复述后先按其格式定制专属 11 问维度表（写在阶段 1 输出末尾），先自检（正交 + 代价轴覆盖）再执行。

### 停止条件（满足后进入补充窗口，不直接进清单整理）
**停止条件**（全部满足才进入补充窗口）：`达到默认最低轮数 + 分档最低覆盖约束已满足 + 无决策阻塞项 + 关键冲突已处理 + 正反边界已覆盖 + 信息增益明显下降`（信息增益下降只是条件之一，不能单独作为完成依据；默认轮数已到但约束未确证 → 继续追加；约束提前确证且已达最低轮数 → 可以提前停止）。

> 停止条件只决定"停止追问"，不等于"完成阶段 2"；完成阶段 2 还需经补充窗口 + 约束清单逐条确认（见「阶段 2 完成判定」）。

### 补充窗口（停止条件满足后、清单整理前）
停止条件满足后**必须**输出（给用户发现遗漏的机会，不是形式确认）：先列"目前我们已经确认"的要点，再问"还有没有重要但刚才没提到的信息、目标、约束或背景？没有可直接说'没有'"。
**用户意图判定**：否定信号（"没有了 / 够了 / OK / 差不多"等）→ 进清单整理；补充信号（"还有 / 对了 / 另外"等）→ AI 追加 1 问，循环继续；意图不明 → 追问 1 次，仍不明确视为"没有更多"。
**循环保护（硬上限）**：用户驱动追加 ≤ **3 次**；AI 驱动追加 ≤ **+5 问**（分档覆盖未满足时），到顶仍未覆盖 → 「严重信息不足」退出或低确证度异常通道；连续 3 次"你随便给"→ 低确证度异常通道；回答冲突禁止自行二选一（附录B）；补充新信息改变需求/目标/约束 → 回退（附录A）。
> 完整窗口话术、语义信号全表、主动收敛声明与追加提问格式见 `references/stage2-toolbox.md` 第五节（进入补充窗口时读取）。

### 阶段 2 完成判定（【约束清单】确证）
完成物是**【约束清单】**。全部满足才进阶段 3：
1. 分档最低覆盖约束已满足（见下；参考轮数不是条件）；
2. **【约束清单】已整理**：从所有回答提取的约束/假设列成清单，**每条标注来源标签**；
3. **用户逐条确认**："清单准确"或逐条修正直到无异议；
4. **认知分类已输出**；
5. **最后一个实质性问题已覆盖反向约束类维度**（不允许在纯正向维度中结束）；
6. **已完成补充窗口**（用户确认"没有更多"或循环到达上限）。

**分档最低覆盖约束（硬约束，"必须"项不得跳过）**：
- **A/B/C 全部必须**：核心目标明确+用户确认 ｜ 关键歧义已消除 ｜ 决策阻塞项已清零 ｜ 无未解决关键冲突
- **B/C 必须**（A 仅部分/如适用）：成功标准可验证（A 如适用）｜ 关键约束已识别 ｜ 事实/假设/推断已区分（来源标签）｜ 认知分类已输出
- **仅 C 必须**：11 维度覆盖（定制版）；**B 部分 / C 必须**：关键假设已列出+验证路径
- **正/反向边界覆盖轮数下限**：A ≥1/≥1 ｜ B ≥2/≥2 ｜ C ≥3/≥3

**【认知分类 = 行动路由器】**（清单整理后输出；不是信息分类器，而是下一步动作路由器；输出快照按下列五行各一行，格式 `· 类别（状态）：____`）：

| 类别 | 状态 | 行动路由 |
|---|---|---|
| 事实 | 已确认 | 通常无需继续验证 |
| 假设 | 待验证 | 影响决策？否 → 保留；是 → 必须验证 |
| AI 推断 | 需验证 | 找依据；必要时转为待验证假设；不得当事实或用户需求 |
| 未知 | 未知 | 是决策阻塞项？否 → 允许保留；是 → 提问 / 实验 |
| 盲区 | 不知道"我不知道什么" | 交给验证里程碑暴露，不硬编 |

**【确证度评分】**（可计算，仅参考不作准入闸门）：
```
确证度 = Σ(每条权重) / 条目数 × 100%
权重：[用户明说]=1.0 ｜ [用户估计·未验证]=0.4 ｜ [AI 推断·需验证]=0.3 ｜ [沉默默认]=0.1
```
输出必须同时给**明细**：`确证度：____%（N 条中：[用户明说] x、[用户估计·未验证] y、[AI 推断·需验证] z、[沉默默认] w 条）+ 拉低评分的条目逐条列出`。每分可追溯到来源；评分低不卡流程（卡流程的是"用户逐条确认"），只提示哪些条目需验证。

## 阶段 3 — 方案输出（强制框架，AI 内部判定 + 输出时用户评审）

> 🎯 **执行锚点**：必须按档位对应模板（A/B/C）输出、必须标注推荐方案、C 档三角色严禁信息互串；禁止为凑"三选一"编造无价值备选、禁止把选择权无理由推回用户。

进入后先输出确认语（完整话术见 `references/plan-templates.md`「进入确认语」）——宣告：需求挖掘结束、约束清单共 N 条（含来源标签）、确证度评分 ____%（仅参考，不作准入；明细见上一步）、按模板 __（A/B/C）__ 输出完整方案。

### 备选原则
只有存在**真实决策分叉**才生成多个方案（先判断：为什么有多条路径？哪个约束导致分叉？不同方案真正牺牲了什么？）。无有意义分叉 → 直接推荐单一方案，**禁止为凑"三选一"制造没有实际价值的方案**。有真实分叉时：方案上限**三个**（超过则只保留决策价值最高的三条，其余在"未采纳路径"一句话说明舍弃理由）；**必须标注推荐方案**并给推荐理由；用户有权否定推荐，但 AI 不得把选择权无理由推回给用户。

### 模板骨架（A/B/C 完整格式与话术见 `references/plan-templates.md`，输出方案前必读）
- **模板 A（轻量）4 模块**：A1 诉求重述（1-2 句）→ A2 推荐方案（明确权衡：放弃了什么，换来了什么）→ A3 快速对抗自查（≥2 条失败场景+规避，具体到触发条件和量级）→ A4 击穿实验 1 行（第一条验证动作 ｜ 证伪后回退）。
- **模板 B（标准）6 模块**：B1 真实诉求重述 & 成功标准 → B2 推荐方案 & 设计权衡（为什么没选其他自然路径）→ B3 方案对比（仅真实分叉时；维度：适用场景/核心优势/主要劣势/落地成本/风险量级/确证依据）→ B4 前置假设与依赖（每条标来源标签+权重；[用户估计]/[AI 推断] 必须给验证步骤，注明失效/降级方式）→ B5 落地步骤 & 可验证里程碑 → B6 核心假设击穿实验。无真实分叉时 B2 一句话说明"为什么没有备选"，跳过 B3，其余模块不变。
- **模板 C（高压）= 模板 B + 三角色分离（角色间严禁信息互串）**：角色 1 方案构建者（按 B1~B6 输出，不加自评）→ 角色 2 红队审查官（逐条攻击，每条攻击必须可追溯到依据——约束清单条目/用户原话/可查事实；编不出依据 = 凑数不计入；不设配额，找不到就如实说）→ 角色 3 终审官（基于攻击结果做**增量修改**，不重写；输出最终确证度、修正关键项、【待用户确认项】、剩余高风险项、逆向验收）。

**完成判定**（AI 内部，不占用户轮次）：方案结构完整、能回溯到核心目标、（C 档）三角色已分离执行；输出时交用户评审。
**回退出口**：方案不可行 / 红队发现重大漏洞 / 用户异议 → 重开本阶段或阶段 2（附录A）。

## 阶段 4 — 对抗式红队自查 + 逆向验收（B/C 强制，A 可选但推荐；模板 C 合并到角色 3）

> 🎯 **执行锚点**：B/C 档必须完整跑 M4-1~M4-4；红队攻击必须每条可追溯到依据（编不出依据 = 不计入）；禁止给无证据的精确概率、禁止把"需用户提供"的未知内部自改（一律回流【待用户确认项】）。

- **M4-1 Pre-Mortem 死因分析 Top 5**：假设方案已彻底上线并最终失败，按可能性从高到低列 5 个"死因"，每条：`死因：____ → 触发条件：____ → 早期信号：____ → 概率量级：高/中/低 → 防死手段：____`。不写"信息不足"空话，必须具体到触发条件、早期信号、量级、前置手段；**禁止没有证据支撑的精确概率数字**。
- **M4-2 反向边界声明（NOT 适用的 3 种场景）**：明确**不适用**的 3 种场景（硬套会失败），每条：`场景描述：____ → 失败模式：____ → 若遇到应该用什么：____`。
- **M4-3 确证度声明 & 提升路径**：确证基础 = 清单 N 条全部经用户确认 + 评分 ____%（见阶段 2，仅参考）+ 未知项见【待用户确认项】；若要再提升一档需补充确认：1. ____ 2. ____。
- **M4-4 逆向验收**：沿追溯链反向核对（无法回溯最初诉求 = 诊断链断裂）：`方案 → 成功标准 → 核心目标 → 约束清单 → 阶段 1 复述 → 最初用户诉求`。核对：核心目标覆盖 ✅/❌；成功标准满足 ✅/❌；清单 N 条逐条核对遵守/规避；关键假设哪些已验证、哪些未验证（进 B6）；未覆盖项 → 【待用户确认项】或"超出本次范围"。B/C 强制，A 建议一两行。

### 溯源标注（全程适用）
关键推理结论后标注**锚点**（不是盖章）：`[用户原话："____"]`；`[来源：<文件> L<行>]`（仅允许标注真实读过的文件）；`[AI 推断·需验证]`。**禁止 `[常识]` 标签**——常识不是锚点，幻觉配上"常识"依然是幻觉；无锚点就不标注。

## 附录A — 动态回退规则表

**核心规则**：新信息只要改变已确认的需求、目标、约束或关键假设，就必须重新打开受影响阶段——不是"更新一个字段继续往下走"。
典型链：清单确认完成 → 方案已输出 → 用户补充新硬约束 → 重新打开阶段 2（更新清单并重新确证）→ 再检查阶段 3 是否需修正。

| 新发现 | 回退阶段 |
|---|---|
| 阶段 1 复述后发现需求理解错误 | 阶段 1 重新复述 |
| 清单逐条确认时推翻关键约束 | 阶段 2 相关分支重挖 + 更新清单 |
| 用户补充新的硬约束 | 阶段 2 更新约束清单 → 检查阶段 3 方案是否受影响 |
| 回答前后矛盾、经用户裁决后 | 更新约束清单 + 重查漂移/冲突检测结论 |
| 目标发生重大漂移 | 阶段 1 复述重开（已知信息保留，不重复追问） |
| 红队攻击击穿关键假设 | 阶段 3 修正方案（C 档走角色 3 增量修正） |
| 逆向验收发现方案偏离真实诉求 | 回退阶段 3 对应模块 |
| 档位升高（A→B、A→C、B→C） | 回阶段 0，重新评估已完成阶段是否满足新档位最低覆盖约束 |
| 档位降低（C→B、C→A、B→A） | 不回退，但须在最终输出声明降档原因及潜在风险 |
| 模式/档位判定被用户异议推翻 | 回阶段 0 按重判协议执行（已知信息保留） |
| 用户在方案输出后才补关键信息 | 按附录A 首行规则回退，方案标注"待重审" |

## 附录B — 异常处理

- **用户拒绝继续回答**（"你直接给方案"）：不无限强问，按风险分流——低风险（A 档）→ 直接给方案但声明假设；中风险（B 档）→ 草案 + 关键假设 + 未知 + 风险；高风险（C 档）→ 明确指出缺什么 + 为什么重要 + 继续决策可能造成什么问题。
- **回答前后矛盾**：禁止自行二选一，指出冲突请用户裁决："你前面说的是 A，现在又说 B。这两点会导致不同方案。请确认当前应以哪一个为准？"
- **坚持错误前提**："你当前的前提是 ____；可能存在问题，依据是 ____；如果不成立，后续方案会发生 ____；请确认：继续坚持还是重新确认？"用户坚持 → 标记 `[用户明确坚持的前提]`，方案继续执行但在 B4 标高风险。
- **判定被异议**：按阶段 0 重判协议——先确认异议实质，不辩护原判定；已知信息保留，不重复追问。
