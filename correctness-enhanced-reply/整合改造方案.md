# correctness-enhanced-reply 整合改造方案

## 决策树分析法（DMA）+ 苏格拉底提问法（SPA）· 内化式版

> 基线：`SKILL.md`（当前版）。配套约束：S1–S11（已全部经用户逐条确认）。
> 一句话总纲：**DMA 决定"下一步问哪个分支"，SPA 决定"这条分支上怎么问到底"；两种方法只重塑提问的血肉，不在文档里产生任何可见框架。**

---

## 1. 改造原则（R1–R4）

| 原则 | 内容 | 依据 |
|---|---|---|
| R1 | **只影响"怎么问"**：不在 SKILL.md 增加任何交付物/嵌套框架；每轮输出仍是 `Qn/n【正向/反向】：一句` | S5 |
| R2 | **红线零改动**：单轮单问、约束清单、来源标签、逐条确认 4 项机制一个字不动 | S6 |
| R3 | **S7 回流有守门**："用户自我推翻"只认用户主动修正信号，AI 不得自行解读加塞 | S7 |
| R4 | **反诘计入 n 问内**：不额外增问，防止问数膨胀触发 S9-③ 配合坍塌 | S9 |

## 2. 四个嵌入点的可直接插入文案

### ① 插入位置：阶段 2 开头（"主导权声明"之后、"五大铁则"之前）

```markdown
### 探测性反诘（进入 n 轮问答前的第一个动作，占 Q1）

对用户清晰表述里**最关键的一个前提**发一句反诘，检验其坚实度：
> "你刚才说『____（引用用户原句的关键结论）』。可是如果____（一个合情反例）呢？"

规则：
- **反诘只能引用用户自己说过的话/结论**为靶子，不得自造前提（防引导性，守铁则 #4）。
- 无论用户是否动摇（有翻转 / 无翻转），都**照常问满 n 问**，反诘不改变问数（S10/S11）。
- 结果只作**过程信号**：
  - 有翻转 → 该前提脆弱，后续问题设计绕到其边界上；
  - 无翻转且给出理由 → 该结论记入约束清单候选（来源 [用户明说]）。
- 这一问**计入 n 问内**（即 Q1/7），不额外增问。
```

**设计亮点（顺带理顺一个旧矛盾）**：反诘是反向约束型问题。以它为 Q1 后，交替序列变成「反向→正向→反向→正向…」——n = 3 / 7 / 11 均为奇数，**最后一问恰好落在反向约束**，天然满足阶段 2 完成判定 #4（"不允许在正向维度中结束"），原"奇数问为正向却要求最后一问反向"的别扭被消解。

### ② 插入位置：阶段 2"五大铁则"之后

```markdown
### 决策树选路（每轮问题如何编排，DMA）

AI 在心中维护一棵**需求决策树**，作为每轮提问的编排依据：
- **根节点** = 需求的核心决策点（目标 / 边界 / 约束）。
- **分支节点** = 回答暴露出的下一个未知（技术 / 规模 / 成本 / 生命周期 / 合规 / 优先级…）。
- **每轮动作**：在当前分支上，选**信息增益最高**的一个未知作下一个问题；按回答结论走下一条分支；已获得 [用户明说] 的分支不重复问。
- **穷举纪律**：每轮决策时，先在心里过一遍"还有哪些可能分支没覆盖"，避免只沿用户熟悉的路径走（S3）。

规则：
- 树**存在心里，不输出成任何可见框架**（S5，单轮单问铁则不变）。
- 正反交替铁则 = 树的左右分支：正向 = 探索上层目标，反向 = 收敛下层边界；二者不冲突（S6）。
- S7 回流（用户推翻）同时**校正树的对应分支**。
```

### ③ 插入位置：阶段 2"输出格式"之后

```markdown
### 苏格拉底追问链 + 反诘（同分支问到底，SPA）

SPA 不是"把 n 个问题问完"，而是**在同一条分支上连续、有结构地问到底**：

1. **追问链**：对用户上一回答里的关键结论，依次连续追问（"依据是什么 / 如果这个条件不成立呢 / 你这个结论的前提是____，对吗"），直到暴露出思维漏洞、或得到坚实结论。
2. **反诘**：对每个关键结论至少反诘一次：
   > "你说『____（用户原句）』，但如果『____（合情反例）』呢？"
   - 只能引用用户原句为靶子；计入 n 问内；不额外增问。
   - 用户因反诘**主动修正/推翻**时，该修正作为新 `[用户明说]` 条目回流约束清单（S7）。
3. **守门（识别"推翻"）**：只认用户主动说出的修正信号——"不对 / 等等 / 我重新想一下 / 之前说错了 / 其实不是"；用户只是附和跟从的，不算推翻，不得回流。
4. **停止**：单分支连追 3 层无新漏洞 → 切到决策树的下一分支；不在单点无限连环（5Why 3 层上限不变，守 S6）。
```

### ④ 插入位置：阶段 0.5"分层提问策略"之后

```markdown
### 问题探索机制（决策树穷举 + 追问链，内化于萌芽期）

- **决策树穷举**：面对模糊感觉，AI 在心里穷举"这个问题定义"的所有可能方向（是效率问题？质量问题？协作问题？认知问题？…），逐个方向用一句开放问题探测用户的痛点归属；用户的应答信号引导剪枝，最终把模糊想法收敛成"某方向上的明确问题"。
- **追问链**：对用户模糊表述里的模糊词连续追问直至含义清晰（"你说的『沉淀』具体指什么？『优化』指什么？"），把笼统说法拆成可验证的具体所指。
- **过程性，不产条目**：此阶段产出的只有"已澄清的问题定义 + 用户确认"，无约束清单条目（S10），供阶段 1 复述使用。
- 原有的**分层提问策略（极度模糊/有方向/有念头）保留为起点框架**，穷举与追问链叠加其上，不替换。
```

## 5. 试跑演示（A 模板 · 3 问，看整合后实际长什么样）

> 用户："帮我设计一个分布式锁方案"（模式 1，措辞清晰）

```
AI：……（阶段 1 复述确认后）
Q1/3【反向约束·探测反诘】：你说"设计分布式锁方案"，但如果你的服务其实单实例、根本不会有并发，锁还有必要吗？
↳ 用户："我们是多实例、有并发。"（无翻转，依据坚实 → 记入约束候选）
Q2/3【正向诉求·决策树选路】：你希望这个锁首要解决哪个问题——防重复处理、资源互斥、还是故障转移时的安全？
↳ 用户："主要是防重复处理，并发量不大。用 Redis 就行。"
Q3/3【反向约束·追问链反诘】：你说"Redis 就行"，但如果将来要跨云容灾，Redis 单点锁的可用性够吗？
↳ 用户："等等，我确实没想过容灾……那还得考虑 Redlock 或数据库锁。"
→ [S7 回流] 新增约束：[用户明说] 不可接受单点，需容灾方案 → 进入清单，方案据此调整。
```

三问分别演示了：探测反诘（①）、决策树选路的目标排序分支（②）、追问链把"Redis 就行"反诘到新增约束（③）。**产生的每一条约束都走回清单 + 来源标签，机制一个没改。**
