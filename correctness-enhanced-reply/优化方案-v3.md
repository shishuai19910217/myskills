# 优化方案：correctness-enhanced-reply SKILL.md 系统性修订

> 版本：v3（接续已删除的 修订方案-v2）
> 定位：独立评审文档，不直接改动 SKILL.md。评审通过后按 M1–M10 落地。
> 依据：对 `SKILL.md` 的两轮对抗式审查（行号引用均指向当前版本）。

---

## 0. 摘要

本方案对 `SKILL.md` 提出一套系统性修订。核心判断：

> **当前版本的"正确性保障"押在单一自报数字——掌握度 ≥95%——而 LLM 自评信心是公认最不可信的输出之一。它是一套精致的提问调度器，不是正确性保障系统。**

两轮审查还暴露了三处**结构性失明**，任何措辞修补都绕不开它们：

1. **用户前提错误时无刹车** —— 流程忠实地把用户错误前提执行得很完美；
2. **未知的未知问不出来** —— 提问只能回收用户已知的约束；
3. **对抗发现无法回流用户** —— 红队挖出的新未知被锁在 AI 内部单方改写。

修订的总体方向：**把信任锚点从"AI 自报数字"移到"用户可验证的确证"，并让方法论的防线落在结尾（验证里程碑），而非开头（提问数量）。**

## 1. 问题清单（合并两轮审查，P1–P19）

### A. 根基性缺陷（决定"这套方法是否真的能防瞎编"）

| 编号 | 问题 | 位置 |
|---|---|---|
| P1 | 正确性阀门是自报掌握度 %。LLM 信心标定不可信，该门只在模型撒谎时才"生效"：诚实模型报不出 95% 会卡死流程，撒谎模型随口盖章形同虚设 | L183 / L273 |
| P2 | 疗效数字（一次正确率 35%→75%、返工 5+→1）无来源、不可证——一个以"不要瞎编"为核心的 skill，第一行宣言就是编造数据 | L9 |
| P3 | "三角色分离"是同一权重扮演三人的幻觉，"严禁信息互串"物理上做不到；配额制"必须攻击成功 ≥1 处 + 攻击数 ≥ 假设数 50%"逼模型在方案成立时硬造批评 | L337 / L342 / L355 |

| 编号 | 问题 | 位置 |

| P4 | 降级规则打架：`选了 C 后不允许降级` vs `误判套高压版直接降级 A`；且阶段 1 话术还邀请用户"换一个更复杂/更简单的模板"，与冻结直接对撞 | L74 vs L439（并见 L155） |
| P5 | 阶段 3 主导权自报家门冲突：总览表归"用户主导"，状态机切换规则却写"用户主导 → AI 主导（AI 进入方案输出）" | L28 vs L34 |
| P6 | "主动收敛"合法绕过 95% 硬门：追加 2 次后 <95% 可提议进入阶段 3，但完成判定 #2 与阶段 3 确认语都要求达标，绕过后百分比无法自洽 | L258 vs L273 / L286 |

| 编号 | 问题 |
|---|---|
| P8 | AI 驱动置信度追加无上限（L184 的"信心<95%→追加"与 L256 的"最多追加3次"是两条独立循环，前者永不触发上限） |
| P9 | 用户随口猜测被洗成高置信假设：B4 的置信度 % 只贴在假设上，不贴用户回答本身的可靠度，"并发大概5000"会记成 90% |

| P11 | 分级轴是**复杂度**而非**出错代价/可逆性**：删库这种简单高代价任务会拿 A（3 问），玩具项目却可能拿 C（11 问+三角色） |
| P12 | 用户前提错误时无刹车："严禁引导"一刀切禁掉了唯一能纠正用户前提的动作（引导性反驳），前提错时流程会产出"把错误前提执行得很完美"的方案 |
| P13 | 红队攻击真的炸掉一条假设时（"完全不成立"），唯一响应是角色内部"打回重做"，新未知被锁在 AI 单方改写，无回流用户的通道 |
| P14 | 五层自评置信度（L286 掌握度 / L322 方案置信度 / L331 假设置信度 / L360 最终方案置信度 / L398 总体置信度）互不约束、无公式关系，纯装饰 |
| P15 | 无验证里程碑：让"用户现在说没补充"≈"这个假设以后不会倒"，却从不要求方案落地后去击穿自己的核心假设——防线缺失在结尾 |
| P16 | 溯源标注是盖章不是溯源：`[常识]` 标签可给幻觉盖章；`[来自 <文件> 第 <段>]` 在纯对话场景无锚点可查，等于给编造引用开后门 |

### D. 体验 / 效率

| 编号 | 问题 |
|---|---|
| P17 | A"轻量版"不轻：复述确认 5 字段 + 3 问 + 3 条失败场景，用户为快点拿到答案常随口"对"，被一个错误基座带飞 |
| P18 | description 触发词模糊（"想优化点什么/萌芽期/先挖后判"），以最低成本的模糊词触发、以最高成本的流程兑现，入口精度与内核雕花失衡 |

## 2. 修订原则（R1–R5）

- **R1 信任锚点**：从"AI 自评数字"移到"用户可验证的确证"——约束清单逐条由用户打钩。
- **R2 求稳成本**：由**出错代价/可逆性**决定，不由复杂度决定。
- **R3 挑战前提**：允许并强制挑战用户前提，但必须带依据、单轮单问、结论回流用户确认。
- **R4 对抗回流**：红队发现的新未知必须列表带回用户，禁止 AI 内部单方改写。
- **R5 防线在结尾**：每个方案必须带"核心假设击穿实验"，把未知的未知交给实验而不是提问。

## 3. 具体修改方案（M1–M10）

### M1 分级轴：复杂度 → 代价 / 可逆性（对治 P11）

- 阶段 0 的"复杂度判定"改为"**代价判定**"，先问两个问题再分级：
  > "如果这个方案错了，最坏代价是什么？能不能回滚？"
- A/B/C 语义重定义：

| 档位 | 语义 | 典型场景 |
|---|---|---|
| A 轻量 | 低代价 / 可逆 | 内部工具、草稿、可随时重来的决策 |
| B 标准 | 中代价 / 部分可逆 | 技术研究、普通架构设计、产品方案 |
| C 高压 | 高代价 / 不可逆 | 代码上线前、对外提案、投资、生产迁移 |

- 复杂度降为代价判定的**次级输入**（复杂但可逆的任务可上 B，不再上 C）。
- 默认判定：无法判断代价时取 B；拿不准是否不可逆时取 C。

### M2 置信系统重构（对治 P1 / P14 / P9）

- **删除"掌握度自评 ≥95%"硬门。** 阶段 2 的完成物改为**约束清单**：
  - AI 把从所有回答中提取的约束/假设整理成清单，**每条标注来源**；
  - 用户逐条确认/修正，**全部确认**后才进入阶段 3；
  - 清单本身成为阶段 3 各模块的引用基础。
- **每条关键信息打来源标签**：`[用户明说] / [用户估计·未验证] / [AI 推断·需验证] / [沉默默认]`。
- **B4 假设置信度只允许贴在"有依据"的假设上**；`[用户估计·未验证]` 一律标"未验证"并给出验证步骤，杜绝"用户随口 5000 QPS 被洗成 90% 假设"。

### M3 挑战用户前提（对治 P12 / P3）

- 在阶段 2 增加一个**合法的非引导行为：反向挑战**。触发条件：用户自述的约束/前提与事实、边界或已知矛盾。
  > 格式："你这条前提可能是错的：原因____。你是坚持它，还是重新确认？"
- 约束：必须有依据、单轮单问、不得指向预设答案。
- 用户坚持 → 记为"**用户明确坚持的前提**"，进方案并在 B4 标高风险。
- 替代 P3 的配额式红队攻击：攻击不再凑数，只打"有真依据"的点。

### M4 红队发现回流用户（对治 P13）

- 阶段 3/4 新增输出模块【**待用户确认项**】：红队攻击中发现的所有"需要用户才知道"的未知，**不得内部自改**，必须列出带回。
- 角色 3 的"剩余高风险未解决项"分两类：`AI 可内部应对` / `必须用户提供信息`（后者必须出现在【待用户确认项】）。

### M5 修复内部矛盾（对治 P4 / P5 / P6 / P7）

- **P4 降级规则统一**：删除"选了 C 不允许降级"的绝对表述。改为：
  - 高代价任务可降到 B（问满 7 问），**不可**降到 A；
  - 低代价任务误用 C 可降 A；
  - 阶段 1 话术保留"换模板"邀请，但明确换档权限。
- **P5 主导权统一**：措辞统一为"阶段 3：**AI 主导输出、用户主导评审**"，状态机与总览表一致。
- **P6 主动收敛改为显式异常通道**：确证度未满时输出固定声明，不再自称达标：
  > "确证度低于阈值（原因：____）。以下方案请按草案对待，风险自担。"
- **P7 阶段 0.5 例问改开放**：删掉"是 X、Y 还是 Z？"的选择式引导，改为：
  > "过去一周里，有没有哪次找资料/做方案花的时间明显比你预期长？当时是什么情况？"

### M6 溯源标注改为锚点（对治 P16）

- **删除 `[常识]` 标签**（可给幻觉盖章）。
- 溯源必须指向锚点：**引用用户原话语 / 可查数据源 / 或明确标"AI 推断"**。
- 无锚点不标注；文件引用只允许出现在真实读过的文件上（附 `file_path:line`）。

### M7 追加验证里程碑（对治 P15）

- 阶段 3 三个模板**强制**新增模块【**核心假设击穿实验**】：
  1. 方案落地后**第一条要做的验证/证伪动作**是什么；
  2. 若被证伪，回退方案是什么。
- B/C 强制，A 建议（与 M10 的压缩方向一致：A 用一行写出即可）。

### M8 循环上限与边界（对治 P8 / P10）

- **AI 驱动追加设硬上限 +5 问**，到顶走"信息不足"退出或低确证度异常通道。
- **回答冲突规则**：发现 Qx 与 Qy 冲突 → 表面冲突 + 请用户裁决，不得自行二选一。
- **用户拒绝规则**：连续 3 次"你随便给 / 差不多就行" → 走低确证度异常通道，不再硬问。

### M9 触发面精化（对治 P18）

- description 触发词从模糊词改为**任务特征词**：`高代价 / 不可逆 / 返工≥2 / 明确要求高精度`。
- 删除"想优化点什么 / 萌芽期 / 先挖后判"这类会让重流程误触发的词。萌芽期深挖仍保留，但触发条件改为"用户只有模糊感觉**且最终要产出方案**"。

### M10 轻量路径（对治 P17 / P19）

- A 模板复述确认从 **5 字段减为 2 字段**（核心目标 + 成功标准）。
- A3 失败场景从 3 条减为 2 条。
- C 模板 11 问维度表生成增加**自检**：生成的维度表须通过一次"是否正交、是否覆盖代价轴"检查后再执行。

## 4. 保留不动

以下部分经审查确认**有效**，修订中保持原样：

- **单轮单问**（真正的提问纪律）
- **正反向交替**（第 1、3、5…问正向，第 2、4、6…问反向）
- **Pre-Mortem 死因分析 Top5**（Klein 的 pre-mortem，成熟技术）
- **反向边界声明**（明确 NOT 适用的场景）
- **"是否还有补充"语义信号表**（具体可执行）
- **追加循环机制**（上限明确化：用户驱动 +3 / AI 驱动 +5）

## 6. 实施步骤

1. 重写阶段 0：代价/可逆性判定（M1）。
2. 重写阶段 2：约束清单确认 + 来源标签 + 上限与冲突/拒答规则（M2 / M8）。
3. 重写阶段 3：反向挑战、【待用户确认项】、核心假设击穿实验（M3 / M4 / M7）。
4. 修复四处内部矛盾：降级规则、主导权措辞、主动收敛异常通道、阶段 0.5 例问（M5）。
5. 更新溯源规则与 description 触发词（M6 / M9）。
6. 压缩 A 模板（M10）。
7. 交叉验证（见下）。

## 7. 验证方式

- **压测**：用 cangjie-skill 阶段 4 方法，同一组 20 条 case，三组对照（原版 / 本方案 / 不用 skill），五维评测表打分。
- **置信度校准检查**：每 20 次执行后统计——自评"高置信"的方案事后被用户打回的比例。若未下降，说明机制仍停留在形式，需要继续收紧锚点（M2）。
- **矛盾复查**：对修订稿再跑一遍两轮审查的问题清单 P1–P19，逐条确认已闭合。
