# 阶段 2 追问工具箱与补充窗口细则

> **归属**：`correctness-enhanced-reply` 阶段 2 外移文件。主文保留铁则、特征识别路由表、提问优先级与完成判定；本文件按需读取——① 开场命中可反诘前提 / 前提未验证 / 需同分支深挖 / 动机不明时读第一~四节；② C 档进入阶段 2 前读第五节；③ 进入补充窗口时读第六节。

## 一、探测性反诘（原固定 Q1，现为路由工具）

对用户清晰表述里最关键的一个前提反诘："你刚才说『____（用户原句的关键结论）』。可是如果____（一个合情反例）呢？"

- **触发**：特征识别命中「方案锚定 / 因果假设 / 用户方案可能不是需求 / 证据不足」等含可反诘前提的特征时，作为该分支的首选工具。
- **只能引用用户自己说过的话/结论**为靶子，不得自造前提（防引导，守铁则 #4）；同样须有依据、单轮单问、不指向预设答案。
- 结果只作**过程信号**：有翻转 → 前提脆弱，后续问题绕到其边界；无翻转且给出理由 → 记入约束清单候选（`[用户明说]`）。
- 它是**反向挑战（铁则 #3）在开场轮的特例**；反向挑战在后续任意一轮发现前提与事实矛盾时触发。

## 二、苏格拉底追问链 + 反诘（同分支问到底）

1. **追问链**：对上一回答的关键结论连续追问（"依据是什么 / 条件不成立呢 / 前提是____，对吗"）直到暴露思维漏洞或得到坚实结论。
2. **反诘**：对每个关键结论至少反诘一次："你说『____（用户原句）』，但如果『____（合情反例）』呢？"只引用原句为靶子，计入本轮，不额外增问。用户因反诘**主动修正/推翻**（"不对 / 等等 / 我重新想一下 / 之前说错了 / 其实不是"）→ 修正作为新 `[用户明说]` 回流约束清单；只是附和跟从不算推翻、不得回流。
3. **停止**：单分支连追 3 层无新漏洞 → 切下一分支，不在单点无限连环。

## 三、动机深挖（5Why）

- **触发**：用户的"方案"未必是真正要解决的问题；正向诉求模糊、动机不明（顺带质疑需求真假）。只追动机不扩维度。
- **形式**：单轮单问，编号标【动机深挖】（例：`Q5【动机深挖】：你提到要加"冲突检测"，为什么这件事对你是问题？背后真正让你不舒服的是什么？`）。
- **上限**：同一主题最多 **3 层**，问出真正动机即停。不违反铁则 #4（开放问题只纵向问为什么）、#1（每轮只问 1 个）。

## 四、前提证据检验（认知边界探测）

> **目的**：探的是**用户的认知边界**——方案推理链的每一环，哪些是他验证过的、哪些只是推测。来源标签能区分 `[用户明说]` 和 `[用户估计·未验证]`，但那个区分是被动的；本工具主动把"用户估计"显式转化为三档分档，防止整个方案建立在未经验证的地基上。

**触发**：特征识别命中「方案锚定 / 用户方案可能不是需求 / 因果假设 / 证据不足」时，本工具**优先于一切细节问题**（主文「提问优先级·前提检验优先」）；主文进入声明的挖掘路线图中，前提检验分支须排在细节分支之前。

**话术模板**（单轮单问，只引用用户原话为靶子）：

```text
你说『____（用户方案的某一环）』——这一环的依据是什么？
是你（或团队）实际验证过，还是一个合理推测？若验证过，结果是什么？
```

**产出：前提三档分档**（对方案推理链的每一关键环打档，记入约束清单候选）：

| 档位 | 判定信号 | 行动路由 |
|---|---|---|
| **已验证事实** | 用户给出验证过程/结果；或 AI 可自行查证（真实文件/数据，须真实读过） | `[用户明说]` / `[来源：____]`，直接进方案 |
| **未验证假设** | 用户自认推测，或给不出依据 | `[用户估计·未验证]`；可低成本验证 → 转验证实验（进 B6）；不可低成本验证 → B4 标高风险 |
| **不可验证** | 现阶段无法获得证据 | 显式声明 + 交给验证里程碑暴露，不硬编 |

**停止**：方案推理链每一环都已有档位（或显式标为盲区）即停；单环追问 ≤3 层，与苏格拉底追问链共用上限。

## 五、C 档维度覆盖清单（11 问正交维度表）

| # | 正交维度 | 本质信息 |
|---|---|---|
| 1 | 应用场景 / 业务场景 | 用在哪、服务谁、使用频率 |
| 2 | 核心痛点 / 目标排序 | 最痛的问题、目标优先级 |
| 3 | 技术栈 / 已有基础设施 | 实现成本和性能上限的硬边界 |
| 4 | 遗忘 / 淘汰 / 生命周期 | 资源膨胀的控制手段 |
| 5 | 跨会话 / 跨模块的数据类型 | 存储结构和召回策略 |
| 6 | 落地规模 / 并发 / 吞吐量 | 索引结构、成本模型、召回策略 |
| 7 | **正确性校验（反向约束）** | 人工确认 + 冲突检测 + 错误回滚？能否接受污染？ |
| 8 | 部署 / 隐私 / 合规 | 云 vs 本地、数据能否外传、合规要求 |
| 9 | 时延 / 成本预算上限 | 缓存 / 预计算 / 双阶段召回，还是不计成本 |
| 10 | 写入 / 变更策略 + 可解释性 | 写入一致性 vs 人工审核可行性、溯源要求 |
| 11 | 结构化程度 / 冲突处理 | 强制类型？非结构化？冲突时覆盖/双版本/人工裁决？ |

> 上表是 Agent 记忆体系的通用化版本；非技术架构任务在阶段 1 复述后先定制专属 11 问维度表（写在阶段 1 输出末尾），先自检（正交 + 代价轴覆盖）再执行。

## 六、补充窗口（完整话术与循环保护）

**窗口话术（必须输出，给用户发现遗漏的机会，不是形式确认）**：

```text
目前我们已经确认：
· ____
· ____
在整理约束清单之前，还有没有你认为重要、但刚才没有提到的信息、目标、约束或背景？
如果没有，可以直接说"没有"。
```

**用户意图判定（语义识别全表）**：

- **没有更多**（→ 进清单整理）："没有了 / 没了 / OK / 可以了 / 够了 / 就这样 / 没问题了 / 不用了 / 差不多了 / 无 / 没什么了"、摇头/表情符号等否定信号。
- **还有补充**（→ AI 追加 1 问，循环继续）："还有 / 补充 / 对了 / 还有一个 / 我再想想 / 另外 / 顺便 / 差点忘了"等。
- **意图不明**（"嗯..."、"让我想想"、"可能吧"）→ 追问 1 次："你是还有补充想提，还是目前已经够了？"仍不明确视为"没有更多"。

**循环保护机制**：

| 保护规则 | 说明 |
|---|---|
| **用户驱动追加上限** | "还有补充"最多 **3 次**，到顶强制进入清单整理 |
| **AI 驱动追加上限** | 分档覆盖未满足（如 C 档 11 维度未覆盖/暴露新维度）可自行追加，硬上限 **+5 问**；到顶仍未覆盖 → 「严重信息不足」退出（附录B）或低确证度异常通道 |
| **回答冲突** | 后续回答推翻前面 → **不得自行二选一**：表面冲突 + 请用户裁决（附录B） |
| **用户拒绝** | 连续 3 次"你随便给 / 差不多就行"→ 低确证度异常通道，不再硬问 |
| **主动收敛** | 追加 2 次后关键维度仍未覆盖 → 主动声明："目前确证度不足（缺：____），继续问边际收益在下降。我可以先出**草案**（标注风险自担），或你补齐 ____ 后再正式输出。"由用户二选一 |
| **补充改变检查** | 补充窗口新信息若改变需求/目标/约束/关键假设 → **回退受影响阶段**（附录A），不得只更新字段继续走 |

**追加提问格式**：`Q<轮数>【<类型>·补充+<次数>】：<问题>`
