## 附录C — 典型失败模式 & 防御手段

| 失败模式 | 行为 | 防御方式 |
|---|---|---|
| 引导性提问 | "你想用向量数据库对吧？" | 重写成开放问题，且问题必须标【正向/反向】 |
| 用自评信心跳过确证 | "我已经 98% 懂了，直接输出" | 完成判定是【约束清单】逐条确认，**不是**自评百分比。清单未确认 = 打回阶段 2 |
| 问满即停 | A 档问满 3 问但决策阻塞项未清就进方案 | 完成判定看分档最低覆盖约束 + 无决策阻塞项，不看问数 |
| 为问而问凑轮数 | 约束已确证仍硬问满参考轮数 | 停止条件含"信息增益明显下降"，允许提前停止 |
| 机械正反交替 | 高价值未知被"该轮问反向了"拦住 | 优先级驱动：阻塞项/信息增益 > 覆盖 > 平衡；双向覆盖是出口约束 |
| 默默执行用户错误前提 | 用户说"必须用老单体"，AI 照做 | **必须**发起反向挑战（带依据）；用户坚持则记"用户明确坚持的前提"并标高风险 |
| 对抗自查走过场 | "失败：信息不足 → 解决：补信息" | 写清楚触发条件、早期信号、概率量级、对应前置手段。空话 = 打回 |
| 红队凑数攻击 | 找不到依据硬编攻击点 | 攻击必须追溯依据；编不出依据的攻击不计入 |
| 红队发现的新未知内部自改 | 攻击炸掉假设后 AI 自己重写 | 所有"需要用户才知道"的未知 → 列入【待用户确认项】带回用户 |
| 给虚假精确概率 | Pre-Mortem 写"失败概率 37.2%" | 使用触发条件、早期信号、量级而非伪精确 |
| 简单任务套高压版 | "晚饭吃什么" 用 C 模板 | 阶段 0 代价判定：低代价误判 C 可降 A |
| 高代价任务降档过头 | C 任务被降成 A（3 问） | 换档权限：高代价可降到 B、**不可降到 A** |
| 档位升高不回退 | A→C 后继续用 A 档的浅结论 | 升档强制回阶段 0 重评，不满足新档覆盖约束的阶段全部重开 |
| 一次抛多个问题 | 一轮输出 5 个问题 | 打回并只保留最关键的 1 个，剩下的后续轮次慢慢问 |
| 三角色信息互串 | 角色 2 复用角色 1 的推理逻辑 | 每个角色独立思考；角色 2 攻击必须带独立依据 |
| 萌芽期直接跳方案 | 用户说"感觉要优化知识沉淀"，AI 直接出方案 | 阶段 0 判定为模式 2 时，**必须**走阶段 0.5 成形 |
| 深挖走过场 | 阶段 0.5 只问了 2 个问题就跳到阶段 1 | 深挖必须挖到用户能清晰说出"问题+场景"，且 AI 复述确认 |
| 深挖超时不终止 | 挖了 10+ 轮仍无进展，硬撑 | 触发 10 轮兜底，输出终止话术 |
| 挖掘完不问补充 | 停止条件满足后不问用户是否有补充 | **必须**执行补充窗口 |
| 追加循环死循环 | 用户反复追加 / AI 自信不足无限加问 | 上限：用户驱动 3 次 / AI 驱动 +5 次，到顶强制进入清单整理 |
| 追加意图误判 | 用户说"差不多了"被误判为"还要补充" | 语义信号表优先匹配，意图不明时追问 1 次 |
| 回答冲突自行二选一 | Q7 与 Q2 矛盾，AI 自己挑一个 | 表面冲突 + 请用户裁决 |
| 用户拒答仍硬问 | 用户说"你随便给"AI 继续追问 | 连续 3 次 → 低确证度异常通道 |
| 溯源盖章不溯源 | 编一个"常识"给幻觉背书 | 禁 `[常识]`；溯源必须指向用户原话 / 真实文件 / AI 推断 |
| 5Why 连环无上限 | 动机追问连环不停，轮数失控 | 同一主题最多追 3 层，问出动机即停 |
| 缺认知分类 | 把"AI 推断"当事实、盲区硬编 | 约束清单后必须输出认知分类自查，盲区交给验证里程碑 |
| 新信息只更新字段不回退 | 用户补充硬约束后，AI 改一行继续原方案 | 结论变化即重开受影响阶段（附录A） |
| 把"主题明确"当"需求明确" | 用户说"我想学 X"就当需求已确认 | 主题≠目标≠需求；至少确认期望结果与关键歧义 |
| 用户附和当推翻 | 用户顺着反诘点头就改结论 | 只认主动修正信号（"不对/之前说错了"等） |
| 输出后不回核对 | 方案输出完就结束，不比对真实需求 | 强制【逆向验收】，沿追溯链回到最初诉求逐项核对 |
| 每轮都让用户确认 | 每问一句就复述一遍求确认 | 按出口模式表执行：确证只在阶段关闭节点 |

## 与其他 Skill 的边界与协作

- 和 [grilling](file:///d:/owned/ai/xuexi/.agents/skills/grilling/SKILL.md) 的区别：**grilling 是对「用户已有方案」进行拷问打磨**，而本 skill 是**在「产出方案之前」先把需求挖干净再出方案**。流程是：先 correctness-enhanced-reply 挖需求 + 出方案初稿 → 再 grilling 拷打方案细节（用户需要时）。如果用户只有模糊想法，先经过本 skill 的阶段 0.5 成形，再走后续流程。
- 和 [0027 对抗式复杂技术研究法](file:///d:/owned/ai/xuexi/.agents/skills/teach/lessons/0027-adversarial-research-methodology.html) 的关系：0027 是**技术研究主题**的实战化版本（包含了 L0-L3 记忆体系的专属 11 问维度和专属 7 模块交付框架），本 skill 是**通用场景模板**，可应用于任何复杂决策 / 方案产出。
- 和 [cangjie-skill 阶段 4 压力测试](file:///d:/owned/ai/xuexi/.agents/skills/cangjie-skill/methodology/06-stage4-pressure-test.md) 的关系：压力测试用来**验证本 skill 的真实效果提升**——对同一组 20 条 case，分别跑"不用 skill" vs "用 skill"，用五维评测打分表量化对比。
- 和 need-diagnosis 的分工：need-diagnosis 是**需求诊断决策引擎**（问题状态机 + 需求模型 + 方案决策全链路）；本 skill 是**回复正确性增强引擎**，聚焦"先挖透再输出 + 对抗自查"。两者机制同源（约束确证 / 动态回退 / 来源分级），按用户激活的 skill 执行，不叠加运行。

## 验证方式（本 skill 自身）

- **压测**：用 cangjie-skill 阶段 4 方法，同一组 20 条 case，三组对照（原版 SKILL.md / 本版 / 不用 skill），五维评测表打分，量化对比。
- **置信度校准检查**：每 20 次执行后统计——自评"高置信"的方案事后被用户打回的比例。若未下降，说明机制仍停留在形式，需继续收紧锚点（约束清单 + 溯源）。
- **回退健康度检查**：每 20 次执行后统计——新信息出现时实际触发回退（附录A）的比例 vs 只更新字段继续走的比例。若回退率趋近于零，说明回退机制停留在纸面。
- **矛盾复查**：对修订稿再跑一遍两轮审查的问题清单 P1–P19，逐条确认已闭合。

> 每次执行完后，如果用户反馈"有偏差"，把偏差点记录到你的会话记忆里，下次执行时在阶段 1 末尾主动规避。
