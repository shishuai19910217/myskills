# codebase-onboarding 技能包 README

> 本 skill 把陌生/遗留代码库转化为带行号证据的分层认知资产（L0–L6），并按需产出功能认知卡（L7）与影响半径清单（聚焦模式二开前）。证据逐条可回溯，运行时结论 100% 带验证方法，不编造。

## 1. 技能使用说明

### 触发词

- 看懂系统类：`帮我读懂这个系统 / 梳理一下这个库 / 逆向分析 xxx / 生成 onboarding 文档 / 新人入门文档 / 系统架构梳理 / 深度分析这个代码库`
- 影响半径/二开类：`评估影响半径 / 二开前评估 / 改 X 会影响哪些地方 / 功能认知卡`

### 输入参数

| 参数 | 必填 | 默认 | 说明 |
|---|---|---|---|
| `repo_path` | 否 | 当前工作目录 | 目标代码库路径 |
| `output_dir` | 否 | `docs/ai-onboarding` | 输出目录，须独立于源码文件，防循环论证 |
| `focus` | 否 | 全量 | 业务域/链路关键词，命中者优先；亦为聚焦模式触发 |
| `business_hints` | 否 | — | 业务背景、术语表、外部系统说明 |
| `output_depth` | 否 | `full` | `full`=全量 L0-L6；`layer`=指定层级；`single`=单功能深挖 |

### 输出（3+1 文件）

- `README.md`：导航、阅读路线、覆盖率声明、核心结论、待确认 Top 5。
- `01-architecture.md`：架构总览、技术栈、模块依赖、调用链、变更影响。
- `02-business-flows.md`：链路全景、节点表、异常分支、功能详细清单。
- `03-data-api-map.md`：数据载体、表结构、操作矩阵、状态机、接口映射。
- `references/`：`output-spec.md` / `verification-checklist.md` / `impact-analysis.md` / `anti-patterns.md`（规范、验证、影响半径、避坑）。
- `examples/refund-flow-example.md`：L0-L6 格式样例（虚构）。

## 2. 触发词对照

| 场景 | 推荐动作 | 备注 |
|---|---|---|
| 用户说“帮我读懂这个系统” | 走全量流程，产出 3+1 文件 | 默认优先 |
| 用户说“改 X 会影响哪些地方” | 聚焦模式，先完成 L0-L5，再产出 L6 影响半径 | `focus` 命中即触发聚焦 |
| 用户说“二开前评估” | 聚焦模式 + L6 表格 + 扩展点优先级 | 影响半径为必要交付 |
| 用户说“生成 onboarding 文档” | 产出 README 为主的 3+1 文件 | 新人可直接看 README |

### 与其他 skill 区别

- `graphify` 做问答式代码关系查询；本 skill 做一次性可交付文档包。
- `reverse-engineer-anything` 针对无源码黑盒；本 skill 针对有源码目标。无源码仅二进制时引导到后者。

## 3. 快速开始（完整流程）

1. 确认 `repo_path`：未指定时默认当前工作目录。
2. Stage 1 预扫描：数源文件总量 → 技术栈/入口/数据载体/配置/测试 → 排除清单命中项。
3. Stage 2 模式判定：全量（默认）或聚焦（`focus` 参数/用户提“要改/要加”）。
4. Stage 3 链路定位：按入口存在性列候选链路；只有一两条时写明判定依据。
5. Stage 4 分层产出：L0→L6 逐层，每层先写信息来源声明，每条结论挂 `文件:行号`；L7 按需产出。
6. Stage 5 验证标注：静态给不了的运行事实统一标注 + 附验证方法，一套标注体系。
7. Stage 6 自检交付：比对 §7.4 五条 + §12 门禁；门禁不满足不宣称完整。

### 完成判据

- 每层落盘且每条结论有来源。
- 运行时结论 100% 带验证方法。
- README 写明覆盖率 X/Y + 未覆盖范围与原因。
- 所有 Mermaid 图与表格语法有效。

## 4. 覆盖率声明位置

- 分层产出（L0–L6）时，每层开头写**信息来源范围声明**（读取了哪些文件/目录）；覆盖率数字写在**产出包的 README** 里（这是产出物的 README，不是本文件）。
- 产出包 README 必须含：总数 Y、完成数 X、未覆盖范围与原因的覆盖率声明（R4）。
- 聚焦模式（`focus` 命中）产出包 README 必须写“聚焦范围 X/Y，非全覆盖”（R5）。

## 5. 注意事项

- 只读不改：禁止 Edit/Write 源码、`git checkout/reset/clean`、装依赖、起服务。唯一写入范围 = `output_dir`。
- 证据可追溯：每条结论挂 `文件:行号`，无证据不写。
- 运行时材料缺失：只标注不出结论，统一写 `[待确认：<验证方法>]`。
- 密钥/token：读到一律脱敏，明文不进文档。
- 本 skill 产出包内的 README 模板（导航/阅读路线/三条最重要结论/待确认 Top 5）见 `references/output-spec.md`。
