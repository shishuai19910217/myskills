# 运行时验证清单 + 静态兑现边界表

**总口径（铁律）**：静态给的是**结构事实**（有什么入口/表/调用/配置）；静态给不了的是**运行事实**（实际频次、真实 topic、DB 现值、谁在用、谁负责）。后者一律标 `[待确认：<验证方法>]`，不得据命名猜测下结论。

## 1. 九项运行时验证清单与静态兑现边界

| # | 验证项 | 静态可兑现 | 静态能拿到的部分 | 需运行时验证的部分 / 方法 | 对应层 |
|---|---|---|---|---|---|
| 1 | 入口是否齐全 | 部分 | 路由/`@Scheduled`/MQ 消费者注解可 grep（含注册式路由） | Swagger 页面、网关路由表、MQ 控制台实际订阅；启动后对 Swagger / 控制台 | L0、L1 |
| 2 | 菜单/权限功能地图 | 否 | 仅 Controller 与鉴权注解 | 菜单/权限多在 DB 或独立后台；查菜单权限表、产品文档 | L1 |
| 3 | 核心链路真实走向 | 否 | 代码层调用链（codegraph + Read） | 日志 / APM / 链路追踪 / 抓包；预发跑单链路取 trace | L2 |
| 4 | 状态机 DB 实际值 | 半 | 枚举类/状态迁移代码 | DB 现值与历史脏数据；连库 `distinct` 状态字段 | L3 |
| 5 | 核心表清单 / ER | 是（有 schema 时） | migration/schema、Mapper/XML 可还原表与关系 | 无 DB 系统按 SKILL §7.2 降级为载体键结构；运行库与 schema 漂移需连库核对 | L4 |
| 6 | 表数据流转（谁写谁读） | 否 | 代码侧读写点可定位 | SQL 日志 / binlog / MQ 控制台验证真实流向 | L5 |
| 7 | 定时任务 / MQ 真实触发 | 部分 | Job 配置、注解、topic 常量 | 实际触发频次、死信、消费组；调度器/MQ 控制台 | L0、L2、L5 |
| 8 | 外部依赖连通性 | 部分 | 客户端配置、接口定义 | 真实地址/鉴权/可用性；联调环境实测 | L0 |
| 9 | 影响半径（L6） | 部分 | IDE Call Hierarchy、grep 反向调用、配置键引用 | 配置中心运行值、灰度/报表下游；查配置中心 + 问负责人 | L6 |

## 2. 三条补充边界

- **阶段定链路**：HTML 要求“结合入口频次推断 3–5 条核心链路”（`deepseek_html_20261019_304437.html:498`）——频次是运行时数据，静态只有**入口存在性**；按存在性列候选，频次一律不编。
- **L7 功能卡**：负责人/测试方式/日志监控在代码里不存在，静态只能留空标注；方法：与功能负责人对齐。
- **多仓微服务**：v1.x 仅支持单仓/多模块；跨仓调用的真实拓扑属运行事实，多仓聚合列 v2.0，本版不宣称支持。

## 3. 按层静态兑现边界（补充分层速查）

| 层 | 需要运行时验证的内容 | 静态可兑现 | 静态兜底动作 |
|---|---|---|---|
| L0 | Swagger 页面、MQ 控制台真实主题 | 部分 | `@Scheduled`/路由/消费者注解可 grep；运行时项标注 |
| L1 | 菜单、权限表、产品文档 | 否 | 不在仓库即标 `[待确认：<验证方法>]` |
| L2 | 日志、APM、链路追踪、抓包 | 否 | 只画代码可证的调用与节点 |
| L3 | DB 状态字段实际值 | 半 | 枚举/迁移代码全可查；DB 实际值标注 |
| L4 | 数据库实际 schema | 是（有 schema 时） | 无 DB 按 §7.2 降级为载体键结构，不留空表 |
| L5 | SQL 日志、binlog、MQ 控制台 | 否 | 写读代码可证；真实数据流标注 |
| L6 | 配置中心运行值 | 部分 | grep 反向查可证；运行值标注 |
| L7 | 负责人/测试方式/日志监控 | 否 | 代码可查字段填证据；不可查字段标注，不编 |

## 4. 标注格式（唯一一套）

- 无标注 = 有代码证据。
- `[推断]` = 基于上下文推测，须写明为什么推断。
- `[待确认]` = 代码里查不到，须写明向谁确认 / 如何验证。
- 运行时结论：`结论 [待确认：<验证方法>]`，例：`refund.success 由 payment-service 发出 [待确认：查 MQ 控制台生产者]`。
- 不使用 `【待验证】`（废弃，不与 `[待确认]` 并存两套）。

## 5. 不允许的降级

1. 不读运行时材料却宣称完整（门禁必判负）。
2. 用“通常/一般”替代具体来源（禁止编造门禁）。
3. 因缺运行时材料而留空节（应写“不适用声明 + 原因”或“缺层 + 补齐路径”）。
4. 多仓聚合：v1.x 仅支持“单仓/多模块”，多仓为 v2.0 远期，不得在当前版本声称支持。
