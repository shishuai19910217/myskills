# 已知坑与避坑清单（12 条去重合并；由旧版 6 条 + 新方案 8 条合并去重而成）

每条含：坑 / 后果 / 规避。落文档时可在“证据位置”栏补本仓库对应 `文件:行号`。

| # | 坑 | 后果 | 规避 |
|---|---|---|---|
| 1 | 大仓库一开始读所有代码 | 陷入细节、上下文溢出，无法形成整体认知 | Stage 1 先数规模、定模式；先七层后深挖；每完成一份立即落盘；`impact`/`explore` 只查核心符号，不做全量符号枚举 |
| 2 | 只信仓库文档和 AI 结论 | 幻觉、过时信息、循环论证 | 以 Read 实读代码为最终依据；冲突时以代码原文为准；`output_dir` 全程排除，不把自己产出当证据 |
| 3 | 静态分析抓不到动态行为却硬写 | 动态分发/反射/配置化路由结论失真 | 结合测试与日志线索，标 `[待确认：<验证方法>]`，不硬猜、不画没有代码证据的运行结论 |
| 4 | 接口定义与实现对不上不交叉验证 | 文档写的接口实际不存在或签名不符 | 四处交叉验证：路由定义、实现函数、`*Mapper.xml`/`@Select`、`CREATE TABLE`；对不上显式写明“定义存在但无实现/实现存在但未暴露” |
| 5 | 业务规则代码里没有却编造 | 产出含主观臆造，信任崩塌 | 不编；对应文档写 `[待确认]` 并在 README 待确认清单交业务方，注明向谁确认 |
| 6 | 忽略配置、定时任务、MQ、权限、审计 | 影响半径严重低估 | L0 入口清单强制覆盖 Job/Cron/MQ Consumer/权限点；§4.2 六类信息逐项销项 |
| 7 | 忽略数据兼容与回滚 | 上线即事故 | L6 强制填“回滚”与“测试范围”；评估 DDL 可回滚性、接口向后兼容、灰度方案 |
| 8 | 把菜单当功能地图 | 业务认知残缺 | L1 必须含角色与链路，菜单仅作参考；权限/菜单多在 DB，不在仓库即标注 |
| 9 | 只画静态图不验证 | 图表漂亮但不可信 | 每层附验证清单（见 `verification-checklist.md`），运行时结论 100% 带验证方法 |
| 10 | 把 `dist/` 当代码证据 | 编译产物陈旧、与源码不一致 | 双份目录只引 `src/`，README 注明双份关系；`dist`/`target`/`build` 进排除清单 |
| 11 | 改公共代码当低风险 | 连锁故障 | 横向扫描 + Call Hierarchy 向上游追踪；按扩展点优先级优先走配置/SPI/继承/切面 |
| 12 | 二开后不更新文档 | 认知资产快速贬值 | 二开完成后强制回灌本文件与 outputs；新坑、新验证方法沉淀到本清单 |

## 新方案降级回退拦截清单（立项卡 §1.3，不得照抄）

| 新方案写法 | 为什么拦 | 本 skill 的处置 |
|---|---|---|
| 每层只写“信息来源目录”（如 `src/order/controller/`） | 削掉 R2 行号级证据 | 目录只作每层开头的**范围声明**；每条结论仍挂 `文件:行号` |
| “优先覆盖核心链路，不做全量穷举” | 削掉 R4 覆盖率声明 | 全量模式必须 X/Y 声明；聚焦模式 README 写“聚焦范围 X/Y，非全覆盖” |
| “至少 3 条核心链路”门禁 | 小系统只有 1 条链时逼编造 | 按系统实际数量；仅一两条时写明判定依据（为什么其余入口不算核心链路） |
| “L0–L6 七层齐全必过”无条件门禁 | 缺运行材料时无法齐，逼凑数 | 允许“缺层 + 原因 + 补齐路径”；L7 本就是可选层 |
| L6 表格三行列数 7/6/3、无表头分隔 | 自带模板不可渲染，被自己的表格门禁判负 | 重构为 9 列表头（见 `output-spec.md` L6 节），缺字段写“—”不省略 |
| 声称支持“微服务多仓聚合” | 与自身版本规划冲突（多仓在 v2.0） | v1.x 仅声明“单仓/多模块，多仓远期支持”，输出不做多仓汇总 |
| 标注两套并存（`[待确认]` 与 `【待验证】`） | 执行者无所适从 | 全文一套：无标注/`[推断]`/`[待确认]`；运行时追加 `[待确认：<验证方法>]` |
