# 小说大纲摘要生成器 Skill — 设计文档

> **版本**：v0.1（设计评审通过，待落地 SKILL.md）
> **交付物形态**：skill（纯提示词 skill，无独立运行时）
> **落地路径**：单 SKILL.md + 平台规则资源区 + 可选 eval 夹具
> **关联仓库**：`D:\owned\ai\myskills`（与 `webnovel-quality-check`、`webnovel-reading-health-check`、`webnovel-deai-lint` 构成网文创作链的前置环节）

---

## 1. 背景与目标

### 1.1 问题

网文作者或"零灵感"用户想从零搭故事骨架，但：

- 面对空白页不知道该写什么，也说不清自己想写什么；
- 现有 skill（质量检查 / 追读体检 / 去 AI 味）都是**创作后置环节**，缺"从 0 到大纲"的前置环节；
- 直接问大模型"给我个大纲"会得到**随机性强、与平台爆款逻辑脱节、不可迭代**的一次性输出；
- 用户经常不知道自己该上哪个平台（番茄 / 七猫），平台赛道规则（爆款 / 避雷）差异大，且这两套规则散落在公开资料里，作者记忆成本高。

### 1.2 目标

设计并实现一个 **小说大纲摘要生成器 Skill**：以"平台层 → 输入层 → 种子层 → 选择层 → 展开层 → 迭代层"六层系统运行，让用户在零输入 / 弱输入 / 有明确偏好三种状态下都能拿到 **对齐目标平台爆款赛道**、**具备完整三幕展开潜力**、**可继续迭代** 的故事骨架。

### 1.3 成功标准（可验证）

1. 零输入 / 弱输入时，**不问一句话**直接产出 3 个故事种子；
2. 每个种子是包含 主角+欲望+阻力+代价 的完整微型故事前提，且三幕可展开性可自证；
3. 3 个种子之间至少有 2 项差异（题材 / 情感 / 结局倾向 / 冲突类型）；
4. 所有种子与展开内容**落在目标平台的爆款赛道内、避开避雷区**（平台合规硬约束）；
5. 用户选中种子后，一次性输出完整三幕大纲摘要（不分步确认），并附平台节奏检查；
6. 大纲输出后主动附"可修改旋钮"，用户任意调整后基于当前大纲**连贯迭代**（非推倒重来）；
7. 平台切换（番茄 ↔ 七猫）后自动重配赛道约束。

### 1.4 非目标（Out of Scope，v1 不做）

- 章节级正文生成（本 skill 只到大纲摘要，不写正文）；
- 完整大纲的细化到章（只做"三幕摘要"骨架，细化留待后续 skill 或用户自行扩写）；
- 自动投稿 / 对接平台 API；
- 生成后自动执行质量检查（可与 `webnovel-quality-check` 串联，但不在本 skill 内跑）；
- 平台爆款规则的实时联网抓取（v1 内置静态规则，联网更新延后，见 §13 开放问题）。

## 3. 核心假设与风险

### 3.1 假设

| # | 假设 | 权重 | 不成立时的降级 |
|---|---|---|---|
| H1 | 大模型能稳定产出"含 主角+欲望+阻力+代价 的完整微型前提" | 1.0（需实测） | 强化种子模板 + 生成后结构化自检回炉 |
| H2 | 平台赛道规则静态化（内置在 SKILL.md）足以支撑"爆款对齐"，不依赖实时抓取 | 0.5（AI 推断） | 引入规则版本号 + 联网刷新机制 |
| H3 | "3 个种子"数量在展示成本与选择自由度间平衡（C6） | 0.7（AI 推断） | 提供"再换一批"命令，不增加默认数量 |
| H4 | 用户愿意在"种子 → 大纲 → 旋钮"三层交互中逐步收敛 | 1.0（用户明说） | 提供"一次出大纲"直通模式（跳过选择层） |
| H5 | 迭代层"旋钮微调"比"推倒重来"更能保留用户已认可的部分 | 1.0（用户明说） | 用户明确要求重来时才重生成 |

### 3.2 风险与缓解（Top 5，对应 Pre-Mortem）

| 死因 | 触发条件 | 概率 | 防死手段 |
|---|---|---|---|
| 种子"虚胖"：字段齐全但戏剧张力为零 | 生成了"模板味"前提，冲突可调和 | 40% | 张力硬门槛（C18）强制"欲望 vs 阻力直接对撞 + 代价不可逆 + 冲突可升级"；不达标重写 |
| 平台合规失效：踩了番茄避雷区 | 模型记忆漂移，未按 C14 避雷清单执行 | 35% | 种子字段12"平台适配验证"强制显式声明；展开层字段12"平台节奏检查"强制显式声明 |
| 种子同质化：3 个本质是同一故事换皮 | 生成时未做差异性对照 | 30% | 差异对照表（题材/情感/结局倾向/冲突类型 ≥2 项不同）逐项比对 |
| 展开层机械拼接：三幕转折无因果链 | 只填字段不推因果 | 30% | 硬约束"每个转折必须由前文因果逼出"；展开时自问"这个转折的上一个原因是什么" |
| 迭代时主题漂移：旋钮调整后人物/因果/主题断层 | 每次调整推倒重来 | 25% | 迭代铁律：只改被旋钮命中的维度，其余锁定；除非用户明确要求重建 |

## 4. 系统架构

### 4.1 六层流水线（C1）

```
输入
  │
  ▼
[平台层]   确定平台（默认番茄，C13）+ 注入赛道约束（C14/C15）
  │
  ▼
[输入层]   判定输入状态：零输入 / 弱输入 / 有明确偏好（C16）
  │
  ▼
[种子层]   生成 3 个种子（12 字段，C17）→ 过 4 硬门槛（C18）→ 暂停等选择
  │
  ▼
[选择层]   用户选一个；"随便"时自动代选（C19）
  │
  ▼
[展开层]   一次性输出完整三幕大纲摘要（12 必填硬字段 + 类型化变体 + 平台节奏检查，C20/C21）
  │
  ▼
[迭代层]   附 9 个可修改旋钮，循环迭代直至用户满意（C22）
```

### 4.2 数据流

1. 读取用户消息中的平台选择（无则默认番茄，C13）→ 从附录A加载对应赛道规则；
2. 读取用户输入 → 状态判定（零 / 弱 / 有偏好，C16），零弱输入不做追问；
3. 生成 3 个候选种子 → 逐项过张力硬门槛 → 通过者按可展开性排序 → 按差异性定最终搭配 → 输出 12 字段（C17/C18）；
4. 暂停（等待用户选择或"随便"指令，C19）；
5. 选中后一次性展开三幕大纲（C9/C20），补类型化变体字段 + 平台节奏检查（C21）；
6. 附加 9 旋钮 → 用户调整 → 基于当前大纲迭代（C22）→ 循环至用户满意或明确要求重建。

### 4.3 技术选型（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 交付形态 | 纯提示词 skill（单 SKILL.md） | 无状态、无运行时依赖，随 opencode / Claude Code 加载即用 |
| 平台规则存储 | SKILL.md 附录A 静态资源区 | 静态高密度规则，正文指针引用（C14/C15 落地） |
| 状态管理 | 会话内内存（种子选择结果、当前大纲、已用旋钮） | 迭代层需跨轮状态，但无需持久化文件 |
| 输出模板 | Markdown 固定字段模板 | C10"固定字段为骨架，允许类型化变体" |
| eval | skill-up 兼容夹具（可选） | 与本仓库 skill-upper evals 体系对齐 |

> **决策 D1**：v1 平台规则**内置静态**（附录A），不做联网抓取。规则带版本号，改版只动附录A。

## 5. 平台层：赛道约束设计（C13/C14/C15）

### 5.1 平台判定

| 输入 | 判定 | 注入规则 |
|---|---|---|
| 未指定 / "番茄" | 番茄小说 | §附录A.1 番茄赛道规则 |
| "七猫" | 七猫小说 | §附录A.2 七猫赛道规则 |
| 其它平台 / 平台名模糊 | 默认番茄，并在输出中标注"按番茄规则运行" | §附录A.1 |

> 平台切换（C22 旋钮8）触发：卸载旧平台规则 → 加载新平台规则 → 基于当前大纲重新做赛道适配验证，而非推倒重来。

### 5.2 赛道约束注入点（贯穿全流程）

| 阶段 | 注入方式 |
|---|---|
| 种子层 | 每个种子的字段2"目标平台与赛道标签"必须落在有效赛道内；字段12"平台适配验证"显式回答是否避开避雷区（C14/C15 的避雷清单逐条核对） |
| 展开层 | 字段12"平台节奏检查"执行 C21 的节奏规则（番茄黄金三章 / 七猫离婚倒计时或 3-5-8） |
| 迭代层 | 旋钮9"赛道微调"限在平台内细分方向选择；旋钮8"平台切换"强制重配 |

### 5.3 平台规则版本管理

- 附录A 顶部标注 `规则版本：2026-番茄-v1 / 2026-七猫-v1`；
- 规则更新时只改附录A，正文指针不变（C14/C15 的参考来源标签 [reference:n] 保留以便溯源）。

## 6. 输入层：状态判定（C16）

| 输入特征 | 判定 | 处理 |
|---|---|---|
| 空输入 / 只有平台选择 | 零输入 | 直接进种子层，不追问 |
| 模糊情绪（如"想写个压抑的""要爽的"） | 弱输入 | 直接进种子层；将情绪作为软约束（C3）注入种子倾向，不要求补全 |
| 一句灵感（如"外卖员重生"） | 弱输入 | 作为软约束注入；可覆盖种子题材倾向，但不锁定全部 |
| 明确偏好（题材/平台/结局倾向等） | 有明确偏好 | 生成 3 个种子并说明"如何吸收该偏好 + 如何对齐平台赛道"（C3） |

> 弱输入处理原则：**软约束只做加权，不做过滤**——即弱输入只影响种子排序与倾向，不淘汰掉与之不同的种子（保住差异性 C7）。

## 7. 种子层：种子 Schema 与硬门槛（C5/C6/C7/C17/C18）

### 7.1 种子 12 字段（C17）

```ts
interface Seed {
  1  标题: string;
  2  目标平台与赛道标签: string;          // 必须对齐平台有效赛道（§5.2）
  3  一句话前提: string;                  // 完整微型故事前提
  4  主角: { 身份: string; 初始状态: string; 缺陷或执念: string };
  5  欲望: { 外在目标: string; 内在需求: string };
  6  阻力: { 主要对抗力量: string; 为什么不可调和: string };
  7  代价: { 失败会失去什么: string; 成功也要付出什么: string };
  8  核心冲突: string;                    // 一句话说清不可调和的对撞
  9  三幕潜力: { 第一幕钩子: string; 第二幕升级: string; 第三幕高潮方向: string };
  10 可能的高潮: string;                  // 主角必须做出的不可逆选择
  11 可能的结局: { 外部结局: string; 内在结局: string };
  12 平台适配验证: string;                // 是否对齐爆款赛道 + 是否避开避雷区（显式回答）
}
```

### 7.2 生成流程

```
生成候选池（≥3 个）
  → [闸门1·张力硬门槛] 主角欲望 vs 阻力是否直接对撞？代价是否不可逆？冲突能否升级？
      · 不达标 → 回炉重写该种子（不做"降级保留"）
  → [闸门2·可展开性排序] 能否自然长出三幕转折、高潮、结局？
      · 对通过闸门1的种子按可展开性从高到低排序
  → [闸门3·差异性定搭配] 题材 / 情感 / 结局倾向 / 冲突类型 ≥2 项不同
      · 取差异最大的 3 个为最终输出
  → 输出 3 个种子 → 暂停，等待用户选择（C18）
```

> **闸门顺序依据 C8**：张力=硬门槛（一票否决）；可展开性=排序验证；差异性=最终搭配。三闸门不可调换、不可并列。

### 7.3 暂停规则（C18）

- 种子输出后**必须暂停**，等待用户选择或"随便"指令；
- 不得在种子层直接展开大纲；
- 用户"随便 / 你选一个" → 按 C19 自动代选（张力最强 → 三幕最完整 → 平台适配度最高）。

## 8. 展开层：三幕大纲摘要 Schema（C9/C20/C21）

### 8.1 必填 12 硬字段（C20）

```ts
interface Outline {
  1  一句话前提: string;
  2  主角: string;
  3  欲望: string;
  4  阻力: string;
  5  代价: string;
  6  第一幕: { 目标: string; 冲突: string; 转折点: string };
  7  第二幕: { 目标: string; 冲突: string; 中点反转: string; 低谷: string; 转折点: string };
  8  第三幕: { 目标: string; 冲突: string; 高潮: string; 结局: string };
  9  高潮: string;                        // 主角必须做出的不可逆选择
  10 结局: { 外部结局: string; 内在结局: string };
  11 主题余韵: string;                    // 故事在追问什么
  12 平台节奏检查: string;                // 开篇钩子是否符合平台"黄金三章"/节奏逻辑（C21）
}
```

### 8.2 可选类型化变体字段（C10，按种子类型自适应）

- 世界观规则（奇幻/科幻/玄幻）
- 关键配角
- 反派逻辑
- 类型标签
- 情感曲线（言情）
- 时间线（重生/穿越/时间循环）
- 叙事视角
- 象征意象
- **短剧适配度评估**（目标平台有短剧改编方向时——七猫短剧定制文赛道必带）

### 8.3 平台节奏附加要求（C21）

| 平台 | 节奏硬约束 |
|---|---|
| 番茄 | 开篇 300 字内必须出现核心冲突或强钩子；每 3 章至少一个情绪释放点；避免慢热铺垫 |
| 七猫 | 离婚文用"离婚倒计时"开局；甜宠文遵循"3-5-8"节奏法（3章内相遇且有肢体/眼神拉扯；5万字内第一次"伪亲密关系"；8万字内第一次"真情感危机"）；情绪拉扯必须足够强 |

### 8.4 展开层硬纪律（C20）

1. **一次性输出**完整三幕大纲，不做分步确认；
2. 每个转折必须由前文因果逼出，不得机械拼接（生成时自检"此转折的上一个原因"）；
3. 高潮必须解决核心冲突，并让主角付出代价（呼应 C5 的"代价"字段）；
4. 结局必须回应主题余韵；
5. 语言具体，避免空泛套话。

## 9. 迭代层：可修改旋钮设计（C11/C22）

### 9.1 九个旋钮

| # | 旋钮 | 取值域 | 影响范围 |
|---|---|---|---|
| 1 | 结局倾向 | 光明 / 苦涩 / 开放 / 悲剧 / 救赎 | 第三幕 + 结局 + 主题余韵 |
| 2 | 主角道德立场 | 善良 / 灰色 / 反英雄 / 反派 | 主角 + 高潮选择 + 阻力逻辑 |
| 3 | 冲突烈度 | 日常 / 生死 / 世界存亡 / 心理 | 三幕冲突 + 高潮代价 |
| 4 | 叙事视角 | 第一人称 / 第三人称限知 / 全知 / 多视角 | 变体字段·叙事视角 |
| 5 | 类型切换 | 奇幻 / 科幻 / 悬疑 / 言情 / 现实等 | 变体字段·类型标签 + 世界观 |
| 6 | 情感基调 | 希望 / 压抑 / 荒诞 / 温柔 / 冷峻 | 全局语气 + 情感曲线 |
| 7 | 节奏 | 紧凑 / 史诗 / 慢燃 | 三幕篇幅分配 |
| 8 | 平台切换 | 番茄 ↔ 七猫 | 重配赛道约束（§5.1） |
| 9 | 赛道微调 | 平台内细分方向（如番茄男频：神豪→专业流） | 种子/大纲的平台标签 + 适配验证 |

### 9.2 迭代铁律（C22）

- 用户提出修改 → 只调整被旋钮命中的维度，**其余锁定**；
- 保持人物、因果与主题连贯；
- **不推倒重来**，除非用户明确要求"重新生成"；
- 平台切换（旋钮8）与赛道微调（旋钮9）后必须**重新执行平台适配验证**（§5.2）。

### 9.3 循环终止条件

- 用户明确表示满意 / 进入下一步（如去写正文、去质量检查）；
- 用户要求重建 → 回到种子层重新生成（保留已选平台的赛道约束）。

## 13. 开放问题与待验证项

1. **张力硬门槛的判定可靠性**：如何用提示词让模型"自我判定张力是否达标"而不放水（H1）——考虑引入"反例攻击"自问（"这个冲突有没有人和稀泥就能解决？"）；
2. **平台规则的时效性**：2026 赛道规则会漂移，静态内置如何保鲜（H2）——是否引入"规则版本号 + 定期人工刷新"；
3. **种子数量**：3 个是否最优（H3）——是否提供"再换一批"旁路而非加数量；
4. **弱输入加权边界**：弱输入（模糊情绪/一句灵感）作为软约束时，加权幅度多少才不伤害差异性（C7 vs C3 的平衡）；
5. **与其他 skill 的衔接**：本 skill 输出大纲后，是否应提示接入 `webnovel-quality-check` 做展开后质量门（v1 只做提示不集成）。

## 14. 明确不适用场景（NOT Applicable）

1. **章节正文生成 / 逐章细化**（本 skill 到大纲摘要为止）；
2. **已有完整大纲、只需质量审查** → 应走 `webnovel-quality-check` / `webnovel-reading-health-check`；
3. **正文 AI 味检测** → 应走 `webnovel-deai-lint`；
4. **实时平台数据抓取 / 投稿自动化**；
5. **诗歌、非叙事类、非中文网文平台**（赛道规则只覆盖番茄/七猫）。
