# 小说大纲摘要生成器 Skill — 设计文档（v1.1 · 篇幅可控·逐章摘要版）

> **版本**：v1.1（在 v0.1 六层版基础上，新增【篇幅层】与【逐章摘要】硬能力）
> **交付物形态**：skill（纯提示词 skill，无独立运行时）
> **落地路径**：单 SKILL.md + 平台规则资源区 + 篇幅结构资源区 + 可选 eval 夹具
> **关联仓库**：`D:\owned\ai\myskills`（与 `webnovel-quality-check`、`webnovel-reading-health-check`、`webnovel-deai-lint` 构成网文创作链的前置环节）
> **相对 v0.1 的变更**：① 六层 → 七层（平台层后插入篇幅层）；② 展开层新增"章数分配表 + 逐章摘要"两个必填硬字段；③ 种子层新增"篇幅适配与章数预估"字段与"逐章可写性"门槛；④ 迭代旋钮 9 → 12 个；⑤ 非目标中移除"细化到章不做"（v1.1 起逐章摘要为必填）。

## 1. 背景与目标

### 1.1 问题

网文作者或"零灵感"用户想从零搭故事骨架，但：

- 面对空白页不知道该写什么，也说不清自己想写什么；
- 现有 skill（质量检查 / 追读体检 / 去 AI 味）都是**创作后置环节**，缺"从 0 到大纲"的前置环节；
- 直接问大模型"给我个大纲"会得到**随机性强、与平台爆款逻辑脱节、不可迭代**的一次性输出；
- 用户经常不知道自己该上哪个平台（番茄 / 七猫），两套赛道规则（爆款 / 避雷）差异大且散落，记忆成本高；
- **v1.1 新增痛点**：即使拿到三幕大纲，作者仍卡在"每一章写什么"——短篇要逐章细排、长篇要百章不水文，而模型最常见的失败模式就是**写几章后偷懒**（"后续同理""第20-50章：主角成长"），或者**章数与用户要求对不上**。

### 1.2 目标

设计并实现一个 **小说大纲摘要生成器 Skill**：以"平台层 → 篇幅层 → 输入层 → 种子层 → 选择层 → 展开层 → 迭代层"七层系统运行，让用户在零输入 / 弱输入 / 有明确偏好三种状态下都能拿到：

1. **对齐目标平台爆款赛道**的故事骨架；
2. **严格适配指定篇幅类型与目标章数**的结构（短篇快节奏单主线 / 长篇多阶段多支线）；
3. **逐章编号、覆盖全部章数、不得跳过**的每章摘要；
4. 可继续迭代的旋钮体系。

### 1.3 成功标准（可验证）

1. 零输入 / 弱输入时，**不问一句话**直接产出 3 个故事种子；
2. 每个种子含 主角+欲望+阻力+代价，三幕可展开性可自证；
3. 3 个种子之间至少 2 项差异（题材 / 情感 / 结局倾向 / 冲突类型）；
4. 所有种子与展开内容落在目标平台爆款赛道内、避开避雷区；
5. 篇幅与章数合规：默认短篇 20 章 / 长篇 100 章；用户指定章数时**严格按指定章数执行**；
6. 用户选中种子后，一次性输出完整三幕大纲摘要，**必含章数分配表 + 逐章摘要**；
7. **逐章摘要覆盖率 = 100%**：编号连续 1..N，无跳章、无合并、无"略/后续同理"（此项可用脚本机械校验，见 §12）；
8. 短篇每章摘要 2-4 句，长篇每章 1-2 句（关键章 3-5 句）；
9. 大纲输出后主动附 12 个可修改旋钮，调整后**连贯迭代**（非推倒重来）；章数调整后**必须重生成章数分配表与逐章摘要**；
10. 平台切换（番茄 ↔ 七猫）后自动重配赛道约束。

### 1.4 非目标（Out of Scope，v1.1 不做）

- 章节级**正文**生成（逐章摘要 ≠ 正文，只给"本章发生什么"的梗概）；
- 自动投稿 / 对接平台 API；
- 生成后自动执行质量检查（可与 `webnovel-quality-check` 串联，但不在本 skill 内跑）；
- 平台爆款规则的实时联网抓取（v1.1 内置静态规则，见 §14 开放问题）。

## 3. 核心假设与风险

### 3.1 假设

| # | 假设 | 权重 | 不成立时的降级 |
|---|---|---|---|
| H1 | 大模型能稳定产出含四要素的完整微型前提 | 1.0（需实测） | 强化种子模板 + 生成后结构化自检回炉 |
| H2 | 平台赛道规则静态化足以支撑"爆款对齐" | 0.5（AI 推断） | 规则版本号 + 联网刷新机制 |
| H3 | "3 个种子"在展示成本与选择自由度间平衡 | 0.7（AI 推断） | 提供"再换一批"命令，不加默认数量 |
| H4 | **模型能在单次任务内完成 100 章逐章摘要而不偷工** | **0.4（AI 推断，v1.1 最大风险）** | 长篇按卷分段连续输出（不等确认）+ 覆盖率机械校验 + 缺章自动补写 |
| H5 | 迭代"旋钮微调"比"推倒重来"更能保留已认可部分 | 1.0（用户明说） | 用户明确要求时才重建 |
| H6 | 用户对"章数不匹配提示"的容忍度高（提示后不阻断体验） | 0.9（AI 推断） | 提示语保持一行、不打断主流程 |

### 3.2 风险与缓解（Top 6，对应 Pre-Mortem）

| 死因 | 触发条件 | 概率 | 防死手段 |
|---|---|---|---|
| **逐章摘要偷工：跳章/合并/写"略"** | 章数多（尤其长篇 100+）时输出预算压力 | **60%** | C14/C28 输出契约 + 收尾自检清单（编号 1..N 连续）+ §12 机械校验；长篇按卷分段输出（§10.4） |
| **章数漂移：分配表章数 ≠ 实际摘要章数 ≠ 用户指定章数** | 分段输出时计数丢失 | **45%** | 三处计数同源：章数分配表先定锚 → 逐章编号严格递增 → 收尾自检三数对齐 |
| 种子"虚胖"：字段齐全但张力为零 | 模板味前提，冲突可调和 | 40% | 张力硬门槛一票否决，不达标回炉 |
| 平台合规失效：踩避雷区 | 模型记忆漂移 | 35% | 种子字段13/展开字段15 强制显式声明适配验证与节奏检查 |
| 长篇水章：摘要逐章存在但大量章节"为什么存在"说不清 | 为凑章数填充过渡章 | 35% | C29-3 自检"本章为何必须存在"；短篇明令"不允许水章"（C21）；关键章加详机制（C28） |
| 迭代时主题漂移 / 章数调整后新旧摘要不连贯 | 旋钮调整推倒重来 | 25% | 迭代铁律：只改被命中维度，其余锁定；章数调整走"重排锚点→保留事件→重分配"而非重写故事（§11.3） |

## 4. 系统架构

### 4.1 七层流水线（C1）

```
输入（平台? / 篇幅? / 章数? / 灵感?）
  │
  ▼
[平台层]   确定平台（默认番茄，C16）+ 注入赛道约束（C17/C18）
  │
  ▼
[篇幅层]   确定篇幅类型与目标章数（默认/校验/提示，C19/C20）+ 加载对应结构规则（C21/C22）
  │
  ▼
[输入层]   判定输入状态：零输入 / 弱输入 / 有明确偏好（C23）
  │
  ▼
[种子层]   生成 3 个种子（13 字段，C24）→ 过 6 硬门槛（C25）→ 暂停等选择
  │
  ▼
[选择层]   用户选一个；"随便"时自动代选（C26）
  │
  ▼
[展开层]   一次性输出完整三幕大纲（16 必填硬字段，C27）
           含章数分配表 + 逐章摘要（C28/C29）+ 平台节奏检查
  │
  ▼
[迭代层]   附 12 个可修改旋钮，循环迭代（C30）
```

### 4.2 数据流

1. 读取平台选择（无则默认番茄）→ 加载对应赛道规则（附录A）；
2. 读取篇幅类型与章数 → 应用默认值 / 不匹配提示（C19/C20）→ 加载短篇或长篇结构规则（附录B），**章数 N 自此成为全局常量**，贯穿种子层/展开层/迭代层；
3. 输入状态判定（零/弱/有偏好，C23），零弱输入不追问；
4. 生成候选种子 → 闸门流水（张力→可展开性→差异性→平台合规→篇幅合规→逐章可写性）→ 输出 13 字段 → 暂停；
5. 选中后：先按 N 生成**章数分配表**（三幕边界锚定）→ 一次性展开 16 字段大纲 → 逐章摘要严格编号 1..N；
6. 附 12 旋钮 → 用户调整 → 连贯迭代；章数变化时回到第 5 步的分配表环节重排。

### 4.3 技术选型（建议）

| 层 | 选型 | 理由 |
|---|---|---|
| 交付形态 | 纯提示词 skill（单 SKILL.md） | 无状态、随加载即用 |
| 平台规则存储 | SKILL.md 附录A 静态资源区 | 静态高密度规则，正文指针引用 |
| 篇幅结构规则 | SKILL.md 附录B 静态资源区（短篇/长篇两套幕结构 + 摘要句数规范） | 与平台规则解耦，改版只动附录B |
| 状态管理 | 会话内内存（平台/篇幅/章数 N/选中种子/当前大纲/已用旋钮） | 迭代需跨轮状态，无需持久化文件 |
| 输出模板 | Markdown 固定字段模板 | C10 |
| **覆盖率校验** | **可选脚本 `tools/check-chapter-coverage`**：从输出中提取"第X章"编号，校验 1..N 连续无重无缺 | C14 的机械兜底，防"偷工"死因 |
| eval | skill-up 兼容夹具（可选） | 与 repo evals 体系对齐 |

> **决策 D1**：平台规则与篇幅规则**内置静态**（附录A/B），带版本号，不做联网抓取。
> **决策 D2**：章数 N 在进入种子层前固化为全局常量；种子字段 12、展开字段 3/8/16 全部引用同一 N，杜绝多处各算各的。

## 5. 平台层：赛道约束设计（C16/C17/C18）

与 v0.1 相同，要点复述：

- **判定**：未指定/模糊 → 番茄并标注；指定七猫 → 七猫规则。
- **注入点**：种子字段 2（赛道标签）与字段 13（平台适配验证）；展开字段 15（平台节奏检查）；迭代旋钮 8/9 触发重配。
- **版本管理**：附录A 顶部标 `规则版本：2026-番茄-v1 / 2026-七猫-v1`，改版只动附录A。
- **v1.1 补充**：番茄"短篇赛道方向"（都市男频/职场商战/三农议题/中短篇IP改编）与七猫"短剧定制文（3-10万保底）"只在**篇幅层判定为短篇**时加权注入——即平台约束 × 篇幅约束是交叉矩阵，不是各自独立。

## 6. 篇幅层：篇幅与章数控制设计（C19/C20/C21/C22，v1.1 新增）

### 6.1 判定矩阵

| 篇幅输入 | 章数输入 | 结果 | 附加行为 |
|---|---|---|---|
| 未指定 | 未指定 | 长篇，N=100 | — |
| 未指定 | 指定 N | N>50 → 长篇；N≤50 → 短篇（按章数反推，提示一句判定结果） | 提示但不追问 |
| 短篇 | 未指定 | 短篇，N=20 | — |
| 短篇 | 指定 N | 短篇，N=指定值 | N>50 时提示"可能更适合长篇"，遵从用户 |
| 长篇 | 未指定 | 长篇，N=100 | — |
| 长篇 | 指定 N | 长篇，N=指定值 | N<30 时提示"可能更适合短篇"，遵从用户 |

> **设计要点**：不匹配提示必须是**单行、非阻断**——说完继续干，不停下来等用户确认（与 C2"不拖延"一致）。

### 6.2 短篇结构规则（1-50 章，C21）

- 单一主线、强钩子、快节奏；
- 幕结构：第一幕 = 第 1-3 章（结尾强钩子）；第二幕 = 第 4 章 ~ ⌊0.8N⌋；第三幕 = 剩余 20%；
- 每 3 章一个小高潮；中点反转落在 ⌊N/2⌋ 附近；
- 每章必须有明确情绪点或反转，**不允许水章**；
- 每章摘要 2-4 句（写细）。

### 6.3 长篇结构规则（50 章以上，C22）

- 主线+支线、多阶段推进、人物成长弧完整；
- 幕结构：第一幕 = 前 25%；第二幕 = 25%-75%；第三幕 = 最后 25%；
- 每 10 章一个阶段转折；每 30 章一个大高潮；每卷（阶段分组）有独立小高潮；
- 每章摘要 1-2 句（写简），关键章（高潮/转折/中点/结局）3-5 句；
- 逐章摘要**先按卷/阶段分组，再逐章展开**。

### 6.4 章数分配表生成算法（展开层字段 8 的前置）

```
短篇: 一幕=[1..3], 二幕=[4..⌊0.8N⌋], 三幕=[⌊0.8N⌋+1..N]
      中点反转锚=⌊N/2⌋；小高潮锚=每3章
长篇: 一幕=[1..⌊0.25N⌋], 二幕=[⌊0.25N⌋+1..⌊0.75N⌋], 三幕=[⌊0.75N⌋+1..N]
      阶段转折锚=每10章；大高潮锚=每30章；中点反转锚=⌊N/2⌋
```

分配表先于此锚定全部"关键章"（转折章/高潮章/中点章/结局章），逐章摘要生成时关键章**自动加详**（C28/C29-4）。

## 8. 种子层：种子 Schema 与硬门槛（C24/C25）

### 8.1 种子 13 字段（C24，v1.1 新增字段 12）

```ts
interface Seed {
  1  种子标题: string;
  2  目标平台与赛道标签: string;
  3  一句话前提: string;
  4  主角: { 身份: string; 初始状态: string; 缺陷或执念: string };
  5  欲望: { 外在目标: string; 内在需求: string };
  6  阻力: { 主要对抗力量: string; 为什么不可调和: string };
  7  代价: { 失败会失去什么: string; 成功也要付出什么: string };
  8  核心冲突: string;
  9  三幕潜力: { 第一幕钩子: string; 第二幕升级: string; 第三幕高潮方向: string };
  10 可能的高潮: string;
  11 可能的结局: { 外部结局: string; 内在结局: string };
  12 篇幅适配与章数预估: string;   // 【v1.1 新增】适合短篇/长篇？预估章数？在用户指定 N 下能否展开（太撑/太瘪都要说明）
  13 平台适配验证: string;         // 是否对齐爆款赛道 + 是否避开避雷区（显式回答）
```

### 8.2 生成流程（6 闸门，C25）

```
生成候选池（≥3）
  → [闸门1·张力]       欲望 vs 阻力直接对撞？代价不可逆？冲突可升级？（一票否决，回炉）
  → [闸门2·可展开性]   能自然长出三幕转折、高潮、结局？（排序）
  → [闸门3·差异性]     题材/情感/结局倾向/冲突类型 ≥2 项不同（定搭配）
  → [闸门4·平台合规]   落在有效赛道、避开避雷区
  → [闸门5·篇幅合规]   【v1.1】能在指定篇幅与 N 章内完成，不强行拉长或压缩
  → [闸门6·逐章可写性] 【v1.1】能否为每一章生成有效摘要而非大量水章
  → 输出 3 个种子 → 暂停，等待选择
```

> 闸门 5 的典型判例：一个"慢热家族史诗"种子在 N=20 短篇下应被回炉或改造；一个"单一事件反转"种子在 N=100 长篇下应补支线/阶段目标，否则回炉。

### 8.3 暂停规则

种子输出后必须暂停；"随便/你选一个"按 C26 代选（张力最强 → 三幕最完整 → 平台适配最高 → **篇幅适配最高**）。

## 10. 展开层：三幕大纲摘要 Schema（C27/C28/C29）

### 10.1 必填 16 硬字段（C27）

```ts
interface Outline {
  1  一句话前提: string;
  2  目标平台与赛道: string;                       // 【v1.1 提升为必填】
  3  篇幅类型与总章数: string;                     // 【v1.1 新增】短篇/长篇 + N（引用全局常量）
  4  主角: string;
  5  欲望: string;
  6  阻力: string;
  7  代价: string;
  8  章数分配表: {                                  // 【v1.1 新增】
       第一幕: `第X章-第Y章`;
       第二幕: `第X章-第Y章`;
       第三幕: `第X章-第Y章`;
     };
  9  第一幕: { 目标; 冲突; 转折点 };
  10 第二幕: { 目标; 冲突; 中点反转; 低谷; 转折点 };
  11 第三幕: { 目标; 冲突; 高潮; 结局 };
  12 高潮: string;                                  // 主角必须做出的不可逆选择
  13 结局: { 外部结局; 内在结局 };
  14 主题余韵: string;
  15 平台节奏检查: string;                          // 黄金三章 / 3-5-8 等（C17/C18）
  16 每章摘要: ChapterSummary[];                    // 【v1.1 新增·第一硬字段】长度必须 === N
}
```

### 10.2 每章摘要格式（C28）

```
第X章｜本章标题｜核心事件｜冲突推进｜人物变化｜情绪点/钩子｜结尾悬念
```

- 短篇：每章 2-4 句；逐章写，不合并、不写"略"；
- 长篇：先按卷/阶段分组再逐章；每章 1-2 句，关键章 3-5 句；编号连续覆盖 1..N；**禁止"第1-10章：主角成长"式阶段摘要代替逐章摘要**。

### 10.3 每章摘要 6 条硬性要求（C29）

1. 每章推进主线或重要支线；
2. 每章结尾必有钩子/悬念/情绪点/转折；
3. 每章能看出"为什么必须存在"；
4. 高潮章/转折章/中点章/结局章写得更具体（与 §6.4 锚点联动）；
5. 章数多时可压缩语言，不得跳章；
6. 与三幕结构、章数分配表严格一致（摘要中的转折章号 = 分配表锚点章号）。

### 10.4 长输出策略（防"偷工"与"漂移"死因，对应 H4）

**问题**：N=100 时逐章摘要输出极长，模型倾向中途偷懒或计数丢失。

**设计**：

1. **先锚后写**：先输出字段 1-15（含章数分配表与全部关键章锚点），再开始逐章摘要——锚点先行使后续每章有"挂靠点"，防因果断裂；
2. **按卷分段连续输出**：长篇按卷/阶段分组（C28），每组写完立即续下一组，**中间不暂停等确认**（C9"一次性"指逻辑上的一次交付，物理上可分多条消息连续发出）；
3. **收尾自检清单**（每次展开输出末尾强制执行并显式声明结果）：
   - [ ] 章节编号 1..N 连续、无重号、无缺号；
   - [ ] 摘要章数 === 分配表总章数 === 用户指定章数 N；
   - [ ] 关键章（转折/高潮/中点/结局）已加详；
   - [ ] 无"略""后续同理""以此类推"字样；
4. **机械校验兜底**：可选脚本扫描输出中的"第X章"编号做 1..N 覆盖校验（§12 M6），eval 用例必跑。

### 10.5 可选类型化变体字段（C10，按类型自适应）

世界观规则 / 关键配角 / 反派逻辑 / 类型标签 / 情感曲线 / 时间线 / 叙事视角 / 象征意象 / **短剧适配度评估**（短篇 + 七猫短剧赛道时必带）。

### 10.6 展开层硬纪律

一次性输出（含义见 §10.4-2）；每个转折由前文因果逼出；高潮解决核心冲突且主角付代价；结局回应主题余韵；语言具体；**逐章摘要完整不省略**。

## 11. 迭代层：可修改旋钮设计（C30）

### 11.1 十二个旋钮

| # | 旋钮 | 取值域 | 影响范围 |
|---|---|---|---|
| 1 | 结局倾向 | 光明/苦涩/开放/悲剧/救赎 | 第三幕 + 结局 + 主题余韵 + 相关章节摘要 |
| 2 | 主角道德立场 | 善良/灰色/反英雄/反派 | 主角 + 高潮选择 + 阻力逻辑 |
| 3 | 冲突烈度 | 日常/生死/世界存亡/心理 | 三幕冲突 + 高潮代价 |
| 4 | 叙事视角 | 第一人称/第三人称限知/全知/多视角 | 变体字段·叙事视角 |
| 5 | 类型切换 | 奇幻/科幻/悬疑/言情/现实等 | 类型标签 + 世界观 |
| 6 | 情感基调 | 希望/压抑/荒诞/温柔/冷峻 | 全局语气 + 情感曲线 |
| 7 | 节奏 | 紧凑/史诗/慢燃 | 三幕篇幅分配（不改动 N 时只调幕内密度） |
| 8 | 平台切换 | 番茄 ↔ 七猫 | 重配赛道约束（§5） |
| 9 | 赛道微调 | 平台内细分方向 | 平台标签 + 适配验证 |
| 10 | **篇幅切换** | 短篇 ↔ 长篇 | 【v1.1】触发结构规则换套 + 章数默认值重议（与用户确认 N） |
| 11 | **章数调整** | 增/减目标章数 | 【v1.1】**必须重生成章数分配表 + 逐章摘要**，覆盖新 N |
| 12 | **每章摘要详略** | 更简/更细/关键章加详 | 【v1.1】只改摘要句数密度，不动事件与结构 |

### 11.2 迭代铁律

- 只调整被旋钮命中的维度，其余锁定；保持人物、因果、主题连贯；不推倒重来（除非用户明确要求）；
- 旋钮 8/9 后重新执行平台适配验证；旋钮 10/11 后重新执行篇幅合规检查。

### 11.3 章数调整的重排算法（旋钮 11 专用，防"新旧不连贯"死因）

```
N → N' 时：
1. 保留：人物、核心冲突、主题、关键事件序列（因果链不动）；
2. 重算锚点：按 §6.4 算法以 N' 重算幕边界与关键章位置；
3. 重映射：原关键事件按因果顺序映射到新锚点（压缩=合并相邻过渡事件；扩充=在阶段内插入支线/升级拍，禁止注水）；
4. 重生成：章数分配表 + 逐章摘要（1..N'）；
5. 自检：§10.4-3 清单以 N' 重跑。
```

> 原则：**改章数是"重新排版同一个故事"，不是"写一个新故事"**。

## 15. 开放问题与待验证项

1. **长输出偷工的真实边界**：单次任务能稳定交付多少章逐章摘要（H4）——N=100/200/300 分层实测，确定"按卷分段"的触发阈值；
2. **张力硬门槛的判定可靠性**：如何防模型自检放水（H1）——引入"反例攻击"自问（"这个冲突和稀泥能不能解决？"）；
3. **平台规则时效性**：2026 赛道规则漂移，静态内置如何保鲜（H2）；
4. **弱输入加权边界**：加权幅度多少才不伤害差异性（C3 vs C7）；
5. **篇幅反推规则**："未指定篇幅但指定章数"时按 50 章分界反推（§6.1），阈值是否合理；
6. **与其他 skill 的衔接**：输出大纲后是否提示接入 `webnovel-quality-check`（v1.1 只做提示不集成）。

## 16. 明确不适用场景（NOT Applicable）

1. **章节正文生成**（逐章摘要 ≠ 正文）；
2. **已有完整大纲、只需质量审查** → 走 `webnovel-quality-check` / `webnovel-reading-health-check`；
