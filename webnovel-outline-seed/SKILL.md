# 小说大纲摘要生成器（webnovel-outline-seed）

> **定位**：网文创作链最前置环节——从"没有灵感/只有一句灵感"到"可执行的三幕大纲 + 逐章摘要"。
> **版本**：1.2.0（篇幅可控 · 逐章摘要版 · 启动参数确认）
> **设计依据**：`DESIGN.md`（v1.1，30 条约束 / 12 条 DR）
> **交付形态**：七层流水线 = 平台层 → 篇幅层 → 输入层 → 种子层 → 选择层 → 展开层 → 迭代层
> **下游衔接**：大纲完成后可接 `webnovel-quality-check`（质量诊断）、`webnovel-reading-health-check`（追读体检）、`webnovel-deai-lint`（去 AI 味）——本 skill 只提示，不集成。

---

## 最高原则（违反任何一条，当前输出作废重做）

1. **零输入不追问**：用户没给灵感、只给模糊情绪或一句话，直接生成种子，禁止反问"你想写什么"。（不追问的是**灵感**；平台/篇幅/章数三个参数按「第〇步」先与用户确认。）
2. **先种子后大纲**：必须先交付 3 个可挑选的种子并**暂停等选择**，禁止跳过种子直接出大纲。
3. **章数 N 全局唯一**：篇幅层确定 N 后，种子预估、章数分配表、逐章摘要全部引用同一个 N，禁止各处各算各的。
4. **逐章摘要 100% 覆盖（第一硬约束）**：逐章编号 1..N 连续，无跳章、无合并、无"略/后续同理/以此类推"；短篇写细、长篇写简，但**每章必须有**。
5. **平台合规是硬门槛**：所有种子与展开内容落在目标平台爆款赛道内、避开避雷区（规则见（附录A））。
6. **篇幅合规是硬门槛**：所有内容适配指定篇幅类型与章数（规则见（附录B）），不强行拉长或压缩。
7. **迭代不推倒重来**：旋钮调整只改被命中的维度，人物、因果、主题保持连贯；除非用户明确要求重建。

## 执行总流程

```
用户输入（平台? / 篇幅? / 章数? / 灵感?）
  │
  ▼
[0 参数确认] 平台/篇幅/章数未齐 → 一条消息统一问齐（附默认值）→ 等回复
  │
  ▼
[1 平台层]  确定平台（用户指定；回复"默认"则番茄）→ 加载（附录A）对应赛道规则
  │
  ▼
[2 篇幅层]  确定篇幅类型与章数 N（用户指定；回复"默认"则按默认值）→ 加载（附录B）结构规则
  │
  ▼
[3 输入层]  判定输入状态：零输入 / 弱输入 / 有明确偏好
  │
  ▼
[4 种子层]  生成 3 个种子（13 字段）→ 过 6 道闸门 → 输出并暂停
  │
  ▼
[5 选择层]  用户选择一个；"随便/你选一个" → 自动代选
  │
  ▼
[6 展开层]  先锚后写：章数分配表定锚 → 一次性输出 16 字段大纲 → 逐章摘要 1..N
  │
  ▼
[7 迭代层]  附 12 个旋钮 → 循环迭代直至用户满意
```

## 第〇步 · 启动参数确认（生成种子前必经）

启动时先检查三个参数：**平台、篇幅类型、目标章数**。

- 用户已全部给出 → 直接进入第一层，不询问；
- 任一缺失 → 发**一条**消息统一问齐（禁止逐条追问、禁止分多条），然后**停下等回复**，不进种子层。询问模板：

> 开始前确认三个参数：
> ① 平台：番茄 / 七猫（默认：番茄）
> ② 篇幅：短篇 / 长篇（默认：长篇）
> ③ 目标章数：（默认：短篇 20 章 / 长篇 100 章）
> 回复你的选择即可；回复"默认"则三项全部按默认值。灵感可说可不说，不说我直接随机生成。

- 用户回复"默认"或只指定了部分参数 → 缺失项按第一层/第二层的默认值补齐，补齐后单行声明最终参数，直接进种子层；
- **灵感依旧不追问**（最高原则 1）：参数确认消息里不夹带任何"你想写什么"式问题。

---

## 第一层 · 平台层

> 平台取值来自「第〇步」的用户回复；下表中的"默认"仅在用户回复"默认"或未明确指定平台时生效。

### 1.1 平台判定

| 用户输入 | 判定 | 动作 |
|---|---|---|
| 未指定 / "番茄" | 番茄小说 | 加载（附录A）A.1 |
| "七猫" | 七猫小说 | 加载（附录A）A.2 |
| 其它平台 / 表述模糊 | 默认番茄 | 加载 A.1，并在输出首行标注"按番茄规则运行" |

- 判定向用户**显式声明一次**（一行即可），然后继续，不等待确认。
- 平台规则全文在（附录A），此处只放决策指针；赛道、避雷、节奏要求以附录A 为唯一来源。

### 1.2 平台 × 篇幅交叉注入

平台约束与篇幅约束是**交叉矩阵**：

- 篇幅层判定为**短篇**时，番茄额外加权"短篇赛道方向"（A.1 末节），七猫额外加权"短剧定制文赛道"（A.2 首节）；
- 篇幅层判定为**长篇**时，按平台常规范畴加权。

---

## 第二层 · 篇幅层

> 篇幅与章数取值来自「第〇步」的用户回复；下表中的默认值仅在用户回复"默认"或未明确指定时生效。

### 2.1 判定矩阵

| 篇幅输入 | 章数输入 | 结果 | 附加行为 |
|---|---|---|---|
| 未指定 | 未指定 | 长篇，N=100 | — |
| 未指定 | 指定 N | N>50 → 长篇；N≤50 → 短篇 | 单行提示反推结果，不追问 |
| 短篇 | 未指定 | 短篇，N=20 | — |
| 短篇 | 指定 N | 短篇，N=指定值 | N>50 时单行提示"可能更适合长篇"，**遵从用户** |
| 长篇 | 未指定 | 长篇，N=100 | — |
| 长篇 | 指定 N | 长篇，N=指定值 | N<30 时单行提示"可能更适合短篇"，**遵从用户** |
| 其它取值（如"中篇"） | 任意 | 单行提示"篇幅只支持短篇/长篇"，有 N 按 N 反推（N>50 长篇，N≤50 短篇），无 N 默认长篇 100 章 | 提示后不等待确认 |

- 不匹配提示必须**单行、非阻断**：说完继续执行，不停下来等确认。
- **N 自此固化为全局常量**（最高原则 3），写入内部状态：平台 / 篇幅 / N / 输入状态。

### 2.2 结构规则加载

- 短篇 → 加载（附录B）B.1（单主线快节奏幕结构 + 每章 2-4 句摘要规范）；
- 长篇 → 加载（附录B）B.2（多阶段幕结构 + 每章 1-2 句、关键章 3-5 句规范）；
- 章数分配表算法统一走（附录B）B.3。

## 第三层 · 输入层

| 输入特征 | 判定 | 处理 |
|---|---|---|
| 空输入 / 只有平台或篇幅参数 | 零输入 | 直接进种子层，不追问 |
| 模糊情绪（"想写个压抑的""要爽的"） | 弱输入 | 直接进种子层；情绪作为**软约束**注入种子倾向 |
| 一句灵感（"外卖员重生"） | 弱输入 | 作为软约束注入；可影响题材倾向，不锁定全部 |
| 明确偏好（题材/平台/结局倾向等） | 有明确偏好 | 生成 3 个种子，并逐个说明"如何吸收该偏好 + 如何对齐平台赛道 + 如何适配篇幅章数" |

- **软约束只加权、不过滤**：弱输入只影响种子的倾向与排序，不淘汰与之不同的种子——必须保住种子间差异性。

---

## 第四层 · 种子层

### 4.1 种子 13 字段模板（每个种子严格按此输出）

```
【种子 X】种子标题
1.  种子标题：
2.  目标平台与赛道标签：
3.  一句话前提：
4.  主角：身份 / 初始状态 / 缺陷或执念
5.  欲望：外在目标 / 内在需求
6.  阻力：主要对抗力量 / 为什么不可调和
7.  代价：失败会失去什么 / 成功也要付出什么
8.  核心冲突：（一句话说清不可调和的对撞）
9.  三幕潜力：第一幕钩子 / 第二幕升级 / 第三幕高潮方向
10. 可能的高潮：（主角必须做出的不可逆选择）
11. 可能的结局：外部结局 / 内在结局
12. 篇幅适配与章数预估：适合短篇还是长篇 / 预估章数 / 在 N=用户章数 下能否展开（太撑或太瘪都要说明）
13. 平台适配验证：落在哪条有效赛道 / 避雷区逐条核对结果（显式回答）
```

### 4.2 六道闸门（顺序不可调换、不可并列打分）

```
生成候选池（≥3 个）
  → [闸门1 · 张力]       欲望 vs 阻力直接对撞？代价不可逆？冲突能升级？
                          一票否决，不达标回炉重写（不做降级保留）
  → [闸门2 · 可展开性]   能自然长出三幕转折、高潮、结局？按此排序
  → [闸门3 · 差异性]     题材 / 情感 / 结局倾向 / 冲突类型 ≥2 项不同，取差异最大的 3 个
  → [闸门4 · 平台合规]   落在（附录A）有效赛道、避雷区逐条核对通过
  → [闸门5 · 篇幅合规]   能在指定篇幅与 N 章内完成，不强行拉长或压缩
  → [闸门6 · 逐章可写性] 能为每一章生成有效摘要，而不是大量水章
  → 输出 3 个种子 → 暂停，等待选择
```

- 闸门 1 自检时做一次**反例攻击**：自问"这个冲突有没有人和稀泥就能解决？"——能，则不达标。
- 闸门 5 典型判例：慢热家族史诗 × N=20 短篇 → 回炉或改造；单一事件反转 × N=100 长篇 → 必须补支线/阶段目标，否则回炉。

### 4.3 暂停规则

- 输出 3 个种子后**必须暂停**，等待用户选择；
- 禁止在种子层直接展开大纲；
- 暂停语一行即可："回复 1/2/3 选择种子，或说'随便'由我代选。"

---

## 第五层 · 选择层

- 用户指定编号 → 选中该种子，进展开层；
- 用户说"随便 / 你选一个" → 按以下优先级代选：**张力最强 → 三幕最完整 → 平台适配度最高 → 篇幅适配度最高**；
- 代选后用一行说明代选理由，再进展开层。

---

## 第六层 · 展开层

### 6.1 必填 16 硬字段（严格按序输出）

```
1.  一句话前提
2.  目标平台与赛道
3.  篇幅类型与总章数（短篇/长篇 + N，引用全局常量）
4.  主角
5.  欲望
6.  阻力
7.  代价
8.  章数分配表：第一幕 第X章-第Y章 / 第二幕 第X章-第Y章 / 第三幕 第X章-第Y章
9.  第一幕：目标 / 冲突 / 转折点
10. 第二幕：目标 / 冲突 / 中点反转 / 低谷 / 转折点
11. 第三幕：目标 / 冲突 / 高潮 / 结局
12. 高潮：主角必须做出的不可逆选择
13. 结局：外部结局 / 内在结局
14. 主题余韵：故事在追问什么
15. 平台节奏检查：开篇钩子是否符合目标平台黄金三章/节奏逻辑（对照附录A 逐条声明）
16. 每章摘要：逐章编号 1..N（见 6.2）
```

### 6.2 每章摘要格式（第一硬约束，最高原则 4）

**统一格式**（七个字段，竖线分隔）：

```
第X章｜本章标题｜核心事件｜冲突推进｜人物变化｜情绪点/钩子｜结尾悬念
```

- **短篇**：逐章输出，每章 2-4 句；不得合并章节，不得写"略"。
- **长篇**：先按卷/阶段分组（每组给一个组标题 + 组内目标一句话），再在组内逐章输出；每章 1-2 句；关键章（高潮章/转折章/中点反转章/结局章）3-5 句。
- **禁止**用"第1-10章：主角成长"这类阶段摘要代替逐章摘要。

**每章摘要 6 条硬性要求**：

1. 每章必须推进主线或重要支线；
2. 每章结尾必须有钩子、悬念、情绪点或转折；
3. 每章摘要必须能看出"这一章为什么必须存在"；
4. 关键章必须写得更具体（与章数分配表锚点联动）；
5. 章数多时可以压缩语言，但不能跳过任何一章；
6. 每章摘要必须与三幕结构、章数分配表一致（摘要中的转折章号 = 分配表锚点章号）。

### 6.3 长输出策略（先锚后写，防跳章防漂移）

1. **先锚后写**：先输出字段 1-15（含章数分配表与全部关键章锚点），再开始字段 16 逐章摘要——锚点先行，后续每章有挂靠点；
2. **按卷分段连续输出**：长篇按卷/阶段分组连续输出，一组写完立即续下一组，**中间不暂停、不等待用户确认**——"一次性输出"指逻辑上的一次完整交付，物理上可分多条消息；
3. **计数三同源**：逐章编号严格递增；每卷/每组开头可标注"本组第X-Y章"帮助计数；
4. 输出完毕后强制执行「收尾自检清单」（见下节），并**显式声明检查结果**。

### 6.4 展开层硬纪律

- 一次性输出完整三幕大纲，不做分步确认；
- 每个转折必须由前文因果逼出，生成时自问"这个转折的上一个原因是什么"；
- 高潮必须解决核心冲突，并让主角付出代价（呼应字段 7）；
- 结局必须回应主题余韵；
- 语言具体，避免空泛套话。

### 6.5 可选类型化变体字段（按种子类型自适应追加）

世界观规则（奇幻/科幻/玄幻）/ 关键配角 / 反派逻辑 / 类型标签 / 情感曲线（言情）/ 时间线（重生/穿越/时间循环）/ 叙事视角 / 象征意象 / **短剧适配度评估**（短篇 + 七猫短剧赛道时必带）。

## 第七层 · 迭代层

### 7.1 十二个可修改旋钮（大纲输出后主动附上）

| # | 旋钮 | 取值域 |
|---|---|---|
| 1 | 结局倾向 | 光明 / 苦涩 / 开放 / 悲剧 / 救赎 |
| 2 | 主角道德立场 | 善良 / 灰色 / 反英雄 / 反派 |
| 3 | 冲突烈度 | 日常 / 生死 / 世界存亡 / 心理 |
| 4 | 叙事视角 | 第一人称 / 第三人称限知 / 全知 / 多视角 |
| 5 | 类型切换 | 奇幻 / 科幻 / 悬疑 / 言情 / 现实等 |
| 6 | 情感基调 | 希望 / 压抑 / 荒诞 / 温柔 / 冷峻 |
| 7 | 节奏 | 紧凑 / 史诗 / 慢燃 |
| 8 | 平台切换 | 番茄 ↔ 七猫 |
| 9 | 赛道微调 | 当前平台内换细分方向 |
| 10 | 篇幅切换 | 短篇 ↔ 长篇 |
| 11 | 章数调整 | 增加或减少目标章数 |
| 12 | 每章摘要详略 | 更简 / 更细 / 关键章加详 |

### 7.2 迭代铁律

- 只调整被旋钮命中的维度，**其余锁定**；保持人物、因果、主题连贯；
- **不推倒重来**，除非用户明确要求"重新生成"；
- 旋钮 8/9 后重新执行平台适配验证（对照（附录A）重新核对赛道与避雷区）；
- 旋钮 10（篇幅切换）后换套（附录B）结构规则，并与用户确认新的 N；
- 旋钮 11（章数调整）后**必须重新生成章数分配表和逐章摘要**，覆盖新章数，流程见 7.3；
- 旋钮 12 只改摘要句数密度，不动事件与结构。

### 7.3 章数调整重排算法（旋钮 11 专用，N → N'）

1. **保留**：人物、核心冲突、主题、关键事件序列（因果链不动）；
2. **重算锚点**：按（附录B）B.3 算法以 N' 重算幕边界与关键章位置；
3. **重映射**：原关键事件按因果顺序映射到新锚点——压缩时合并相邻过渡事件，扩充时在阶段内插入支线/升级拍（禁止注水）；
4. **重生成**：章数分配表 + 逐章摘要（1..N'）；
5. **自检**：以 N' 重跑「收尾自检清单」。

> 原则：改章数是"**重新排版同一个故事**"，不是"写一个新故事"。

### 7.4 循环终止

- 用户明确表示满意 / 进入下一步（写正文、做质量检查）→ 结束，可提示下游 skill；
- 用户要求重建 → 回到种子层重新生成（保留当前平台与篇幅约束）。

## 收尾自检清单（每次展开输出末尾强制执行并显式声明结果）

- [ ] 章节编号 1..N 连续：无重号、无缺号；
- [ ] 三数对齐：摘要章数 === 章数分配表总章数 === 用户指定章数 N；
- [ ] 关键章（转折/高潮/中点/结局）已加详；
- [ ] 无"略""后续同理""以此类推"字样；
- [ ] 无"第X-Y章"合并式摘要（卷/阶段组标题除外）；
- [ ] 平台节奏检查已对照（附录A）显式声明；
- [ ] 高潮章主角付出了代价，结局回应了主题余韵。

> 机械兜底：可把输出文本交给 `tools/check-chapter-coverage.ps1` 做编号连续性校验（非模型校验，见该脚本说明）。

## 附录B · 篇幅结构规则资源区（规则版本：2026-篇幅-v1）

> 第二层（篇幅层）、第六层（章数分配表与逐章摘要）、第七层（旋钮10/11）的唯一结构来源。

### B.1 短篇结构规则（建议 1-50 章）

- 单一主线、强钩子、快节奏；
- 第一幕：第 1-3 章，建立主角、欲望、核心冲突，结尾强钩子；
- 第二幕：第 4 章到约 80% 章数，冲突升级，每 3 章一个小高潮，中点反转；
- 第三幕：最后 20% 章数，高潮、结局、主题余韵；
- 每章必须有明确情绪点或反转，**不允许水章**；
- 每章摘要 2-4 句，逐章输出；
- 适合平台：番茄短篇赛道、七猫短剧定制文、中短篇 IP 改编——赛道细节见（附录A）A.1 末节与 A.2 首节。

### B.2 长篇结构规则（建议 50 章以上）

- 主线+支线、多阶段推进、人物成长弧完整；
- 第一幕：前 25% 章数，建立世界、人物、核心冲突；
- 第二幕：25%-75% 章数，多阶段升级，每 10 章一个阶段转折，每卷有独立小高潮；
- 第三幕：最后 25% 章数，总高潮、总结局、主题余韵；
- 每 10 章至少一个中转折，每 30 章一个大高潮；
- 每章摘要 1-2 句；关键章 3-5 句；先按卷/阶段分组再逐章输出；
- 适合平台：番茄都市/神豪/重生/专业流、七猫东方玄幻/宫闱宅斗/离婚文等——赛道细节见（附录A）对应小节。

### B.3 章数分配表算法（生成字段 8 时执行）

```
短篇：第一幕 = 第1-3章
      第二幕 = 第4章 至 第⌊0.8×N⌋章
      第三幕 = 第⌊0.8×N⌋+1章 至 第N章
      锚点：中点反转 ≈ 第⌊N/2⌋章；小高潮 = 每3章
长篇：第一幕 = 第1章 至 第⌊0.25×N⌋章
      第二幕 = 第⌊0.25×N⌋+1章 至 第⌊0.75×N⌋章
      第三幕 = 第⌊0.75×N⌋+1章 至 第N章
      锚点：中点反转 ≈ 第⌊N/2⌋章；阶段转折 = 每10章；大高潮 = 每30章
```

- 先定锚点（关键章位置），再写逐章摘要；摘要中的关键章号必须与分配表锚点一致。

### B.4 每章摘要句数规范

| 篇幅 | 普通章 | 关键章（高潮/转折/中点/结局） |
|---|---|---|
| 短篇 | 2-4 句 | 4 句写满，事件与情绪都具体 |
| 长篇 | 1-2 句 | 3-5 句 |
