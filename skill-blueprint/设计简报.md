## 1. 背景与问题（基于 t1 盘点与 t2 治理）

### 1.1 仓库现状
- t1 盘点：根目录 **14 个真技能**（含 SKILL.md）+ 1 个 `codebase-onboarding - 副本`（非技能副本），共计 15 项。
- 全部技能均为**领域能力**（代码逆向、认知勘探、正确性回复、模型选型、AI味扫描、PRD 打磨、圆桌勘探、前提前置、网文去AI味/选题/质检/体检）。
- **不存在任何覆盖「技能自身生命周期管理」的技能**：新建/升级/设计一个 Agent Skill 的方法论、目录规范、SKILL.md 骨架、lint 规则挂钩、与本团队流程（设计→撰写→质检→验收→安装）的衔接，均缺乏可复用的指导性技能。

### 1.2 为什么需要它
本团队（Skill 工坊）的核心使命正是「新 Skill 从设计→撰写→静态质检→行为验收→安装归档」。团队自身缺一条标准化、可留痕、可重复的「新技能设计蓝图」，会导致每轮新建技能都要重新摸索规范、易与已有技能触发词撞车（t2 已暴露 codebase-onboarding 硬碰撞、reading-health-check v1/v2 触发词重叠、novel-ai-flavor-scan v3/v4 路由歧义）。

### 1.3 本技能解决什么
以「新建/升级某个现有技能」为入口，产出一份**可直接交付给技能撰写员写 SKILL.md 的设计简报**，并给出 SKILL.md 骨架、目录结构、触发词规范、质量门禁（与 `tools/lint-skill.ps1` 挂钩）、行为验收案例模板。本技能本身**不写 SKILL.md 的最终正文**（那是 t4 writer 的事），也不执行安装（那是 t7 librarian 的事），只负责「设计蓝图+交付标准」。

## 3. 设计原则

1. **与现有技能无碰撞**：命名、触发词与 14 个已安装技能及 t2 提及的全部技能互不重叠（见 §5）。
2. **可回滚**：本技能仅新增目录与文件，不修改任何现有技能目录；删除即干净。
3. **与 lint 契约对齐**：SKILL.md 骨架必须满足 `tools/lint-skill.ps1` 的通用检查（frontmatter name=目录名、description≥60 字符、锚点双向完整、必需章节）。
4. **阶段化 + 模块化**：参考团队现有 SKILL.md 风格（M1/M2… 章节 + S0/S1… 阶段 + Do/Don't 表）。
5. **中文优先**：正文、触发词、错误信息全部中文，示例保留英文关键字。

## 6. SKILL.md 骨架（t4 直接套用）

frontmatter（必须）：

```yaml
---
name: skill-blueprint
description: 新技能设计蓝图与 SKILL.md 骨架生成器。按「需要新建/升级某个现有技能」的需求，输出技能设计简报、目录结构、触发词规范与 lint 门禁建议，供技能撰写员直接写出可通过静态检查的 SKILL.md。触发词：设计一个新技能 / 新建 Agent Skill / 写 SKILL.md / 技能蓝图 / skill-blueprint。
---
```

正文章节（`##` / `###` 二级标题，供 lint 验结构完整）：

1. **一、形态与位置**（形态=纯 Skill 无代码；位置=`d:\owned\ai\myskills\skill-blueprint\`；动机；模型）
2. **二、入口与触发词**（触发词列表；非目标/边界；与现有技能的区分表）
3. **三、设计流程（阶段化）**
   - S0 需求确认：复述「新建/升级哪个技能」、确认目标用户与产出、圈定范围
   - S1 碰撞自查：名称/触发词与已有技能互斥（参考 t1 inventory、t2 治理报告）
   - S2 输出设计简报：目录结构、SKILL.md 骨架、lint 规则挂钩
   - S3 移交撰写：把简报与骨架交给技能撰写员写 SKILL.md
4. **四、SKILL.md 编写规范**（frontmatter 要求；description≥60 字符含触发条件；中文模块化 M1/M2…；阶段化 S0/S1…；Do/Don't 表；锚点双向完整 `（附录X）`↔章节；资源区有正文入点）
5. **五、质量门禁与 lint**（`pwsh tools/lint-skill.ps1 -Path <名>` 必须 PASS；frontmatter name=目录名；description 长度；禁词零命中；唯一模式≤1 次）
6. **六、行为验收案例**（触发词正例应命中本技能；反例不应误触；参考 `_qa-fixture/tiny-echo` 的夹具模式）
7. **七、安装与归档**（`pwsh tools/install-skill.ps1 -Path skill-blueprint`；`-List` 确认；更新 docs 总览索引；退役/删除须先报用户确认）
8. **附录A：SKILL.md 骨架模板**（完整可复制模板）
9. **附录B：lint 规则挂钩示例**（与 `tools/lint-config.json` 格式一致的片段）
10. **术语表**（Agent Skill、SKILL.md、frontmatter、触发词、lint 门禁、行为验收）

> 锚点完整性：正文中凡出现 `（附录A）` / `（附录B）` 均须有对应章节；附录章节须在正文中被引用（≥2 次命名，满足 lint 锚点规则）。

## 7. 与现有技能的区分（避免重叠，落实 t2 治理精神）

| 现有技能 | 职责 | 本技能不做 |
|----------|------|------------|
| model-selector | 推荐思维模型 | 不推荐模型，只输出技能设计蓝图 |
| round-table-skill | 边界不清晰问题的圆桌勘探 | 不做多席位盘问，只输出设计骨架 |
| correctness-enhanced-reply / verify-before-propose | 高可靠回复与红队自审 | 不做对抗式审查，只做设计规范输出 |
| 各网文技能 | AI味/选题/体检/质检 | 不碰网文内容 |
| codebase-onboarding | 代码库逆向与 onboarding 文档 | 不分析任意代码仓库，只规范技能目录 |

> 路由原则：用户若在「设计新技能」语境下同时提及上述技能的领域词，优先由对应领域技能处理；仅当用户明确要「新建/设计/升级某个 Agent Skill」时，才命中 skill-blueprint。

## 8. 风险与回滚

| 风险 | 缓冲/回滚 |
|------|-----------|
| 触发词与未来新增技能重叠 | 本技能仅新增目录，删除即干净；t2 碰撞动作全部可回滚，本技能遵循同原则 |
| SKILL.md 骨架未通过 lint | t4 写完后自跑 `pwsh tools/lint-skill.ps1 -Path skill-blueprint`，失败不进入 t5 |
| 误修改现有技能 | 本设计严格限定「只改 skill-blueprint 目录」，不碰任何现有技能目录 |

## 9. 验收标准（供 t5 reviewer 参考）

1. `skill-blueprint/` 目录下直接存在 `SKILL.md`（真技能判据）。
2. `SKILL.md` frontmatter `name: skill-blueprint` 与目录名一致；`description` ≥60 字符且含触发条件。
3. 正文含 `##`/`###` 二级标题，结构完整；`（附录A）`/`（附录B）` 引用与章节双向对应。
4. `pwsh tools/lint-skill.ps1 -Path skill-blueprint` 退出码 0（PASS）。
5. 触发词正例命中、反例不误触（基于 cases/trigger-cases.yaml）。
6. 不修改任何现有技能目录（git diff 仅新增 `skill-blueprint/` 下文件）。

## 10. 交付给 t4（writer）的约定

- 输入：本设计简报（`skill-blueprint/设计简报.md`）+ 骨架模板（`skill-blueprint/scaffold/SKILL.md.template`，随本简报一并交付）。
