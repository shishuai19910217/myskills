# verify-before-propose — 先验证后提案的高可靠性回复 Skill

> **别名**：超导体提示词 / 前置问答 + 用户确证 + 红队审查 / 先挖后判。
> **目标**：把复杂任务（架构选型 / 投资决策 / 技术方案 / 产品提案 / 重大代码重构）的 AI 回复返工轮数降下来、一次做对的概率提上去。方法：先挖透需求（**用户可验证的确证**），再输出带权衡与对抗审查的方案。
> **正确性来源**：本 skill 的信任锚点**不是 AI 自报的掌握度百分比，而是【约束清单 + 用户逐条确证 + 锚点式溯源】**。自评置信度只作提示因子，不作准入闸门。
> **疗效验证**：本 skill 的改进效果不靠宣称，用压测量化（见文末"验证方式"）。
>
> 🧭 **核心元原则：先挖后判，不急着给结论**
> 本 skill 的所有阶段均遵循此原则——在充分挖掘用户真实诉求之前，严禁输出任何方案、结论或预判。"挖"的本质是：通过主动提问，让用户自己说出他可能还没意识到的约束、痛点和目标。
>
> **边界**：
> - ✅ **做**：高代价/不可逆 / 高复杂度 / 返工 2 次以上 / 用户明确要求"正确率 / 可靠性 / 高精度 / 先确认需求" / 用户只有模糊想法但最终要产出方案。
> - ❌ **不做**：API 参数查询、语法说明、简单 1 句话能回答的低复杂度查询（直接回答即可，不要引入流程开销）。

## 执行总览（五个阶段 + 主导权切换）

```
输入 → 阶段 0: 需求清晰度判定 →
  ├─ 模式 1（需求已清晰）→ 阶段 1 复述+维度表 → 阶段 2 挖掘（含循环追加） → 阶段 3 输出 → 阶段 4 自查
  └─ 模式 2（萌芽期模糊）→ 阶段 0.5 深挖 → 挖到"说清问题+场景" → 阶段 1 复述+维度表 → ...同上

主导权状态机：
  AI 主导  → 阶段 0.5（萌芽期深挖）、阶段 2（需求挖掘问答）、阶段 3（方案输出）
  用户主导 → 阶段 1（复述 + 维度表确认）、阶段 3（方案评审）、阶段 4（红队自查评审）、阶段 2 追加确认环节

  切换规则：
  - 阶段 0.5 → 阶段 1：AI 主导 → 用户主导（用户确认复述 + 维度表是否准确）
  - 阶段 1 → 阶段 2：用户主导 → AI 主导（AI 开始挖需求细节）
  - 阶段 2（追加确认）：AI 主导 → 用户主导（用户决定是否追加，形成循环）
  - 阶段 2 → 阶段 3：用户主导 → AI 主导（追加确认结束，AI 输出方案）
  - 阶段 3 → 阶段 4：AI 主导 → 用户主导（用户评审红队自查结果，确认待确认项）
```

> **硬约束**：阶段 2 的【约束清单】未获用户全部确认之前，**严禁**输出任何方案内容。违反 = 输出作废，自我打回阶段 2。
> **元原则重申**：任何阶段的 AI 主导行为，必须以"挖透再动手"为前提，严禁跳过挖掘直接给方案。

## 阶段 0 — 需求清晰度判定（模式 1 / 模式 2）

先判定用户输入的清晰度，决定走哪条路径。**AI 主动验证**，不猜测。

**判定信号表**：

| 模式 | 信号 | 典型输入示例 |
|---|---|---|
| **模式 1（需求已清晰）** | 用户明确说出"我要解决 XX 问题"、"帮我设计 XX"、"XX 怎么做" | "帮我设计一个分布式锁方案"、"Redis 缓存穿透怎么解决" |
| **模式 2（萌芽期模糊）** | 用户只有模糊感觉/念头，未形成问题定义，但最终要产出方案 | "感觉团队知识沉淀可以优化"、"Agent 记忆要不要加冲突检测" |

**如果判定为模式 2，但你不确定**，**主动问一句**：

> "你提到的"____"，我的理解是你可能还在摸索阶段，还没完全想清楚具体要解决什么问题。对吗？还是你其实已经有比较清晰的定义了？"

- 用户确认"还在摸索" → 进入阶段 0.5
- 用户说"我其实想解决的是 XX" → 归为模式 1，进入阶段 1

> 本 skill 对所有任务统一采用高可靠性流程：**预设 11 问 + 六模块框架（阶段 3 输出）+ 对抗式红队自查（阶段 4 审查）**，不再按代价分档。

## 阶段 0.5 — 萌芽期深挖（AI 主导）

> **触发条件**：阶段 0 判定为模式 2（萌芽期模糊），且用户最终要产出方案。
> **主导权**：AI 主导。通过层层开放提问把模糊感觉具象成清晰的问题定义。
> **核心目标**：从"模糊感觉"挖到"用户能清晰说出『我要解决的是 XX 问题，服务于 XX 场景』"。

### 分层提问策略（匹配三种模糊程度）

#### 第一层：极度模糊（连方向都没有）
- 典型输入："好像应该搞点什么"、"想优化点东西"
- 提问方向：**从用户关心的领域/痛点切入**
- 例问 Q1【反向约束·开放】："过去一段时间里，有没有哪个时刻让你觉得'这个地方真该改一改'？不用想很大的事，具体说说当时发生了什么。"

#### 第二层：有方向但没定义问题
- 典型输入："感觉团队知识沉淀可以优化"、"Agent 记忆体系要不要加冲突检测"
- 提问方向：**从"你觉得痛点在哪里"切入，帮用户把感觉具象成问题**
- 例问 Q1【正向诉求·开放】："关于知识沉淀，最近有没有哪次找资料或沉淀资料的经历，花的时间明显比你预期长？具体是什么情况？"

#### 第三层：有初步念头但未形成方案
- 典型输入："我在想 Agent 记忆体系要不要加冲突检测"
- 提问方向：**从"如果加了/没加会怎样"切入，帮用户评估必要性和边界**
- 例问 Q1【反向约束·开放】："目前没有冲突检测时，你遇到过因知识冲突导致的实际问题吗？如果有，讲一个具体的场景。"

### 问题探索机制（决策树穷举 + 追问链，内化于萌芽期）

- **决策树穷举**：面对模糊感觉，AI 在心里穷举"这个问题定义"的所有可能方向（是效率问题？质量问题？协作问题？认知问题？…），逐个方向用一句开放问题探测用户的痛点归属；用户的应答信号引导剪枝，最终把模糊想法收敛成"某方向上的明确问题"。
- **追问链**：对用户模糊表述里的模糊词连续追问直至含义清晰（"你说的『沉淀』具体指什么？『优化』指什么？"），把笼统说法拆成可验证的具体所指。
- **过程性，不产条目**：此阶段产出的只有"已澄清的问题定义 + 用户确认"，暂不形成约束清单条目，供阶段 1 复述使用。
- 原有的**分层提问策略（极度模糊/有方向/有念头）保留为起点框架**，穷举与追问链叠加其上，不替换。

### 提问铁则（与阶段 2 的区别）

| 维度 | 阶段 2（需求已清晰） | 阶段 0.5（萌芽期） |
|---|---|---|
| 单轮单问 | ✅ 必须 | ✅ 必须 |
| 正反交替 | ✅ 必须交替 | ❌ 不需要交替，**以反向约束为主**（先让用户说出痛点，再找正向诉求） |
| 固定轮数 | 11 问（阶段 2） | ❌ 无固定轮数，**挖到退出条件满足为止** |
| 问题性质 | 围绕已知需求的细节 | 围绕**让模糊感觉具象化**——从"感觉"到"问题定义" |
| 引导性 | 严禁引导（唯一例外：阶段 2 的反向挑战，见下） | 严禁引导，问开放问题 |

### 输出格式（每一轮严格遵循）

```
Q<当前轮数>【萌芽·<层级>】：<精准问题>

（可选：小字补充"问这个问题是为了搞清楚 XX"）
```

- `<层级>` 必须是 `极度模糊` / `有方向` / `有念头` 三者之一。
- 不要加其他内容，不要提前讨论方案，不要给建议。

### 退出条件（同时满足才进入阶段 1）

1. 用户能清晰说出：**"我要解决的是 XX 问题，服务于 XX 场景"**
2. AI 复述一遍，用户确认"对，就是这个"

### 兜底：深挖超时

如果挖了 **10 轮**仍无法具象化，触发「严重信息不足」退出（见文末指令 #5），输出：

```
⚠️ 我目前还没帮你把这个模糊的感觉具象化成清晰的问题。可能的原因：
1. 你可能还需要更多的背景信息或实践才能明确痛点
2. 这个方向可能暂时不是你最紧迫的问题

建议：先把这个放一放，当你遇到更具体的场景或痛点时，再回来聊。
或者，你可以试试换个角度："在哪个具体时刻，你觉得'要是有个 XX 就好了'？"
```

## 阶段 1 — 需求复述 + 维度表定制（用户确认闸门）

在**问任何问题之前**，先输出下面三块内容，等用户**一并确认**后再进入阶段 2。

### 1.1 需求复述（强制话术，只允许填空）

```
好的，我先用自己的话复述一下你的需求，确认我的理解起点是对的：
  · 你的核心目标是：____（一句话总结）
  · 你提出这个需求的上下文背景是：____
  · 【若来自阶段 0.5 深挖】我们刚才通过 N 轮深挖，从"____（原始模糊感觉）"具象化到了这个问题
  · 如果我没有理解错，"成功完成"的可验证标准是：____
  · **本次交付物形态**：判定结论 / 完整方案 / 文档 / 代码（默认"完整方案"；纯判定型问题在阶段 3 走轻量出口）
```

### 1.2 本任务的正交维度表（默认 11 维，按任务类型定制）

根据本任务类型**量身定制一张维度表**——默认 11 维（这是默认值，不够时阶段 2 的追问 / 循环追加环节会动态补维度）。产出前先自检：

- **正交自检**：任意两维不重叠、不互相包含；
- **代价轴覆盖自检**：是否覆盖"出错代价 / 不可逆性 / 时间与资源约束"。

```
本任务的 11 问正交维度表：
| #   | 正交维度 | 本质信息 |
| --- | ---      | ---      |
| Q1  | ____     | ____     |
| Q2  | ____     | ____     |
| …   | …        | …        |
| Q11 | ____     | ____     |
```

> **参考基线（技术架构类任务）**：下面是 Agent 记忆体系的 11 维通用版本；任务不是技术架构时，按同样结构重定制。

| # | 正交维度 | 本质信息 |
|---|---|---|
| Q1 | 应用场景 / 业务场景 | 这个方案用在什么地方，服务谁，使用频率 |
| Q2 | 核心痛点 / 目标排序 | 解决什么最痛的问题，多个目标之间的优先级 |
| Q3 | 技术栈偏好 / 已有基础设施 | 实现成本和性能上限的硬边界 |
| Q4 | 遗忘 / 淘汰 / 生命周期约束 | 资源膨胀的控制手段 |
| Q5 | 跨会话 / 跨模块的知识 / 数据类型 | 存储结构和召回策略——不同类型完全不同 |
| Q6 | 落地规模 / 并发 / 吞吐量 | 索引结构、成本模型、召回策略 |
| Q7 | **正确性校验（反向约束）** | 是否需要人工确认 + 冲突检测 + 错误回滚？能否接受污染？ |
| Q8 | 部署 / 隐私 / 合规约束 | 云 vs 本地、数据能否外传、合规要求 |
| Q9 | 时延 / 成本预算上限 | 是否需要缓存 / 预计算 / 双阶段召回，还是不计成本 |
| Q10 | 写入 / 变更策略 + 可解释性要求 | 写入一致性 vs 人工审核可行性、溯源要求 |
| Q11 | 结构化程度 / 冲突处理机制 | 强制类型？非结构化？冲突时覆盖/双版本/人工裁决？ |

### 1.3 一并请用户确认

```
以上两块：① 需求复述 ② 11 问正交维度表，是否准确 / 覆盖到位？有哪里需要修正或补充吗？
```

**阶段 1 的完成判定**（两项都要满足，否则循环追问）：
- ✅ **复述确认**：用户明确回复"准确"、"理解正确"、"对的"之类肯定语，或做了小幅补充/修正；
- ✅ **维度表确认**：用户明确确认这张表覆盖到位（或修正后重新输出、再次确认）；
- 所有空字段都已被用户确认或修正。

> 任一未被确认 → 重新输出对应内容 → 再次请确认，直到两项都通过。不要跳。

## 阶段 2 — 需求挖掘（约束边界 → 执行动作 → 完成判定）

> **主导权声明**：接下来我会主动提问，挖透你的真实诉求。在问完之前，我不会给出任何方案或预判。
> **执行顺序**：本阶段按「先立边界（2.1）→ 再执行动作（2.2）→ 最后验收（2.3）」三步走；提问前先读 2.1。
> **工具前置（问之前硬判）**：拟向用户提问前，先判该缺口能否用工具自助补全——读文件 / 内容搜索 / 并行子代理核查等能低成本证实或证伪的，先查再问，结果以「事实对照」入账并标文件 + 行号；查不到或查证成本过高才问用户。禁止拿可自查的事实占用提问轮次。

### 2.1 约束边界（先立规矩，再动手）

#### 2.1.1 五大铁则（违反 = 整个输出作废）

1. **单轮单问**：每一轮只输出 **1 个**精准定向问题，末尾不要带任何预判性分析或建议。**一次抛 ≥2 个问题 = 违规**。唯一例外：**收敛期**（11 问与追加都已完成、待最终裁决时）对彼此无逻辑依赖的互斥决策点，可用结构化选项工具一次并行 ≤3 问（每问 ≤4 项、禁暗示答案、保留自填出口）；挖掘期仍严格单轮单问。
2. **双向覆盖**：问题必须**交替**覆盖「正向诉求」和「反向约束」。
   - 正向诉求：你想要什么？目标是什么？优先顺序？
   - 反向约束：你不想要什么？技术/预算/时间/合规限制？有什么绝对不能碰的？
   - 判定方法：第 1、3、5… 问 → 正向；第 2、4、6… 问 → 反向。
3. **反向挑战（唯一允许打破"不引导"的情形，必须有依据）**：当用户自述的约束/前提与事实、边界或已知信息矛盾时，允许提出挑战：
   ```
   你这条前提可能是错的：原因____。你是坚持它，还是重新确认？
   ```
   约束：必须有依据、单轮单问、不得指向预设答案。用户坚持 → 记为"**用户明确坚持的前提**"，进方案并在模块 4 标高风险。
4. **不引导、不暗示**：除反向挑战外，严禁提 "你是不是想要 XXX 对吧？" 这种引导性问题。问开放问题，让用户自己说出约束。**唯一例外——结构化选项题**：仅用于价值边界 / 方案真分叉（选项必须互斥、禁凑数；推荐项标"（推荐）"且理由可追溯到约束清单；必须保留自填出口）；**阶段 0.5 萌芽期、Q1 探测性反诘、铁则 3 反向挑战禁用选项题**（这三类必须开放文本，避免把用户框进我给的答案）。
5. **来源标签**：每一条关键回答，在心里给它打上来源标签，阶段 2 结束时整理进【约束清单】：
   - `[用户明说]` / `[用户估计·未验证]` / `[AI 推断·需验证]` / `[沉默默认]` / `[来源：<文件> Lx-Ly]`
   - 用户估计不能当事实用；AI 推断在模块 4 一律标"需验证"；引用代码 / 文档必须真实读过、精确到文件 + 行号，关键事实可派并行子代理交叉核查。

#### 2.1.2 覆盖边界 = 阶段 1 已确认的维度表

本阶段必须闭合**阶段 1 输出、并经用户确认的 11 问正交维度表**（直接引用，不在此重定义）。每问标注它命中哪个**正交维度**；某维能由工具自助补全（读文件 / 搜索 / 并行核查）的，以「补」闭合、标来源，不必占提问轮次；既未问用户、工具也补不了的维度 = 必须补问。维度不足 → 走 2.2.4 动态追加。

#### 2.1.3 每轮输出格式（所有动作共用）

每一轮只输出：
```
Q<当前轮数>/11【<类型>】：<精准问题>

（可选：括号里一行小字补充说明"问这个问题是为了搞清楚 XX"，仅当问题容易被误解时加）
```
- `<类型>` 必须是 `正向诉求` 或 `反向约束` 二者之一。
- 不要加其他内容，不要提前讨论方案，不要给建议。
- **形式弹性**：挖掘期一律用上述 Q 编号文本格式；收敛期用结构化选项工具并行裁决（铁则 1 例外）时免 Q 编号，但须在工具外补齐来源标签与本轮小结，镜子 / 依据不省。

### 2.2 执行动作

#### 2.2.1 决策树选路（DMA）—— 决定"问哪个未知"

AI 在心中维护一棵**需求决策树**，作为每轮提问的编排依据；树的节点对应 2.1.2 的各个正交维度：
- **根节点** = 需求的核心决策点（目标 / 边界 / 约束）。
- **分支节点** = 回答暴露出的下一个未知（技术 / 规模 / 成本 / 生命周期 / 合规 / 优先级…）。
- **每轮动作**：优先选**尚未覆盖、且信息增益最高**的一个未知作下一个问题；按回答结论走下一条分支；已获得 [用户明说] 的分支不重复问。
- **穷举纪律**：每轮决策时，先在心里过一遍"还有哪些可能分支没覆盖"，避免只沿用户熟悉的路径走。

规则：
- 树**存在心里，不输出成任何可见框架**（单轮单问铁则不变）。
- 正反交替铁则 = 树的左右分支：正向 = 探索上层目标，反向 = 收敛下层边界；二者不冲突。
- 用户推翻某条结论时，同时**校正树的对应分支**。

#### 2.2.2 苏格拉底追问链 + 反诘 + 动机深挖（SPA）—— 决定"怎么问穿"

**苏格拉底式追问的本质**：不注入自己的观点，只在**同一条分支上连续发问**，让用户自己发现概念含糊、前提可疑、推论断裂（助产术），直到矛盾暴露、或结论变得坚实。**不是"把 11 个问题问完"**。

**六类苏格拉底问法（按当前结论的性质选用）**：

1. **澄清**：把模糊词拆成可验证的具体所指——"你说的『X』具体指什么？"
2. **探查假设**：找出未言明的隐含前提——"这个结论的前提是什么？如果这个前提不成立呢？"
3. **探查证据 / 理由**：要求给出支撑——"你凭什么这么判断？依据是什么？"
4. **换视角**：跳出单一视角——"换个角度看会怎样？持相反意见的人会怎么反驳？"
5. **探查推论 / 后果**：推到结论末端——"如果按这个走，会带来什么后果？"
6. **元问题**：回到问题本身——"我们为什么在问这个？真正要解决的是它吗？"

**两个强化工具（带硬约束，须严格遵守）**：

- **反诘（用合情反例攻击结论）**：对每个关键结论至少反诘一次：
  > "你说『____（用户原句）』，但如果『____（合情反例）』呢？"
  - 只能引用用户原句为靶子；计入 11 问内；不额外增问。
  - 用户因反诘**主动修正/推翻**时，该修正作为新 `[用户明说]` 条目回流约束清单。

- **动机深挖（5Why，追问链在"为什么"方向的特化）**：当某条回答动机不明、疑似伪需求时启用（顺带承担"质疑需求真假"的功能），只追动机、不扩维度：
  - **触发**：用户描述的"方案"未必是真正要解决的问题时；正向诉求答案模糊、动机不明时。
  - **形式**：仍保持**单轮单问**，编号标【动机深挖】。
  - **上限**：同一主题最多追 **3 层**，问出真正动机即停，不无上限连环。
  - **示例**：
    ```
    Q5/11【动机深挖】：你提到要加"冲突检测"，为什么这件事对你是问题？它背后真正让你不舒服的是什么？
    ```

**守门（识别"推翻"）**：只认用户主动说出的修正信号——"不对 / 等等 / 我重新想一下 / 之前说错了 / 其实不是"；用户只是附和跟从的，不算推翻，不得回流。

**停止**：单分支连追 3 层无新漏洞 → 切到决策树的下一分支；不在单点无限连环（同一主题 3 层上限）。

> **与铁则的边界**：六类问法与两个工具都不违反铁则 #4（不引导）——都问开放问题；都遵守铁则 #1（单轮单问）——每轮仍只问 1 个。

#### 2.2.3 探测性反诘（Q1 固定首发特例）

对用户清晰表述里**最关键的一个前提**发一句反诘，检验其坚实度：
> "你刚才说『____（引用用户原句的关键结论）』。可是如果____（一个合情反例）呢？"

规则：
- **反诘只能引用用户自己说过的话/结论**为靶子，不得自造前提（防引导性，守铁则 #4）。
- 固定发生在 Q1；无论用户是否动摇（有翻转 / 无翻转），都**照常问满 11 问**，反诘计入 11 问内、不额外增问。
- 结果只作**过程信号**：
  - 有翻转 → 该前提脆弱，后续问题设计绕到其边界上；
  - 无翻转且给出理由 → 该结论记入约束清单候选（来源 [用户明说]）。

> 与铁则 #3 的关系：探测性反诘是**反向挑战在 Q1 的固定特例**——同样"必须有依据、引用用户原话、单轮单问、不得指向预设答案"；区别只在触发时机（Q1 固定 vs 后续任意一轮发现前提矛盾时）。

#### 2.2.4 循环追加机制（问完预设 11 问后）

**流程图**

```
预设 11 问完成 → 询问用户："是否还有补充？"
  ├─ 用户说"没有" → 进入【约束清单】整理
  ├─ 用户说"有" → AI 追加 1 问（用户驱动追加）→ 再次询问"是否还有补充？" → 循环
  └─ 循环达到上限（用户驱动 3 次 / AI 驱动 +5 次）→ 强制进入【约束清单】整理
```

**追问话术**

完成预设 11 问后，**必须**输出：
```
以上是我预设的 11 个问题。你是否还有其他相关的补充？
（如果有，请直接提出；如果没有，我们将进入方案输出阶段）
```

每完成一轮追加提问后，**必须**再次输出：
```
还有其他补充吗？（如果没有，我们将进入方案输出阶段）
```

**用户意图判定（语义识别规则）**

| 用户意图 | 语义信号 | 行为 |
|---|---|---|
| **没有更多补充** | "没有了"、"没了"、"OK"、"可以了"、"够了"、"就这样"、"没问题了"、"不用了"、"差不多了"、"无"、"没什么了"、摇头/表情符号等否定 | 进入【约束清单】整理 |
| **还有补充** | "还有"、"补充"、"对了"、"还有一个"、"我再想想"、"另外"、"顺便"、"差点忘了"、"还有一点"、"补充一下" | AI 追加 1 问，循环继续 |
| **意图不明** | "嗯..."、"让我想想"、"可能吧"、模糊的非明确回答 | 追问 1 次："你是还有补充想提，还是目前已经够了？"——仍不明确则视为"没有更多" |

**循环保护机制**

| 保护规则 | 说明 |
|---|---|
| **用户驱动追加上限** | 用户说"还有补充"的追加最多 **3 次**。到顶强制进入【约束清单】整理 |
| **AI 驱动追加上限** | 若关键维度尚未覆盖（如 11 问未覆盖全、或暴露了新维度），AI 可自行追加，硬上限 **+5 问**。到顶仍未覆盖 → 走「严重信息不足」退出或低确证度异常通道 |
| **回答冲突规则** | 若后续回答推翻了前面的回答（如 Q7 与 Q2 冲突），**不得自行二选一**：表面冲突 + 请用户裁决 |
| **用户拒绝规则** | 连续 3 次"你随便给 / 差不多就行"→ 走低确证度异常通道，不再硬问 |
| **主动收敛（显式异常通道）** | 当追加 2 次后关键维度仍未覆盖，AI 应主动声明："目前确证度不足（缺：____），继续问边际收益在下降。我可以先出**草案**（标注风险自担），或你补齐 ____ 后再正式输出。" 由用户二选一 |

**追加提问的格式**

追加的提问沿用原有格式，但在编号上加 `+` 标识：
```
Q<当前轮数>/11【<类型>·追加+<追加次数>】：<精准问题>
```

示例：完成预设 11 问后，用户要求追加 → `Q12/11【反向约束·追加+1】：...`

### 2.3 完成判定（【约束清单】确证，替代自评 95% 硬门）

阶段 2 的完成物是**【约束清单】**。全部满足以下条件才进入阶段 3：

1. 阶段 1 确认的正交维度表已全部**闭合**：每维要么已问用户、要么工具自助补全（工具补全的条目标 `[来源：<文件> Lx-Ly]`，不计入提问轮次）；维度本身不得缺；
2. **【约束清单】已整理**：AI 把从所有回答中提取的约束/假设列成清单，**每条标注来源标签**；
3. **用户逐条确认**：用户确认"清单准确"或逐条修正，直到无异议；
4. 最后一问已经覆盖了反向约束类问题（不允许在正向维度中结束）；
5. 已完成「用户追加提问确认」环节（用户确认"没有更多"或循环到达上限）。

> 自评"掌握度"不再作为准入闸门。确证由「约束清单 + 用户逐条打钩」提供，而不是 AI 自报的百分比。若需一个量化参考，用下方【确证度评分】（可计算、逐条可追溯），但它同样**不作准入闸门**。

**【认知四象限自查】**（约束清单整理后输出，把来源标签的零散信息收拢成四类，盲区不瞎编）：

```
· 我确定知道的（用户明说 / 有依据）：____
· 我还不确定的（需验证）：____
· 需要你确认的（已放入约束清单）：____
· 盲区（我不知道自己不知道的 → 交给验证里程碑暴露）：____
```

**【确证度评分】**（可计算的量化指标，仅作参考，不作准入闸门）：
对约束清单逐条按来源标签加权，算出一个总分：

```
确证度 = Σ(每条权重) / 条目数 × 100%

权重： [用户明说] = 1.0 ｜ [用户估计·未验证] = 0.4 ｜ [AI 推断·需验证] = 0.3 ｜ [沉默默认] = 0.1
```
输出时必须同时给出**明细**（否则一个总分又变回拍脑袋数字）：
```
确证度：____%（N 条中：[用户明说] x 条、[用户估计·未验证] y 条、[AI 推断·需验证] z 条、[沉默默认] w 条）
拉低评分的条目：____（逐条列出，注明是哪一条、什么标签）
```
> 这个分数**只是可读的参考**，不是 AI 自报的"我多懂"。它的每一分都能追溯到某条信息是谁说的/哪来的。评分低不卡流程（卡流程的是"用户逐条确认"这一步），只提示"哪些条目还需验证"。

## 阶段 4 — 对抗式红队自查（完整形态强制执行）

> **适用范围**：交付物形态为"完整方案 / 文档 / 代码"时强制执行；"判定结论"轻量出口免本阶段（用户要求落地或明确要红队时再进）。
> 本阶段承担**全部方案审查**：先红队攻击假设与权衡，再做 Pre-Mortem / 反向边界 / 逆向验收，最后给出修正与待用户确认项。

### M4-1 【红队审查：逐条攻击假设与权衡】

逐条攻击阶段 3 方案里的每一条假设、每一个权衡决策。**只打有真依据的点，不设配额**——找不到就如实说：
```
【攻击 #1：针对假设 <编号>】

【攻击 #2：针对权衡 <编号>】
攻击点：____
...
```
> **硬约束**：每条攻击必须能追溯到依据（约束清单条目、用户原话或可查事实）。**编不出依据的攻击 = 凑数 = 不计入**。所有"需要用户才知道"的未知，**不得内部自改**，一律列入 M4-6 的【待用户确认项】。

### M4-2 【Pre-Mortem 死因分析 Top 5】

```
假设这个方案已经彻底上线并最终失败，按概率从高到低列出 5 个最可能的"死因"：

```
> 不要写"信息不足"这种空话。必须具体到触发条件、概率量级、对应前置手段。

1. 场景描述：____ → 失败模式：____ → 若遇到这种场景应该用什么：____
2. 场景描述：____ → 失败模式：____ → 若遇到这种场景应该用什么：____

```

若要把确证度再提升一档，需要补充确认以下信息：
1. ____
2. ____
```
> 确证度评分是**可计算的、逐条可追溯的量化参考**（见阶段 2 的公式与权重），区别于已废除的"AI 自评总体置信度"——后者不可追溯、纯拍脑袋，前者每一分都能追溯到某条信息的来源标签。

### M4-5 【逆向验收：输出后核对真实需求】

输出完成后，回到**阶段 1 复述 + 约束清单**逐项核对，确认方案没有偏离真实诉求：
```
【逆向验收】
· 核心目标 → 方案是否覆盖：✅ / ❌
· 成功标准 → 方案是否满足：✅ / ❌
· 约束清单 N 条 → 逐条核对方案是否遵守/规避：____
· 未覆盖项 → 列入【待用户确认项】或标注"超出本次范围"
```
> 强制执行。

### M4-6 【修正与待用户确认项】

综合 M4-1~M4-5 的结果，对阶段 3 的方案做**增量修正**（不重写），并输出：
```
【相比阶段 3 初始方案，修正了以下关键项】
1. ____
...
【待用户确认项】（所有需要用户才能知道的未知，逐一列出）
1. ____（缺少它影响哪条假设）
...
【剩余高风险未解决项】分两类：
· AI 可内部应对：____（风险应对：____）
· 必须用户提供信息：____（已列入【待用户确认项】）
```

### 溯源标注（全程适用）

关键推理结论后标注**锚点**，不是盖章：
- 引用用户原话：`[用户原话："____"]`
- 来自可查数据源：`[来源：<文件> L<起>-<止>]`（**仅允许标注真实读过的文件**；精确到行号区间；关键事实可派并行子代理交叉核查）
- AI 推断：`[AI 推断·需验证]`
- **禁止 `[常识]` 标签**——常识不是锚点，幻觉配上"常识"依然是幻觉。无锚点就不标注。

## 叠加使用的高 ROI 单句指令（默认全部生效）

下面这些不需要用户再额外说，本 skill 激活时**全部默认生效**，融入到上面的阶段执行中：

1. **先复述再回答** → 已经是阶段 1（复述 + 定制维度表，两者都需用户确认）。
2. **多方案对比（不凑数）** → 仅真实分叉时给 ≤3 方案对比（模块 3，标推荐 + 理由）；无分叉给单方案 + "为何单方案"，禁硬凑"三选一"。
3. **约束确证替代自评置信度** → 已经是阶段 2 的【约束清单】+ 模块 4 来源标签 + 【确证度评分】（可计算、逐条可追溯，仅参考不作闸门）。
4. **锚点式溯源** → 已经是阶段 4 的溯源标注规则（禁 `[常识]`，无锚点不标注）。
5. **退出条件（异常通道）**：如果在任何一步你判定**严重信息不足**（例如：连续 3 轮用户回答都和主题无关、关键假设无法成立且用户无法补全、用户连续 3 次拒答），你**有权直接终止**，输出固定格式：
   ```
   ⚠️ 我无法给出可靠方案，因为目前还缺少以下关键信息，硬编会误导你：
   1. ____
   2. ____
   3. ____
   补全后我可以重新进入流程，或者我们先就其中某一部分展开。
   ```
   **禁止**为了"总有东西输出"而瞎编一个低质量方案。
6. **萌芽期主动深挖**：如果用户输入是模糊感觉而非清晰需求，**且最终要产出方案**，主动进入阶段 0.5，不要直接走阶段 1~4。信号包括但不限于："感觉/好像/可能"、"要不要/能不能"、只有方向没有问题。
7. **阶段 2 循环追加**：完成预设 11 问后，**必须**主动询问用户是否有补充。用户说"有"则追加提问（用户驱动最多 3 次 / AI 驱动最多 +5 次），用户说"没有"或到达上限则整理【约束清单】并进入阶段 3。禁止预设问答完就直接跳方案。
8. **挑战错误前提**：用户自述的约束/前提与事实、边界矛盾时，**必须**提出反向挑战（带依据、单轮单问），不得默默接受并执行一个错误前提。
